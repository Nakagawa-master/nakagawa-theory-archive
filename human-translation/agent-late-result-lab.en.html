What if a cancelled AI task later says, “Done”?

English | 日本語版

You stopped a task in an AI coding agent. But a worker running elsewhere sends its result afterward. Accepting that result as a success could change the answer or the budget of a task that is already over.

It is possible for the system to receive a result without being entitled to accept it. That distinction matters more than whether the result looks correct. Try the two orders below.

Try both orders (works offline)

The task starts running. If Result A arrives first, it is accepted once. If cancellation or recovery settles first, the result of the old task cannot update the current record.

Why are the outcomes different?

Accepted first: the running task records one accepted result and a corresponding receipt. An identical retry can be acknowledged without a second answer or usage write.

Cancelled or recovered first: the old worker might still physically finish, but it no longer has authority to publish a new answer or change the task's accepted usage. A late submission is stale.

Different payload after acceptance: a conflicting response is not a replay of the original receipt. It cannot overwrite an accepted result.

The point is not “discard every result that arrives late.” It is: what was actually accepted, and which persisted receipt proves that acceptance? A completion report and a record-changing decision are not the same event.

Did a real project fix this?

This demonstration simplifies the specific acceptance distinction implemented in Qwen Code PR #13241. The receiving developers implemented and tested the change, merged it, and included the PR in stable Qwen Code v0.25.0. In a later related discussion, a project participant spontaneously referred back to the option selected by @Nakagawa-master.

This is an educational simulation, not a live Qwen Code interface. It does not simulate every real lease state, API response or budget policy. It does not claim every AI product has this defect, nor that real end users have tried this teaching page. The usage values 100 and 1,050 are illustrative.
