# 気になる場面から、一つだけ

ここはGitHubですが、最初から仕様書や理論を読む場所ではありません。

生活や仕事の中で「これ、ちょっと分かる」と思う場面を一つ選んでください。  
一つだけ読んでも、何か見方を持ち帰れるようにしています。

人物像や第三者での実例まで含めて最初に見たい場合は、こちらからどうぞ。  
→ [まず一つだけ読んでみてください](../../STORIES.md)

## 1｜エラーだったから、もう一度押した

画面では失敗。相手側では成功。  
その間にある「まだ分からない」を消してしまうと、善意のやり直しが二重決済になります。

→ [「エラーだったから、もう一度押した」](01-double-charge-after-error.md)

## 2｜今月は大成功。でも来月の手が減っていた

売上は伸びた。  
その代わりに、信用、時間、体力、選択肢まで減っていたら？

→ [今月は大成功。でも「次に使える手」が減っていたら？](02-success-eats-tomorrow.md)

## 3｜AIが3案を作り、人間が1つ選んだ

最後に選んだのは自分。  
でも、最初から候補に入らなかった4つ目の道は？

→ [AIに3案出してもらって、自分で1つ選んだ](03-ai-made-the-menu.md)

## 4｜担当者を替えたのに、同じ失敗が戻ってきた

人が違うのに、失敗する場所が同じ。  
それなら、人を動かしている情報や評価や権限にも原因があるかもしれません。

→ [担当者を替えた。なのに、同じ失敗がまた起きた](04-same-mistake-new-person.md)

## 5｜50人の声。でも確認は1回かもしれない

50人が別々に確かめたのか。  
50人が同じ一つの話を広げただけなのか。

→ [50人が同じことを言っている](05-fifty-people-one-rumor.md)

## 6｜承認したあとで、中身が変わった

「承認済み」の記録があっても、人が見ていない内容まで通ってしまうことがあります。

→ [「承認しました」──でも、その後で中身が変わっていたら？](06-approved-one-thing-executed-another.md)

## 7｜専門家を信じる。でも訂正不能にはしない

頼ることと、反例が出ても直せなくすることは別です。

→ [専門家を信じる。でも「訂正してはいけない」にしない](07-trust-experts-without-making-them-uncorrectable.md)

## 8｜測れなかった。なのに「0」と記録された

本当に0だったのか。  
それとも、値を取れなかっただけなのか。

→ [測れなかった。なのに「0」と記録された](08-could-not-measure-became-zero.md)

## 9｜同じ共有のまま。でも使われる場所が変わった

共有が期限内でも、AIの能力や実行場所が後から変われば、その共有の意味まで同じとは限りません。

→ [同じ共有のまま。でも、使われる場所が変わっていたら？](09-same-share-different-runtime.md)

## 横に読むと、同じ形が見えてくる

決済とニュースと組織は、まったく別の話に見えます。

でも、

**結果だけを見る  
→ その結果を作った情報・順番・権限を見る  
→ 混ざっていたものを分ける  
→ 間違った時に戻れる道を残す**

という読み方は、どの話にも持ち運べます。

そこまで見えると、個別の「コツ」ではなく、別の問題にも使える考え方になります。
