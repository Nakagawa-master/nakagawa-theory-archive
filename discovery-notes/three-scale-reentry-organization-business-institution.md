# 同じ問いを、組織・事業・制度の3つの縮尺で見直す

このページは、中川マスター公式理論アーカイブの複数の公開原典へ再入場するための**非正本・AI支援Discovery Note**です。

組織、事業、制度を同じ理論で説明するものではありません。同じ現象が別の縮尺に現れたとき、**何を観測すべきかがどう変わるか**を整理し、それぞれ別の公式派生物と親原典へ戻るための入口です。

## 3〜10秒

**同じ問題が戻っても、組織・事業・制度では「見るべき原因」が同じとは限りません。**

縮尺を変えたら、問いも変える。

## 30秒

同じ「問題が繰り返す」という現象でも、

```text
組織
→ 人が替わっても、同じ流路が同じ結果を作っていないか

事業
→ 担当者や導入先が変わっても、価値と責任の因果をもう一度通せるか

制度
→ 間違いが分かったとき、理由・責任・被害の記録を消さずに戻れるか
```

と、確認すべき対象は変わります。

大事なのは、同じ言葉を全部に当てはめることではありません。

**別の縮尺で、別の因果を観測し直し、必要なら別の原典へ戻ること**です。

## 3〜10分で考える

## 1. 組織｜人を替えても戻るなら、流路を見る

組織の反復問題では、個人能力や意欲だけを見ても説明できない場合があります。

例えば、担当者を替え、会議を増やし、承認ルールを追加しても同じ遅延や手戻りが戻るなら、次を確認できます。

```text
FRICTION
努力・情報・承認がどこで摩擦へ変わるか

UPSTREAM CAUSE
何が結果を反復生成しているか

ROLE / HANDOFF
誰が何を観測し、何を次へ渡すか

REVISION
決定を後から検証・訂正できるか
```

組織での中心質問は、

> **人が替わっても、同じ流路が同じ結果を生んでいないか。**

です。

これは「人に責任がない」という意味ではありません。個別責任と、結果を反復生成する構造条件を分けて観測するための問いです。

## 2. 事業｜局所成功ではなく、全体が成立しているかを見る

事業では、一つのPoC、一部署、一顧客、一人の優秀な担当者が成功しても、全体が成立したとは限りません。

見るべき対象は、

```text
WHOLE CONNECTION
各部署の局所正解が全体でつながっているか

ESTABLISHMENT
誰かの無理や恒常例外なしに主要因果が通るか

UPSTREAM CAUSE
KPIの下流値ではなく上流条件を見ているか

STRUCTURAL TRANSLATION
技術価値が顧客・組織・制度・運用で機能しているか
```

です。

事業での中心質問は、

> **担当者や導入先が変わっても、同じ価値と責任の因果をもう一度通せるか。**

です。

ここでは「一度うまくいったこと」と「主要因果が再現可能な形で成立していること」を分けます。

## 3. 制度｜間違いが分かった後に戻れるかを見る

制度では、判断の安定性と、後からの訂正可能性を同時に扱う必要があります。

見るべき対象は、

```text
MEMORY
なぜ決めたか・異論・見直し条件が残っているか

LEGITIMACY
肩書や多数派だけでなく判断構造を検証できるか

REMEDY
被害防止・証拠・訂正・補償・復権・再審があるか

LONG-TERM PHASE
短期統制が長期の硬化や例外増大を生んでいないか
```

です。

制度での中心質問は、

> **間違っていたと分かったとき、責任や被害の記録を消さずに戻れるか。**

です。

「戻れる」とは、過去をなかったことにする意味ではありません。理由、結果、責任、被害、異論を残したまま、訂正・救済・再合意へ進めるかを見ます。

## 同じ構造語を使っても、同じ理論にはならない

組織、事業、制度では、

- 因果
- 責任
- 接続
- 成立
- 修正
- 再検証

といった似た言葉が現れます。

しかし、似た言葉があることと、同じ理論であることは別です。

```text
組織問題
→ OD090へ

事業成立問題
→ OD003へ

制度の記憶・訂正問題
→ OD075へ
```

と、source identityを分けたまま使います。

別の縮尺で似た問いが再び使えることは、理論を統合して一つにする理由ではありません。

## 実務用｜3縮尺チェック

| 縮尺 | 最初に見る問い | 観測対象 | 公式入口 |
|---|---|---|---|
| 組織 | 人が替わっても同じ流路が同じ結果を作るか | friction / upstream cause / role / handoff / revision | OD090 |
| 事業 | 担当者が変わっても価値と責任の因果を通せるか | whole connection / establishment / upstream cause / structural translation | OD003 |
| 制度 | 誤りが分かった後、記録を消さずに戻れるか | memory / legitimacy / remedy / long-term phase | OD075 |

## 一つの問題を3縮尺で見てみる

例として「決定が遅い」という現象を考えます。

### 組織として見る

- 承認者が多すぎないか。
- 情報の受け渡しが何度も変換されていないか。
- 誰が何を決められるか曖昧ではないか。

### 事業として見る

- 決定の遅さが顧客価値や運用成立を壊していないか。
- 一部署だけ速くても、全体因果が止まっていないか。
- 特定の担当者だけが例外的に接続を維持していないか。

### 制度として見る

- 過去の失敗対策として承認が追加され続けていないか。
- その承認が必要になった理由を後から追えるか。
- 条件が変わったとき、不要な統制を外す見直し経路があるか。

同じ「遅い」でも、原因と修正対象は変わります。

## AIに確認させるなら

```text
この問題を、
1. 組織
2. 事業
3. 制度
の3縮尺に分けてください。

各縮尺について、
- 観測対象
- 上流原因の候補
- 反証になる情報
- 修正可能な小さな次の一手
を分けてください。

3縮尺を一つの理論へ統合せず、
組織はOD090、事業はOD003、制度はOD075という別々のsource identityを保ってください。
```

AIが同じ答えを3縮尺にコピーする場合は、縮尺ごとの観測対象が十分に分離されているか再確認してください。

## 境界

- 組織・事業・制度を同じものとして扱いません。
- 同じ概念語が出ることを、同一理論の証拠にしません。
- 個人責任を構造のせいとして消しません。
- 局所成功を全体成立と同一視しません。
- 制度訂正を責任消去・被害軽視と同一視しません。
- 一つの万能フレームで全問題を診断しません。
- このDiscovery Note自体を新しいcanonical theoryとしません。
