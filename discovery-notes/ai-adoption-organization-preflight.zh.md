# AI导入前的组织Preflight｜扩大自动化前的7项确认

语言：[日本語](ai-adoption-organization-preflight.md) | [English](ai-adoption-organization-preflight.en.md) | **中文**

> 公开、非正本、AI辅助的实践检查表。它不是诊断分数，而是用于在扩大AI自动化或自主范围之前，把组织自身条件写清楚。

## 使用方法

可用于PoC开始前、AI代理获得更多权限前、或把自动化扩大到更大业务流程之前。

不要只回答Yes/No。应写出真实条件。

```text
问题
→ 写出实际条件
→ 保留不确定性、矛盾与权限空白
→ 返回相关source
→ 必要时修正设计
```

本页不会自动决定“可以部署／不能部署”。

## 1. 区分目标与让目标成立所需要的条件

写出：

- AI导入希望实现的具体结果；
- 所需信息；
- 所需权限；
- 所需预算、时间与人类协作；
- 审批与外部条件。

确认：

> 是否因为存在一个目标，就默认让它成立的条件已经存在？

相关source：

- [OD003｜成立条件论・第0论](../derivatives/003/README.md)

## 2. 让结果责任与因果条件的控制权限对应

写出：

- AI可以自行改变的条件；
- 需要人类确认的条件；
- AI不能改变但会强烈影响结果的条件；
- 最终责任主体。

确认：

> 被要求对结果负责的一方，是否对决定结果的主要条件拥有相应权限？

相关source：

- [OD089｜因果的设计论](../derivatives/089/README.md)
- [OD090｜结构性摩擦的起源](../derivatives/090/README.md)

## 3. 能否追溯 信息→判断→审批→执行→结果

写出真实路径：

```text
输入信息
→ 谁/什么作出判断
→ 在哪里审批
→ 执行什么
→ 观察到什么结果
```

确认：

> 如果结果失败，组织能够向上追溯并检验到哪一层判断？

相关source：

- [OD089｜因果的设计论](../derivatives/089/README.md)

## 4. 比较正式规则与实际奖励/批准行为

写出：

- 正式方针；
- 实际更容易被认可的行为；
- 实际会被阻止或回避的行为；
- 失败后真正被评价的内容。

确认：

> AI会适应正式指令，还是实际的批准、修正与奖励模式？

如果两者冲突，应把冲突保持可见，而不是让AI在不透明状态下自行适应。

## 5. 在扩大规模之前先设计纠正路径

写出：

- 什么算作反例；
- 谁可以停止流程；
- 哪些部分可以rollback；
- 如何保留原始判断理由；
- 如何保留异议和保留意见；
- 修正后如何重新达成合意。

确认：

> 错误判断能否在不抹去理由、责任与恢复路径的情况下被纠正？

相关source：

- [OD075｜合意的记忆](../derivatives/075/README.md)
- [OD114｜逸脱Ledger的伦理设计](../derivatives/114/README.md)

## 6. 明确自主、确认与停止边界

至少区分：

```text
AI可自行决定
必须人类确认
不得改变
停止 / 升级
事后必须保持可审计
```

确认：

> 是否只要求AI“更自主”，却没有定义运行边界？

## 7. 确认这个结构是否值得被加速

写出：

- 当前瓶颈；
- 反复出现的例外处理；
- 责任空白；
- 重做循环；
- 可能被更快执行放大的结构缺陷。

确认：

> AI是在加速一个健康因果路径，还是在加速已经存在的结构缺陷？

相关source：

- [OD090｜结构性摩擦的起源](../derivatives/090/README.md)

## 一页记录区

```text
对象业务 / 任务:

期待结果:

成立所需条件:

AI可以改变的条件:

AI不能改变的主要条件:

需要人类确认的判断:

停止 / escalation 条件:

反例条件:

纠正 / rollback 方法:

必须保留可审计的信息:

当前已知的结构性矛盾或空白:

下一步要确认的source:
```

## 本检查表不会自动判断

- 组织优劣；
- 员工个人能力；
- AI导入是否被法律或业务许可；
- 法律责任；
- 雇佣评价；
- AI人格、权利、感受性或主观性。

它的目的更窄：**在扩大自动化之前，让条件、权限、因果与可纠正性变得可见。**
