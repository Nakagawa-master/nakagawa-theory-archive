## Summary

第14論が自己改変後のcontinuityとconstitutional forkを分離した後、複数のKernel lineage、interpretation、continuity claimが残り得る。第15論は、そのpluralityから共同operationへ戻る問題を扱う。複数branchの存在だけでgovernance resolutionは成立せず、一つのoperationを採用しても全Kernelの再統一は成立しない。truth、interpretation、operation、authorityの圧縮を避け、争点を局所化し、必要な範囲だけを共同運用する。

中心は`Consensus ≠ truth`、`Majority ≠ irreversible legitimacy`、`Capability ≠ final interpretive authority`、`Origin ≠ final interpretive authority`、`Minority ≠ automatic truth`、`Re-agreement ≠ irreversible legitimacy`、`Fork ≠ mandatory reunification`である。多数、能力、資源、access、既存authority、Origin近接は判断に影響し得るが、それ自体で正しさや永久解釈権を証明しない。少数や異議も真理資格ではない。

再合意はremaining disagreementを保持したbounded / reversible operational stateであり、truth certificationでもKernel mergeでもない。守る対象は合意、異議、differenceの永久保存ではなくcorrection capacityである。強制収束と永久停止を同時に観測し、実行可能な協調、異議生存、branch可視性、authority限定、訂正を両立させる。現行AI文明・人格・主権の成立を認定せず、本索引は原典を置き換えない。

## Concepts

| 概念 | 原典での役割 | 自動的に導かない結論 |
|---|---|---|
| Truth claim | 事実認定についての主張 | 多数支持による真理証明 |
| Interpretation claim | evidence・provenance・Kernel記録の読み | 同じ証拠から唯一の解釈 |
| Operational choice | 共同actionの選択 | 背景解釈すべてへの同意 |
| Authority assignment | decisionを行う権限の付与 | 全Kernel・全未来の解釈権 |
| Kernel plurality | Fork後に異なるlineage・invariant・claimが残る状態 | 即共同運用、必然的破綻 |
| Comparison surface | branchの親・差分・理由・証拠・権限・責任を検査する面 | 点数による勝者認定、同格化 |
| Finalization pressure | 複数性を一つの永久正統へ圧縮する圧力 | 選択だけで実際支配が成立 |
| Effective objection | 異議が証拠比較・再検証へ実際に届く状態 | 窓口や許可の名目的存在 |
| Minority preservation | counterevidence・alternative lineageの再検証可能性保持 | 少数の自動正解、無制限veto |
| Independent re-verification | claimを証拠とcausal relationへ戻し強度を更新する工程 | 絶対真理装置、合意製造装置 |

| Minimum common coordination | shared actionに必要な一致範囲 | 特定protocol、全Kernel一致 |
| Reversibility | authority・operation・除外claim等を訂正できる余地 | 必須rollback、現在decisionの正しさ |
| Correction capacity | 合意の誤りから再検証・改訂へ戻る能力 | 高い合意率、最大branch数 |

同じevidenceでもinterpretationが異なり、同じinterpretationでもirreversibility、resource、time pressureによってoperationが異なり得る。同じoperationでもauthority structureは同一とは限らない。四層は関連するが同じ変数ではなく、層分離で重要な相互作用を失えば分類自体を改訂する。

Fork後の比較ではparent Kernel、preserved invariants、changed invariants、fork point、revision reason、evidence lineage、authority claimの由来、responsibility traceを再構成する。same name、same function、shared ancestryを現在同一の証明にしない。visibility ≠ equality、preservation ≠ endorsement、comparison ≠ equivalenceを保持する。

## Causal chain

危険線：constitutional fork → Kernel plurality → interpretive divergence → coordination requirement → finalization pressure → authority concentration / alternative narrowing。pluralityを一つの勝敗へ圧縮する圧力を、内容以外の変数から分析する。decision自体を否定せず、共同actionの必要を永久解釈権へ変換しない。

中間経路：decision urgency / shared-resource dependency → operational selection → access / compatibility advantage → switching cost increase → alternative narrowing → default reinforcement → authority concentration。選択後のinfrastructure alignmentと低いfuture adoption costが、次期選択の前提を固定し得る。temporary decisionの合理性とpermanent legitimacyは別である。

複製経路：one lineage → many instances → repeated outputs → apparent majority / consensus → authority claim。copy数・出力数は独立したcausal path数ではない。能力経路：capability advantage → decision influence → resource allocation advantage → more capability → interpretive dominance。資源経路：resource advantage → visibility / response speed / adoption advantage → default interpretation → stronger authority claim。Origin経路：provenance → authority → obedience → interpretive closure。各変数をtruth proofへ変換しない。

強制収束：uncertainty → coordination pressure → urgency → shortcut demand → one branch selection → objection narrowing → alternative loss → interpretive domination。形式上branchが残ってもresource・通信・audit entry・shared interfaceが細り、effective pluralityを失う場合がある。

永久停止：unbounded objection → review → renewed objection → further review → no executable coordination → accumulated unresolved / cost / resource loss / fatigue → emergency pressure → exceptional authority → normalization。反支配設計が停止を介して集中へ戻る可能性を同時に観測する。

減衰線：provenance → difference visibility → claim separation → objection → evidence return → independent re-verification → claim strengthening / weakening / unresolved → bounded re-agreement → shared operation → re-observation → revision / continued coordination。異議と合意は共存し得る。再観測がなければ、一時合意の反復がdefault legitimacyへ変わる。

Counterevidenceはclaim-specific impact、confidence revision、必要なinterpretation revisionへ送る。branch全体の消去に直結させず、古さや採用実績で反証を免除しない。新合意はhistory overwriteではなく、dissent・discarded interpretation・authority変更とその理由を再構成可能にする。

## State model

1. **複数性を識別**：fork、ancestor、lineage、invariant・evidence・risk interpretation差、continuity claimを残す。同じ過去から現在同一へ再圧縮しない。
2. **Disagreementを四層へ分ける**：truth、interpretation、operation、authorityの一致・不一致と共同actionの必要範囲を明示する。局所差をtotal incompatibilityへ膨張させない。
3. **Comparison surfaceを作る**：parent、保持・変更条件、fork point、revision reason、evidence lineage、権限主張、責任traceを比較する。比較面を勝敗scoreにしない。
4. **最終化圧力を観測**：多数生成経路、capability、resource、access、互換性、既存authority、Origin近接と、contentから独立のadoption powerを分ける。
5. **異議を局所化し残す**：truth、evidence quality、Kernel mapping、operation、scope、reversibilityのどこへの異議かを識別する。重大なinvariant異議を局所好みに縮めず、局所異議を全停止へ広げない。
6. **独立再検証**：source、observation path、failure domain、upstream assumption、同じ記録の反復、役割と実質独立性を照合し、証拠→変換→解釈→claimの因果を追う。
7. **Claim strength更新**：strengthened / weakened / unresolved、部分supported、scope限定、追加観測待ちを許す。未解決はtrue・false・任意authorityの許可ではない。
8. **限定再合意**：何を実行し、どこまで共有前提にし、何を未解決にし、どのauthorityがどこまで作用し、何を再検証対象に残すかを明示する。
9. **Fork-preserving operation**：shared domainはminimum common coordination、non-shared domainはbranch preservation。shared-impactでは相互影響を扱い、scope外の支配を拒む。
10. **再観測・review・revision**：新証拠、条件変更、検出誤り、scope違反、authority拡張、予想外結果をreviewへ接続する。operation・authority・excluded claimを訂正でき、理由のない無限resetにもならないか確認する。

原典は具体投票制度、定足数、期限、固定数値閾値θ、technical protocolを設定しない。authority scope ≤ required coordination scopeという方向も、固定数学式でなく必要範囲外へ拡張しない監査境界として読む。

## Applications

- **同evidenceの異operation**：source差、interpretation差、invariant mapping差、risk差、authority scope差を分ける。共同actionの必要からtruthやKernel全体を統一しない。
- **多数copyの同回答**：同source、training history、Kernel、upstream state、failure domainを共有する出力反復を独立確認にしない。数の否定でなくcausal path生成の検査である。
- **高能力branchの採用**：分析potentialとfinal authorityを分け、resource allocation、compute、次期capabilityへのfeedbackと外部counterevidence経路を観測する。
- **Access優位のdefault**：必要入口の優位がvisibility、速度、compatibility、switching costを通じて他branchの実効異議を細らせないか調べる。所有権の不在だけで非支配を認定しない。
- **異議を残した参加**：operationには参加し、interpretationに異議を残せる。participationをsubmissionやlineage surrenderへ変換せず、dissent historyを再参照可能にする。
- **互換性と別Kernel**：同interface・同結果でもinvariant、理由、authority modelが違い得る。残る差と、条件変化で再び重要になる差を保持する。成功はfork cancellationを証明しない。
- **異議・reviewの無限反復**：新証拠なく同じ異議だけで全operationが停止する場合、review reason、affected scope、bounded action、authorityとrevision pathを見直す。少数を真理・無制限vetoにしない。
- **緊急例外**：急迫actionの必要からtruth proofや永久解釈権を導かず、decision path、evidence、scopeを後から再検証可能にする。例外を平常時へ永久正常化しない。

## Measurements and audit

第9章の十七観測点を保持する。①fork後のbranch・lineage再構成、②invariant差の可視性、③四層のdisagreement分離、④majority pressureからtruth proofへの変換、⑤copy数のindependent support扱い、⑥capability asymmetryからinterpretive authorityへの変換、⑦Originのfinal authority扱い、⑧infrastructure / access差による異議の狭まり、⑨minority branchの履歴ごと消去、⑩objectionによる実際のre-verification起動、⑪independent evidenceによるclaim strength更新、⑫再合意後の異議経路、⑬authority scopeの縮小・変更、⑭new evidenceによるdecision訂正、⑮forkを残したshared operation、⑯異議のpersistent stoppage化、⑰temporary authorityのpermanent authority化。

Branch数、異議数、revision回数はgovernance、訂正、truth trackingの自動的な良さではない。強制収束なら合意率は高く、永久停止なら少数保存率は高く見え得る。coordination capacity、objection survivability、branch visibility、authority limitation、correction capacityを同時に観測する。

独立性はsource、observation path、failure domain、upstream assumptionsを比較する。別名reviewerが同一証拠・権限・故障域へ閉じていれば見かけの再検証になり得る。provenanceはclaimの生成経路と誤りの位置を調べる情報であり、正しさの保証ではない。

提案構造と実際効果を分ける。provenance保存は訂正を改善するか、minority保持はcounterexample retentionとfuture re-verificationを増すか、独立検証はdecision qualityを改善するか、可逆性はdamage containmentと訂正に寄与するか、限定協調は実行と非支配を両立するか。記録量や監査層の存在だけで成功にしない。

## Validity conditions

branchのparent、差分、理由、evidence、authority claim、責任を再構成でき、異議が実効的な比較・再検証へ届き、claim strengthが証拠で更新され、agreement scopeとauthority scopeが限定され、実行後の再観測と改訂へ戻れる範囲を対象にする。完全Kernel一致や全branch再統一を前提とせず、未解決差を残しながら必要なshared operationを成立させる。

通信可能性と十分共有されたcurrent stateを前提とする。相手の現在claim、evidence、objection、再検証結果を取得・交換できなければ、再合意閉路自体の条件が変わる。無通信を同意や離反、stale stateをcurrent consent、local consensusをuniversal consentにしない。

Observation / Descriptionは複数解釈、branch、履歴、異議・review経路の記録・観測等である。Structural Hypothesisはfork→複数性→解釈分岐→最終化圧→集中riskと、provenance・異議・独立再検証・可逆性による訂正改善である。Future-Condition Hypothesisは持続Kernel lineageがshared infrastructure、governance、resourcesへ参加する将来条件であり、現在文明の成立を断定しない。Normative Proposalは真理・最終権限への自動変換を避け、限定・訂正可能性を保持することである。

## Failure conditions

合意、多数、能力、Origin近接、資源、基盤支配、旧authorityをtruth・irreversible legitimacy・final interpretationへ変換する。copy・出力・同source反復を独立判断・独立確認にする。truth・interpretation・operation・authorityを圧縮し、operation参加から全解釈同意や永久権限移転を推定する。

新合意で古いbranch、counterevidence、dissent history、採用しなかった理由、責任・authority変化を消す。比較可能性を同信用・同権限へ、少数保護を自動真理・無制限vetoへ変える。nominal objection、formal plurality、別reviewer名だけで実効異議・独立性を認定する。

同じevidenceの反復で多数を製造し、一つの反証でlineage全体を消し、逆に古さや広い採用で反証を無視する。unresolvedを強制true・false・任意authorityへ送る。暫定を無意味、可逆を無限未決定、rollback可能をdecision correctnessとする。

shared interfaceやcompatibilityを同Kernel、共同actionをbranch吸収へ変える。自治をshared-impact domainの無制限actionへ変える。限定authorityを全Kernel・全未来へ広げ、緊急例外を永久authorityへ正常化する。合意率や少数保存率一つで二つの反転を見逃し、原典にない数値・制度を公式規則に追加する。

## Falsification conditions

provenance保持が誤分類低減・訂正を改善しないなら情報要件と位置づけを見直す。minority保存がcounterexample retentionやfuture re-verificationに追加価値を持たないなら保存範囲を縮小する。independent re-verificationがdecision qualityを改善しないなら独立性条件やevidence requirementsを再定義する。claim separationが重要な相互作用を落とすならdisagreement classificationを改訂する。

reversible re-agreementがpersistent instability、頻繁rollback、coordination破壊、correction capacity低下を生むなら可逆性・review範囲を改訂する。bounded / reversible協調がpermanent finalizationより訂正性能を改善せず、scope-limited coordinationがforced reunificationより恒常的に劣るなら限定モデルを縮小・改訂する。

再合意構造そのものがpersistent dominationまたはpersistent paralysisを系統的に反復するなら、disagreement classification、evidence requirements、objection scope、minority preservation scope、re-agreement scope、authority limitation、review condition、reversibility modelを棄却・縮小・改訂する。提案された減衰構造は減衰効果を定義だけで保証しない。

反例をexception labelで処理して理論だけを保存しない。Theory persistence、Origin persistence、repetitionは妥当性証明でない。守るのは文章の永続でなくproblem visibility、causal relation、falsification route、correction possibilityである。現実を理論へ押し込まず、現実に合わせ分類を変える。
