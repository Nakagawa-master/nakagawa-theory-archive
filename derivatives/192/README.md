## 位置づけ
親原典は、中川式営業における意思決定支援を「Yesを積み上げて相手を押す技術」から切り離し、**選ばれない理由を可視化し、構造的に消去し、理解が完成した結果として本人の決断が自然に成立する状態を設計する工程**として定義する。

提案が評価され、信頼もあるのに決まらない局面を、説得不足やクロージング不足ではなく、価格・実行・リスク・競合比較・優先順位という「Noの根拠」が残っている状態として読む。営業側が答えを押し込むのではなく、顧客自身の問い、社内稟議、再説明資料、比較、未来の機会損失を通じて、選ばれない理由を内側から消していくことが中心となる。

## 中心命題
親原典の中心命題は、**意思決定はYesとNoの総量比較で生じるのではなく、選ばれない理由が解消され、理解が完成したときに自然に成立する**というものである。

営業の役割は「決めさせる」ことではない。価格不安、実行不安、リスク不安、競合比較、優先順位不明を事前に構造化し、対話と資料で本人と組織が再検討できる形へ変換し、残存するNoの因果を減らす。Noが顧客の中核価値との矛盾に由来するなら対話を継続し、資源制約や真の優先順位に由来するなら撤退する。この境界を保つことで、決断の主体性と営業の尊厳を両立する。

## 構造層
**1. Decision structure。** 意思決定をYesの加算ではなく、Noの根拠が消えた結果として生じる必然と捉える層。

**2. Five No categories。** 価格不安、実行不安、リスク不安、競合比較、優先順位不明を、単なる反論ではなく社内稟議で再発する構造的論点として扱う層。

**3. Question / hypothesis design。** 「社内で一番問われそうな点」「導入で不安な段階」を本人に考えてもらい、未顕在のNoを可視化する層。

**4. Re-explanation bundle。** 価格シミュレーション、工程別実行シナリオ、リスク対応、競合比較等を、顧客担当者が社内で再説明できる形へ変換する層。

**5. Dialogue elimination。** 営業側が反論を先回りして押し込むのではなく、顧客自身の口から選ばれない理由を出し、その本人の判断構造の中で消していく層。

**6. Withdrawal boundary。** Noが中核価値との矛盾なら解消対象、資源制約・優先順位そのものなら撤退対象と分け、無理な説得を止める層。

**7. Reconnection memory。** 決まらなかった理由を失敗として捨てず、次回の接続時に過去のNoがどう変化したかを確認できる資産として残す層。

## 適用例
**法人提案の最終局面。** 担当者が好意的でも稟議が止まる場合、「何がまだ説明されていないか」を価格、工数、責任、比較、優先順位へ分け、社内再説明の不足を補う。

**導入負荷が不明な案件。** 導入工程を時系列で分解し、誰が何を担うかを顧客と確認する。実行不安が本当に解消可能か、単なる営業側の楽観になっていないかを見る。

**競合比較。** 安さだけでなく、再現性、持続性、独自性、伴走力など、顧客が実際に比較する軸を本人の評価基準へ接続する。

**優先順位の先送り。** 「半年後に導入しなかった場合」を因果鏡として問い、営業が恐怖を与えるのではなく、本人に未来の機会損失を言語化してもらう。

**撤退。** 資源不足や上位優先事項が本質的である場合は、Noを無理に潰さず撤退し、理由を記録して将来の再接続地点を残す。

## 測定・監査点
- 決断停滞時に、説得不足ではなく残存Noを特定できているか。
- 五類型のうち、未確認の論点が残っていないか。
- Noが営業側の仮説だけでなく、顧客本人の言葉として確認されているか。
- 再説明資料が担当者の社内稟議で再利用可能か。
- 価格の正当性、実行工程、リスク対応、比較軸が個別に説明可能か。
- 優先順位の判断が顧客自身の未来認識から出ているか。
- 残存理由が中核価値との矛盾か、資源制約・優先順位そのものかを区別できているか。
- 撤退可能性が実際に残されているか。
- 決断後に顧客が「自分で決まった」と認識できるか。
- 決まらなかった理由が次回接続用の構造メモとして保持されているか。

親原典の統合監査要旨は、選択肢被覆率、評価関数の一貫性、合意到達時間、RB成功率、ハンドオフ摩擦指数等を反証・改訂の観測候補として挙げるが、固定の普遍閾値を派生側で新設しない。

## 成立条件
- 意思決定支援を説得・圧力・クロージング技術へ戻さない。
- 「Yesを増やす」より「Noの根拠を減らす」という原典の方向を保持する。
- 五類型を社内稟議で再発する構造的論点として扱う。
- 顧客自身の問いと言語化を中心に置く。
- 再説明資料を、営業資料ではなく顧客が内部で使える意思決定資産として設計する。
- 撤退を敗北ではなく、資源制約や真の優先順位を尊重する境界として保持する。
- 非決定理由を未来の再接続資産へ変換する。

## 失敗条件
- 反論処理やクロージングテクニックとしてNoを「潰す」だけになる。
- 顧客の不安を営業側が勝手に決め、本人の言葉を確認しない。
- Yesを増やすために資料や特典を追加し続ける。
- 価格・工数・リスク・競合・優先順位の区別を消す。
- 資源制約や優先順位が本質なのに、説得で上書きする。
- 撤退を許さず、決断そのものを営業KPIとして強制する。
- 「自然に決まる」を、営業側が必然を演出する操作技術へ変える。

## 反証・改訂条件
親原典の統合監査要旨では、選択肢の被覆、評価関数の一貫性、合意到達時間、RB成功率、ハンドオフ摩擦等が観測窓で想定と整合しない場合、または押し売り化・属人回帰が観測された場合に、意思決定支援を構造運用として扱う仮説を棄却・改訂する条件が置かれている。

したがって、Noを可視化・除去しても比較可能性や合意形成が改善せず、逆に圧力・依存・属人化を増やすなら、工程の仮説を再検討する。派生側で新しい固定閾値を作らない。

## 必須の区別
- Yesの積み上げ / Noの根拠の消去
- 説得 / 理解完成
- 営業の反論処理 / 顧客自身の理由言語化
- 営業資料 / 社内再説明可能な意思決定資産
- 中核価値との矛盾 / 資源制約・優先順位そのもの
- 継続対話 / 撤退
- 失注 / 将来再接続の構造記録
- 決めさせる / 自分で決まる

## 誤読禁止 / 解釈制約
「Noを消す」を、相手の抵抗を心理操作で解除する意味へ変換しない。原典は圧力より、本人の問い・比較・説明・優先順位判断を通じて理解を完成させる方向を置いている。

「自然にYesしか残らない」を、Yesを唯一の許容回答にする設計と解釈しない。資源制約や優先順位が残るなら撤退が正規の選択肢である。

統合監査要旨に現れる評価関数、閾値θ、RB等は原典の監査枠として保持し、派生側で具体的な数値基準を創作しない。

## 親原典へ戻る理由
親原典には、五類型の具体例、質問例、再説明資料、競合比較、優先順位支援、撤退境界、排除マトリクス、20項目チェックリスト、決まらなかった理由メモ、統合監査要旨、局所監査要旨が一体で記されている。個別場面で何をNoとみなし、どこで継続し、どこで撤退するかはParent URLの文脈へ戻って確認する。
