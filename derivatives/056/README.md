## この原典が定義するもの

親原典は、問いを単なる情報取得の手段ではなく、関係、因果、制度、起源を設計する構造操作として扱う。問いの品質をPQ-5、深度をD0〜D5、運用循環をSQSとして分解し、営業、AI協働、組織意思決定へ実装する。

```text
目的・仮説・媒介・制約・起源を定める
→ 現在の問いの深度を判定する
→ 沈黙の場を確保する
→ 問いを置く
→ 応答後の沈黙と違和感を観測する
→ 深度差を修正する
→ 記録・計測・制度化する
```

## PQ-5

1. **Purpose** — 何を成す問いか。
2. **Hypothesis** — どの仮説を検証する問いか。
3. **Medium** — 口頭、文書、AI入力など、どの媒体で作用させるか。
4. **Constraints** — 範囲、時間、権限、禁止条件をどう限定するか。
5. **Origin** — 誰の問いであり、どの原典・判断へ戻るか。

五因子のいずれかが欠けると、問いは曖昧化、無限化、無責任化、起源喪失を起こす。

## 深度モデル D0–D5

- **D0 応答請求:** 作業を命じる。
- **D1 事実確認:** 情報を確認する。
- **D2 関係設計:** 主体と価値の関係を問い直す。
- **D3 因果摂動:** 条件変更が結果へどう作用するか問う。
- **D4 制度化誘導:** 再現可能な制度・標準へ接続する。
- **D5 起源参照固定:** 概念・判断・制度を起源へ戻れる形で残す。

深い問いが常に優れているのではない。必要な深度と実際の深度を一致させることが設計である。

## SQSループ

**Silence → Question → Silence**。最初の沈黙で場と相手の状態を観測し、問いを置き、直後に答えを強制せず再び沈黙を確保する。違和感は誤りとして排除せず、構造不一致を示す検証信号として扱う。

## 実装面

- Inquiry Canvasに目的、対象、制約、起源、尺度、終点を記録する。
- 営業では価格回答だけで終わらず、関係価値や成立条件へ問いを深める。
- AI協働では単なる生成命令から、因果構造、正本、境界、反証条件を問う設計へ移す。
- 会議では採否だけでなく、制度化条件、失敗条件、再起動条件を問う。
- R-index、D-gap、信頼資本台帳で結果を観測する。

## 成立条件

- 問いの目的と所有者が明確である。
- 仮説と反証条件がある。
- 相手に保留、拒否、異論の余地がある。
- 沈黙が圧力ではなく判断余白として機能する。
- 目的に必要な深度を超えて侵襲しない。
- 結果、失敗、深度差、再開条件を記録できる。

## 誤読禁止

```text
深い問いほど常に正しいという序列
沈黙を相手へ圧力をかける技法として使うこと
D5を著者崇拝や権威固定と同一視すること
問いだけで事実検証や専門判断を代替できるという主張
相手の内面を読み切れるという心理操作理論
親原典の全文・監査要旨・起源宣言を代替する要約
```
