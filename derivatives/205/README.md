## 位置づけ
本原典は、不動産市場OS Vol.7で「合意から履行までの時間」を短縮した後に残る行政摩擦を、窓口の遅さではなく**説明責任の不確実性**として捉える行政編である。行政・公的資料は存在していても、取引の重要事項説明へ接続する際に、どの資料のどの版を、どの範囲へ、どの例外条件で適用し、欠落や矛盾があれば誰が止め、誰が説明・検証するのかが束ねられていなければ、確認は案件ごとに再発生する。

そこで親原典は、行政データを単にAPI化するのではなく、**参照束（Reference Cluster）**として、出典・版・範囲・例外・欠落状態・停止条件・責任境界・差分履歴を一つの監査可能な説明単位へ束ねる。狙いは「調査を速くする」だけではなく、説明責任を毎回ゼロから組み立てる時間を減らし、市場の基準時間を書き換えることにある。

## 中心命題
親原典の中心命題は、**行政接続の本質はデータを増やすことではなく、重説・取引判断に使う根拠を「参照束」として監査可能に束ね、欠落・矛盾・未確定を停止可能な状態として明示し、説明・検証・提供の責任境界を固定することで、行政情報の確認時間を説明責任の再構築時間から切り離すことにある**、というものである。

そのため、最小仕様では Source / Version / Scope / Exception / Missing State / Stop Condition / Conflict Detection / Responsibility Boundary を保持し、欠落を推測で埋めない。未確定・要確認・停止を正式な状態として扱い、停止には再開条件を伴わせる。T/S/Rは本原典で Trace / Stop / Responsibility と定義される。

## 因果線
```text
行政・公的データは存在する
↓
しかし資料ごとに版・範囲・例外・更新時点が異なる
↓
重説・取引判断へ接続するたびに人が根拠を再構築する
↓
どの資料を使ったか、なぜ止めたか、誰が説明するかが曖昧になる
↓
確認時間ではなく「説明責任の不確実性」が行政摩擦になる
↓
行政データを参照束Specへ変換する
↓
Source / Version / Scope / Exceptionを固定する
↓
欠落を未確定 / 要確認 / 停止として状態化する
↓
矛盾・差分を検知し、停止条件を先に定義する
↓
各停止に再開条件を付ける
↓
Provider / Explainer / Verifierの責任境界を固定する
↓
根拠・版・差分・停止・責任を一つの監査束へ連結する
↓
重説作成後の追加照会・再交渉・説明事故を減らす
↓
行政確認の基準時間が「毎回再調査」から「参照束を検証」へ変わる
↓
Trace / Stop / Responsibility、θ・δ・現象Mで反証・改訂する
```

## 構造層
**1. Administrative Friction。** 行政摩擦の本体を、資料の有無や窓口速度ではなく、説明責任を成立させるまでの不確実性として扱う。

**2. Reference Cluster。** 一つの取引判断に必要な複数根拠を、相互参照可能な一つの説明単位へ束ねる。

**3. Source / Version。** 何を根拠にしたかだけでなく、どの版・更新時点かを追跡可能にする。

**4. Scope。** 市区町村全体、地区、道路、筆、建物等、資料が実際に適用できる範囲を明示する。

**5. Exception。** 一般ルールと例外条件を分離し、例外を通常ルールへ埋没させない。

**6. Missing State。** データが無い／確定できない場合を未確定・要確認・停止として明示し、空白を推測で埋めない。

**7. Stop Condition。** 出典・版不明、自治体内差異が大きい、重要ハザード欠落、境界未確定等では自動生成・自動判断を停止する。

**8. Restart Condition。** 停止だけで終わらず、追加確認・新しい版・専門家検証・境界確定等、再開に必要な条件を指定する。

**9. Conflict Detection。** 複数資料・旧版と新版・自治体間仕様差を差分として検出し、変更履歴へ残す。

**10. Responsibility Boundary。** 情報提供者、説明者、検証者を分離し、誰が何を保証・説明するかを固定する。

**11. Observed / Estimated / Uncertain。** 観測事実、推定、未確定を同じ確度で表示しない。

**12. Reverse Proposal DX。** PDF・紙・Excel等で運用される行政出力を否定せず、市場側が参照束へ翻訳し、行政が接続しやすい状態へ整える。

**13. Baseline Time Rewrite。** 調査・照会を案件ごとに再構築する運用から、既に監査可能に束ねられた根拠を検証する運用へ移す。

**14. T/S/R。** Traceは出典・版・範囲の追跡可能性、Stopは欠落・矛盾時の停止可能性、Responsibilityは提供・説明・検証の責任境界である。

## 適用例
**ハザード。** ハザード情報が存在しても、更新版・対象範囲・地番との対応が不明なら「安全」と推定せず停止する。版と適用範囲が確定してから再開する。

**道路・再建築。** 自治体資料の一般説明と個別道路条件を分離し、個別確認が必要なら要確認状態にする。一般ルールだけで再建築可と断定しない。

**境界。** 筆単位へ対応できない資料しかない場合、地区情報を個別敷地へ過剰適用せず、境界未確定として停止・確認へ送る。

**自治体更新。** 新旧版の差分を検知した場合、該当参照束を再検証対象へ移し、重要条件の差分が大きければ自動生成を止める。

**重説。** 一つの説明項目に対し、出典URL、版、対象範囲、例外、確度、説明責任者、検証者を同時表示し、後から「どの根拠で説明したか」を再現できるようにする。

## 測定・監査点
- 参照束生成後の追加照会率。
- 重説内容を原因とする再交渉率。
- 誤説明・見落としを原因とする紛争率。
- 自治体更新差分による自動生成停止頻度。
- 監査ログ欠損率。
- 出典URL・版・範囲の追跡可能率。
- 未確定情報が推定へすり替わっていないか。
- 停止件数に対して再開条件が明示されている割合。
- Provider / Explainer / Verifierの責任境界が保持されているか。
- 公開監査束と参照束の整合。

## 成立条件
- 出典・版・範囲・例外を追跡可能にすること。
- 欠落・矛盾・未確定を正式な状態として扱うこと。
- 停止条件と再開条件を一対で持つこと。
- 推定と観測を区別すること。
- 説明・提供・検証の責任境界を固定すること。
- 行政データの既存形式を入力として扱い、存在しないデータを捏造しないこと。
- Trace / Stop / Responsibilityと公開監査束を定期的に整合させること。

## 失敗条件
- 出典や版が不明なまま説明を確定する。
- 地区レベル情報を個別敷地へ無条件適用する。
- 欠落値をAI推定で埋めて確定情報として扱う。
- 停止条件がなく、重要情報欠落でも自動生成を続ける。
- 停止後の再開条件が定義されていない。
- 新旧版・自治体差・資料間矛盾を無視する。
- 情報提供者・説明者・検証者の責任が混線する。
- 参照束が生成されても追加照会・再交渉・説明事故が減らない。

## 反証・改訂条件
Condition Zでは監査周期、Trace / Stop / Responsibility、公開監査束の整合を確認する。参照束生成後の追加照会率、重説起因の再交渉率、誤説明・見落とし起因の紛争率、自治体更新差分による停止頻度、監査ログ欠損率等の主要指標が閾値θを継続的に悪化させる場合、参照束Spec・停止条件・責任メタを改訂する。

公開監査束との整合が崩れた場合は、該当参照束を無効化し、再生成・再監査する。θは反証閾値、δは観測窓の記号であり、原典は全自治体・全市場へ共通する固定数値を定義していない。

## 必須の区別
- 行政データ不足 / 説明責任の不確実性
- データ接続 / 参照束化
- 公式資料 / 当該物件への適用可能性
- 観測 / 推定 / 未確定
- 欠落 / ゼロ
- 停止 / 失敗
- 停止条件 / 再開条件
- 情報提供 / 説明 / 検証
- API化 / 説明責任の構造化
- 行政DX / 市場側翻訳
- 調査時間短縮 / 基準時間の書き換え

## 誤読禁止 / 解釈制約
本稿は、行政が遅い、紙やPDFが劣っている、AIが行政判断を代替できる、と主張するものではない。行政が既に出している情報を市場側で監査可能な参照束へ翻訳し、欠落や矛盾があれば止め、責任境界を明示する設計である。ハザードや老朽インフラ等は確度と適用範囲を保持し、個別物件へ過剰適用しない。

また、参照束は重説・法的判断・専門家責任そのものを代替しない。説明責任を成立させる根拠構造を束ね、確認・説明・検証を再現可能にする接続面である。

## 親原典へ戻る理由
親原典では、行政摩擦の再定義、参照束Specの最小要件、欠落状態、停止／再開条件、差分検知、責任境界、観測／推定／未確定、自治体への逆提案DX、統合監査要旨、Trace / Stop / Responsibility、θ・δ・現象Mまでが章を跨いで定義される。派生面は検索・理解・接続の入口であり、個別行政資料の適用範囲と説明責任は親原典で確認する。
