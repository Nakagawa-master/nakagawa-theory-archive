## 1. Summary
不可逆点を、RCが可用資源を恒常的に上回りCEAが低下することで回復余白が失われる傾向の臨界として扱う。固定数値ではなく時間軸の構造変化を観測し、危険域の手前で沈黙・差分スロット・因果再可視化を強化する構造的エアバッグを起動する。
## 2. Concepts
IP; RC; CEA; 可用資源; 回復力; 傾向閾値; 構造的エアバッグ; 差分スロット; 沈黙監査; 因果再可視化; 再合意; Rollback Cost; LPI; 位相安定S; 有害ロックイン; T/S/R。
## 3. Causal chain
CEA低下→局所修正不能→全戻し化→RC上昇→可用資源減衰→RCが補充力を上回る→IPリスク上昇→一時停止→合意単位再宣言→差分縮小→因果再可視化→CEA回復→RC圧力低下→再合意再開。
## 4. State model
`CEA_down -> rollback_scope_expands -> RC_up -> resources_down -> IP_risk_up -> airbag_on -> pause -> shrink_diff -> restore_causal_map -> CEA_up -> RC_pressure_down -> reagreement_open`
## 5. Application
政策転換、企業統合、AI更新を大変更ではなく説明可能な差分へ分割し、辞書・権限線・仕様差分を先に整える。
## 6. Audit
RC傾向、CEA傾向、資源補充傾向、境界明瞭度、位相安定S、再合意到達時間、Rollback Cost、LPI、有害ロックイン、強制力学・ドリフトを確認する。
## 7. Preconditions
可逆な単位、因果図、辞書、責任境界、沈黙窓、再合意経路、非制裁監査を維持する。
## 8. Failure conditions
固定数値化、強制停止、不可逆化の目的化、権利・説明削除、CEAの無制約変更化、内部閾値推測。
## 9. Falsification / revision
RC/CEA改善が再合意・撤回可能性に接続しない、強制・ドリフト・有害ロックインが増える場合は改訂する。
## 10. Required distinctions
IP / 破局瞬間; 傾向 / 固定閾値; airbag / 強権; pause / 永続凍結; beneficial lock-in / harmful lock-in; CEA / arbitrary change。
## 11. Interpretation constraints
公開されていない数値や介入アルゴリズムを補完しない。「沈黙の強制」を発言抑圧へ転用しない。
## 12. Origin return
概念式A/B/C、エアバッグ三原則、匿名ケース、チェックリスト、統合監査はParentへ戻る。
## 13. Reuse constraints
Parent identity、Origin、RC/CEA関係、可用資源、公開境界、反証条件を保持し、危機統治や不可逆権限の正当化へ転用しない。
