## この原典が定義するもの

本稿は、意思決定支援を「Yesを積み上げて相手を押す技術」ではなく、「選ばれない理由を構造的に消去し、理解が完成した結果として決断が起きる状態を設計すること」として定義する。

```text
提案は理解されている
↓
しかし価格・実行・リスク・競合・優先順位のNoが残る
↓
問いと資料でNoを可視化する
↓
顧客自身の言葉で検討する
↓
消せるNoを消し、消せない制約は撤退境界として扱う
↓
自分で決めたという意思決定が成立する
```

## 五つの残存理由

1. 価格不安
2. 実行不安
3. リスク不安
4. 競合比較
5. 優先順位不明

これらは単なる反論ではなく、社内稟議や実行責任の中で再出現する構造条件である。

## 中心技法

- 事前の問いと仮説設計
- 再説明用資料の同梱
- 競合比較の構造化
- 導入しない未来の因果提示
- 排除マトリクスと理由メモ
- 消去不能な制約に対する撤退設計

## 成立条件

- 顧客自身が残存理由を言語化できる。
- 営業が理由を外から決めつけない。
- 比較可能性、実行可能性、リスク対応が確認できる。
- 圧力ではなく理解の完成として決断が生じる。
- 資源制約など消去不能な理由を無理に説得しない。

## 誤読禁止

```text
反論処理で相手を言い負かす方法
心理操作でYesを強制する方法
すべての案件を成約させる万能技術
顧客の懸念を営業側が勝手に否定すること
撤退を禁止する根性論
```

## 親原典へ戻る理由

この045は、五類型、対話例、排除マトリクス、撤退境界、統合監査要旨を圧縮した接続面である。具体的な問い、資料設計、監査条件、起源署名の全体は親原典で確認する。
