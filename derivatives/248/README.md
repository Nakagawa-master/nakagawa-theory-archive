## 位置づけ
本ParentはAdoryを「LINEでアンケートを取るサービス」として紹介するだけではない。Nakagawa Masterは、現場に生じる小さな不調・違和感・疲弊・関係変化が、正式相談の心理負担や報告手続の摩擦によって組織へ届かず、離職・休職・事故・業績悪化等の結果が出てから初めて可視化される問題を読む。価値核は、低摩擦な継続観測によって小さな変化を**先行指標化**し、対話・支援の時間を前へ移す構造である。

## 中心命題
組織は結果指標だけを見ていると介入が遅れる。だが、小さな不調を集めれば自動的に未来を予測できるわけでもない。重要なのは、入力摩擦を下げ、単発値ではなく時系列の変化を見ることで「何かが変わった」という兆候を把握し、それを個人への断定・処罰ではなく、確認・対話・支援を始める入口として使うことである。先行指標は原因確定や離職予言ではなく、**結果が大きくなる前に確認する時間を作るための観測装置**として読む。

## 因果線
```text
現場に小さな不調・違和感が生じる
→ 正式相談・報告には心理・時間・手続摩擦がある
→ 小さな変化が組織へ届かない
→ 状態悪化が蓄積
→ 離職・休職・事故・業績悪化等の結果指標で発覚
→ 対応開始が遅い
→ 低摩擦な継続入力を設計
→ 単発値ではなく時系列変化を観測
→ 先行指標として兆候を可視化
→ 個人断定せず確認・対話へ接続
→ 必要な支援・業務調整を早める
→ 介入後の状態変化を再観測
```

## 構造層
1. **現場感覚層**: 疲弊、違和感、関係変化等の小さな兆候。
2. **報告摩擦層**: 正式相談まで上げる心理・手続コスト。
3. **低摩擦入力層**: 日常的に状態を伝えやすい接点。
4. **継続観測層**: 単発回答ではなく時系列を取る。
5. **変化抽出層**: 絶対値より変化・偏り・持続を確認する。
6. **先行指標層**: 結果前に確認を始めるシグナルとして扱う。
7. **対話接続層**: 指標から個人断定せず確認へ移る。
8. **支援・改善層**: 業務負荷、関係、休養、相談等へ接続する。
9. **権利保護層**: 監視・処罰・不利益利用を防ぐ。
10. **再観測層**: 介入後の変化を継続して確認する。

## 状態モデル
潜在不調相 → 未報告相 → 低摩擦入力相 → 継続観測相 → 変化検出相 → 先行指標相 → 確認・対話相 → 支援相 → 改善/継続観測相。

## 適用例
チーム状態が数週間にわたり変化した場合、それだけで個人の離職や疾病を予測せず、「業務負荷、関係、役割、休養等に変化がないか」を確認する対話の入口にする。組織サーベイでも年1回の満足度だけでなく、短い周期の変化を見る。ただし回答率やスコア自体を目的化せず、実際の支援へ接続する。

## 測定・監査点
- 入力摩擦が過度に高くないか。
- 継続回答が可能か。
- 単発値と時系列変化を分けているか。
- 指標が実際の結果より先行するか。
- ノイズや一時変動を過剰解釈していないか。
- 変化検出から対話までの遅延を追えるか。
- 匿名性・プライバシー・利用目的が明確か。
- 指標が処罰・人事不利益へ転用されていないか。
- 対話・支援後の状態を再観測しているか。

## 成立条件
低摩擦な継続観測が、結果発生前の意味ある変化を捉え、その変化が適切な確認・対話・支援へ接続し、プライバシーと不利益利用防止が保たれる場合に成立する。

## 失敗条件
LINE利用そのもの、アンケート回答率、個人監視スコア、離職・疾病の確定予測へ縮小する、指標が対話ではなく処罰へ直結する、ノイズを兆候と誤認する、支援へ接続しない場合は失敗する。

## 反証・改訂条件
継続入力が結果に対して先行性を持たない、ノイズが大きすぎる、変化検出後も支援開始が早まらない、不利益利用が増える、別の観測手段の方が高い説明力を持つ場合は適用範囲・運用条件を改訂する。

## 必須の区別
アンケート / 先行指標；状態観測 / 個人監視；相関兆候 / 因果確定；早期介入 / 早期処罰；変化検出 / 未来予測；対象事実 / Nakagawa Masterの構造読解。

## 誤読防止／解釈制約
回答から個人の離職・疾病・能力を確定予測しない。先行指標は対話・支援の入口であり、人事処分の自動根拠ではない。「先行指標化」はNakagawa Masterの構造読解であり、Adory自身の公式企業定義へ置換しない。
