## Summary
不動産市場OS Vol.4は、Vol.3で成立した計算可能な盤面を、責任の所在が宙に浮かない「担保可能な盤面」へ変換する責任構造編である。AIを収集・整形・一次計算・パターン検出・条件差可視化の計算レイヤーへ限定し、専門家・金融・行政等を責任レイヤーとして接続する。AIは選択肢の条件を示せるが最終判断や個別法的判断を命令しない。専門家は広告主ではなくGuarantorとして担当領域の真正性・説明可能性・更新責任を引き受ける。出力をGeneral / Estimate / Conditionalに分け、誤謬をInput / Model / Interpretation / Operationalの四層へ分解し、未確定・例外を文脈付きでエスカレーションする。信頼を人格でなく役割分離、責任境界、監査、更新構造から生成し、T/S/R＝Transparency / Separation / ResponsibilityとCondition Zで継続監査する。

## Concepts
- Calculation vs Guarantee: 計算可能性と社会的担保可能性の分離。
- AI Calculation Layer: 収集、整形、一次計算、パターン検出、条件差可視化。
- Responsibility Layer: 人間・専門家・制度主体が責任を引き受ける層。
- Boundary Fixing: AIの許可領域と禁止領域を固定する。
- Guarantor: 担当領域の真正性・説明可能性・更新責任を引き受ける専門家。
- Output Strength: General / Estimate / Conditionalの強度区別。
- Four Error Layers: Input / Model / Interpretation / Operational Error。
- Escalation: 未確定・例外・個別判断を文脈付きで人へ渡す。
- Financial Connection: 「買える」と「貸せる」を同じ前提で並置する。
- Trust Infrastructure: 担当・監査・更新・事故切り分けによる構造的信頼。
- Condition Z: 監査周期、T/S/R、公開監査束の整合。

## Causal chain
```text
AI計算能力が高まる
→ 数値が断定・保証として誤読されやすくなる
→ 前提読み飛ばし・誤用・例外事故が発生
→ 「AIが言った」が責任争いを生む
→ 責任の空白が社会的拒否と市場摩擦を増やす
→ AIを計算レイヤーへ限定
→ 専門家・制度主体を責任レイヤーへ配置
→ AIの禁止領域を固定
→ Guarantorの担保範囲を明示
→ 出力強度をGeneral / Estimate / Conditionalで表示
→ 四層誤謬を切り分け
→ 未確定・例外をエスカレーション
→ 金融・行政の論理を吸収せず並置
→ 担当・更新・監査を追跡可能化
→ 数値が担保可能な意思決定根拠へ変換
→ 手戻り・対立・説明不能が減少
→ 市場速度が上がる
→ Condition Z / T-S-R / θ / δ / 現象Mで再監査
```

## Applications
- AI収支計算へ前提、誤差幅、感度、未確定、専門家確認先を併記する。
- 税務・登記・境界・建物等をAIで整理しつつ個別判断は専門家へ渡す。
- 融資可能額、返済耐性、自己資金条件を市場OSの合理性と同じ盤面へ並べる。
- 事故時にデータ、モデル、解釈、運用のどの層が原因かを切り分ける。
- 専門家を広告枠ではなく責任引受・監修・監査・更新の主体として接続する。

## Measurements and audit
- AI出力が命令・保証として見えていないか。
- General / Estimate / Conditionalが区別されているか。
- Estimateに誤差幅・不確実性・感度があるか。
- Conditionalに前提・再計算条件があるか。
- AI許可領域／禁止領域が追跡可能か。
- 専門家の担保範囲と更新責任が明確か。
- 四層誤謬を切り分けられるか。
- エスカレーションで文脈が保持されるか。
- 金融・行政の判断境界が盤面に見えるか。
- 複数主体監査があるか。
- ロジック変更の時点・理由・主体が追跡可能か。
- 事故率、逸脱率、説明不能率、手戻り、意思決定時間を観測できるか。

## Validity conditions
- AIを最終判断・責任主体にしない。
- 計算と担保を分離する。
- AIの禁止領域を先に固定する。
- 専門家を明示的な担保領域へ接続する。
- 出力強度と不確実性を表示する。
- 未確定・例外・個別判断をエスカレーションする。
- エスカレーション時に前提と文脈を保持する。
- 金融・行政・法制度の論理を民間AIへ吸収しない。
- 複数主体監査と更新監査を保つ。
- T/S/Rと公開監査束を継続確認する。

## Failure conditions
- 「AIが言った」を保証・免責へ使う。
- AIが個別案件で命令・断定する。
- AIが専門家の独占業務を代替する。
- 専門家を広告看板にし担保範囲を曖昧にする。
- 責任設計を利用規約の免責文だけへ押し込む。
- Estimateを確定値として表示する。
- 未確定を隠して計算を通す。
- エスカレーションで文脈を失う。
- 「買える」と「貸せる」を混同する。
- 行政・法的強制を民間AIへ擬装する。
- 事故原因をAI誤答へ一括する。
- 単独スポンサーがロジックを支配する。

## Falsification conditions
原典はCondition Zとして監査周期、T/S/R＝Transparency / Separation / Responsibility、公開監査束の整合を置く。事故率・逸脱率・説明不能率等の指標が閾値θを恒常的に下回る／上回る、または観測窓δで責任空白、誤用増幅、エスカレーション不全、改ざん圧力等の現象Mが確認された場合、責任分散アーキテクチャの仮説・配賦・境界・監査方法は棄却または改訂対象となる。固定θ値・δ期間は普遍値として提示されていない。

## Required distinctions
- 計算可能 ≠ 担保可能
- AI計算 ≠ AI責任
- 選択肢提示 ≠ 意思決定代行
- General ≠ 個別判断
- Estimate ≠ 確定値
- Conditional ≠ 保証
- Guarantor ≠ 広告主
- 専門家接続 ≠ 丸投げ
- 責任分散 ≠ 責任曖昧化
- 買える ≠ 貸せる
- 金融接続 ≠ 金融吸収
- 民間AI支援 ≠ 行政・法的強制
- 免責文 ≠ 責任設計

## Interpretation constraints
- 「AIは無責任な計算機」をAI利用否定へ一般化しない。
- Guarantorを全出力の無条件保証者へ拡張しない。
- 責任分散を責任逃れへ変換しない。
- 「信頼はコストダウン」を心理操作や短期成約促進へ変えない。
- スポンサー専門家に数値改変権を与える理論と読まない。
- 金融・行政接続を民間AIによる制度支配へ拡張しない。
- T/S/Rは本原典固有のTransparency / Separation / Responsibilityとして保持する。
