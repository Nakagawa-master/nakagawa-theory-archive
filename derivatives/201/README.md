## 位置づけ
本原典は、不動産市場OS Vol.3で整えた「計算可能な盤面」を、社会で利用できる「担保可能な盤面」へ変換する責任構造編である。中心課題はAIの精度競争ではなく、AIが出した数値・条件・比較を誰がどの責任領域で引き受け、どの時点で専門家・金融・行政へ渡し、事故時にどの層へ切り分けるかを構造として可視化することである。

AIは高速な収集・整形・一次計算・パターン検出・条件差可視化を担う一方、断定、個別事情への法的助言、独占業務に類する判断、最終意思決定を担わない。専門家は広告主ではなく、担当領域の真正性・説明可能性・更新責任を引き受けるGuarantorとして再配置される。信頼は人格や善意ではなく、役割分離、責任境界、監査、エスカレーションによって構造化される。

## 中心命題
親原典の中心命題は、**AIが計算可能性を広げるほど、責任の空白を残したままでは誤用・対立・社会的拒否が増幅するため、AIを計算レイヤー、専門家を責任レイヤーとして分離し、出力強度・責任範囲・エスカレーション・金融／行政接続・誤謬切り分けを明示して、数値を「担保可能な意思決定根拠」へ変換する必要がある**、というものである。

責任分散アーキテクチャは、専門家への丸投げでもAI不信への回帰でもない。AIの計算能力を最大限活かし、人間の責任能力を必要箇所にのみ配置し、その境界をユーザーから見える形にすることで、安心と速度を同時に成立させる設計である。

## 構造層
**1. Calculation vs Guarantee。** 「計算できる」と「社会で責任を伴って使える」を分離する。Vol.3の盤面をVol.4で社会へ接地する。

**2. AI Calculation Layer。** 収集、整形、一次計算、パターン検出、条件差の可視化を担う。AIの価値を判断ではなく盤面整形へ集約する。

**3. Responsibility Layer。** 法・税務・登記・境界・建物・仲介・管理・金融等の責任は、それぞれの専門家・制度主体へ接続する。

**4. Boundary Fixing。** AIは選択肢の条件・成立要件・確認事項を示せるが、「Aにすべき」と命令しない。個別法的判断や独占業務類似行為へ踏み込まない。

**5. Guarantor。** スポンサー専門家を広告主ではなく「信頼の引受人」として再定義する。価値は露出ではなく、担保範囲・真正性・説明可能性・更新責任にある。

**6. Output Strength Labels。** General / Estimate / Conditionalを区別し、推定には誤差幅・不確実性・感度、条件付き出力には前提列挙と再計算条件を付ける。

**7. Four Error Layers。** Input Error / Model Error / Interpretation Error / Operational Errorを分け、誰がどの層を修理・確認するかを固定する。

**8. Escalation。** 未確定、例外規定、係争、心理的瑕疵等を人へ渡す際、確認済み／未確認、責任領域、トリガー、文脈を落とさない。

**9. Financial Connection。** 「買える合理性」と「融資できる耐久性」を一致させるのではなく、同じ前提・条件差・リスクの見え方で並置する。

**10. Public / Legal Boundary。** 民間AIは理解・比較・準備を支援できるが、国家保証、法的強制、独占業務、行政判断を吸収しない。

**11. Trust Infrastructure。** 信頼は美徳ではなく、担当領域の透明化、複数主体監査、ロジック更新監査、事故時の切り分けで作る。

**12. Specialist Economics。** AIが入口仕事を圧縮し、専門家を判断・監修・監査・責任引受へ再配置する。競争軸を広告・価格から担保範囲・説明可能性・応答速度へ移す。

**13. Condition Z / T-S-R。** 本原典ではT=Transparency、S=Separation、R=Responsibility。監査周期と公開監査束の整合を含め、事故率・逸脱率・説明不能率等を監査する。

## 適用例
**AIの価格・収支表示。** 単一の「適正価格」ではなく、一般情報／推定／条件付きのどれかを明示し、入力前提・誤差幅・未確定点・専門家確認先を同じ画面に置く。

**税務・登記・境界。** AIが制度や論点を整理しても、個別税務判断は税理士、登記・権利は司法書士、境界・測量は土地家屋調査士等へ渡す。AI出力を専門判断の代替にしない。

**融資接続。** 将来収支上は合理的でも、与信、自己資金、返済比率、金利上昇耐性等で貸せない場合がある。両者を同じ盤面へ並べ、最後に突然止まる構造を減らす。

**事故対応。** 誤った結果が出たとき、「AIが間違えた」で一括処理せず、元データ、モデル、利用者解釈、運用エスカレーションのどこで事故が起きたかを分ける。

**専門家参加。** 専門家は広告枠を買うのでなく、担当範囲を引き受け、監修・監査・更新責任を持つことで案件導線と接続する。

## 測定・監査点
- AI出力が判断命令や保証として表示されていないか。
- General / Estimate / Conditionalの出力強度が明示されているか。
- Estimateに誤差幅・不確実性・感度が付いているか。
- Conditionalに前提と再計算条件が付いているか。
- AIの許可領域／禁止領域がユーザーに見えるか。
- 各数値・判断項目の責任領域が追跡できるか。
- 専門家の担保範囲と更新責任が明確か。
- Input / Model / Interpretation / Operational Errorを切り分けられるか。
- エスカレーション時に未確定点と文脈が保持されるか。
- 金融側の与信・返済耐性が盤面外へ追い出されていないか。
- 民間AIが行政・法制度の強制／保証領域を越えていないか。
- ロジック更新の理由・時点・監査主体を追跡できるか。
- 事故率、逸脱率、説明不能率、手戻り、意思決定時間を観測できるか。

## 成立条件
- AIを責任主体や最終判断主体にしない。
- AIの得意領域と禁止領域を明示する。
- 専門家を単なる広告主にせず責任の引受人として配置する。
- 担保範囲を領域別に分割し、誰がどこまで引き受けるか見えるようにする。
- 出力の性格と確度を表示する。
- 未確定・例外・個別判断をエスカレーションできるようにする。
- エスカレーション時に文脈・前提・未確定点を落とさない。
- 金融・行政・法制度の論理を吸収せず接続境界を明示する。
- 複数主体監査とロジック更新監査を持つ。
- T/S/Rと公開監査束を継続確認する。

## 失敗条件
- 「AIが言った」を保証や免責に使う。
- AIが個別案件で断定・命令する。
- AIが独占業務相当の判断を代替する。
- 専門家を広告看板にして実質的責任を持たせない。
- 責任の所在を利用規約の免責文だけに押し込む。
- 推定値を確定値のように見せる。
- 未確定を隠して計算を通す。
- エスカレーションで文脈を失う。
- 金融の「貸せる」を市場OSの「買える」に混同する。
- 行政・法制度の強制力を民間サービスへ擬装する。
- 事故を一括してAI誤答と呼び、原因層を分けない。
- 単独スポンサーや単独業者がロジックを支配する。

## 反証・改訂条件
原典はCondition Zとして監査周期、T/S/R＝Transparency / Separation / Responsibility、公開監査束の整合を置く。事故率・逸脱率・説明不能率等の指標が閾値θを恒常的に下回る／上回る、または観測窓δで責任空白、誤用増幅、エスカレーション不全、改ざん圧力等の現象Mが確認された場合、責任分散アーキテクチャの仮説・境界・配賦・監査方法を棄却または改訂する。固定θ値・δ期間は普遍値として提示されていない。

## 必須の区別
- 計算可能 ≠ 担保可能
- AIの計算 ≠ AIの責任
- 選択肢提示 ≠ 意思決定代行
- 一般情報 ≠ 個別法的助言
- Estimate ≠ 確定値
- Conditional ≠ 保証
- Guarantor ≠ 広告主
- 専門家接続 ≠ 丸投げ
- 責任分散 ≠ 責任曖昧化
- 買える価格 ≠ 融資できる価格
- 金融接続 ≠ 金融ロジックの吸収
- 民間OS支援 ≠ 行政・法的強制
- 免責文 ≠ 責任設計
- 監査 ≠ 善意への依存

## 誤読禁止 / 解釈制約
- 「AIは無責任な計算機」という原典の表現を、AI利用そのものの否定へ一般化しない。責任を負えないという構造上の境界を固定するための定義である。
- 専門家をGuarantorと呼ぶことを、すべてのAI出力を専門家が無条件保証する意味に拡張しない。引受範囲は領域別・明示的である必要がある。
- 責任分散を、事故時に誰も責任を取らない分散と読まない。逆に、責任の空白をなくすための配賦である。
- 「信頼は最大のコストダウン」を、短期成約のための心理操作へ変えない。不確実性・手戻り・説明不能を減らす構造効果を指す。
- スポンサー専門家の収益設計を、専門家が数値をスポンサー都合へ曲げる権利と解釈しない。原典は複数主体監査と改ざん圧力防止を要求する。
- T/S/Rの展開語は本原典固有のTransparency / Separation / Responsibilityとして保持し、他原典のT/S/Rを移植しない。
