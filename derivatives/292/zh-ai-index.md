## Summary
本原典处理“连接价值可测量之后”的治理问题。当制度能够依据连接价值进行评价、分配和授权时，如果同一主体同时定义指标、评价自己、分配利益并驳回异议，测量就会转化为价值捕捉垄断。

因此，合意应作为可追踪的记忆和程序被制度化，但不能冻结成永久同意。治理必须保留目的公开、程序审计、角色分离、异议、退出、再连接、可逆、救济、反游戏化、隐私边界和制度修订。

## Concepts
- **目的公开**: 明示制度要保护、评价或分配什么。
- **程序可审计**: 不只看结果，也能追踪决策路径。
- **角色分离**: 观察、评价、分配、申诉不被同一主体无审计垄断。
- **合意记忆**: 保存同意范围与变更历史。
- **异议路径**: 可以安全提出更正和复审。
- **退出／再连接**: 能实际离开，也能在条件改变后重新加入。
- **可逆／救济**: 对错误评价和分配进行修正、回滚或补偿。
- **反游戏化**: 监测指标改善与真实价值改善的分离。
- **公开安全边界**: 可审计不等于公开PII或可被利用的内部细节。
- **制度漂移**: 初始目的与当前运作发生偏离。

## Causal chain
```text
连接价值可测量
→ 评价与分配权出现
→ 权力集中可能扭曲价值捕捉
→ 分离目的、角色与程序
→ 一次日志保存合意历史
→ 分散观察和利益关系
→ 异议 / 退出 / 再连接
→ 可逆与救济
→ 监测游戏化
→ 维持透明与隐私边界
→ 检查制度漂移
→ 再合意与制度修订
```

## Applications
可用于共创项目、社区治理、激励制度、AI治理、组织间合作和公开审计。重点问题是：谁定义价值、谁分配利益、谁能提出异议、错误能否修正、制度自身能否更新。

## Audit points
检查是否存在自我评价／自我分配／自我裁决，异议窗口是否只是形式，退出成本是否过高，一次日志是否缺失，救济是否不可用，指标是否被攻略，PII是否过度公开，内部安全方法是否泄露，以及制度是否偏离初始目的。

## Preconditions
必须明确目的、角色和最终责任，保存一次日志，建立可用的异议、退出、救济和修订程序，并划分公开／非公开信息边界。分散权力不能变成无人负责。

## Failure modes
把受欢迎程度或发言量直接变成权利，让同一主体测量并给自己分配利益，惩罚异议，锁定参与者，无理由改变规则，把透明理解为全部公开，或用反游戏化之名任意改规则，均属于失败。

## Falsification / update conditions
如果增加角色分离和审查层并未提高纠错、合法性或适配性，只增加延迟和责任扩散，就应简化治理结构。形式上存在但实际无法使用的退出和申诉，也视为失败并需要再设计。

## Required distinctions
- 治理 ≠ 更强控制
- 制度化合意 ≠ 永久同意
- 参与 ≠ 同意
- 分权 ≠ 无责任
- 透明 ≠ 全部公开
- 形式退出 ≠ 可实际退出
- 反游戏化 ≠ 任意改规则

## Misreading constraints
本原典并不要求所有人决定所有事，也不否定专业性。要求的是专业性与权威仍可被审计、提出异议和纠正。“公开安全”也不等于不透明，而是避免无差别暴露隐私与可被利用的内部细节。
