## Summary
旧制度が現実の生活機能を担っている状態で新制度へ即時切替すると、機能断絶・不利益・反発を生み得る。秩序ある置換は、新旧を一定期間デュアル運用し、責任境界、実機能の代替能力、救済、rollback、終了条件を観測しながら、新系が担う範囲を増やして旧系を段階縮退する移行設計である。

## Concepts
- 秩序ある置換: 機能代替を確認しながら段階的に新系へ移ること。
- デュアル運用: 新旧二系を移行期間だけ並走させること。
- 実機能代替: 新系が旧系の現実的役割を実運用で担える状態。
- 移行境界: 新旧それぞれの責任・適用範囲・例外の分離。
- rollback: 致命的失敗時に安全な状態へ戻す経路。
- 反発吸収: 異議・不安・不利益を設計改善情報として読むこと。
- 置換比率: 新系が担う確認済み機能・範囲の拡大度。
- 旧系縮退: 依存が下がった範囲だけ旧系を減らすこと。

## Causal chain
```text
旧系が不可欠機能を担う
→ 即時切替は断絶リスクを生む
→ デュアル運用
→ 責任・境界を明示
→ 新系の代替能力を実地観測
→ 失敗・反発を修正へ接続
→ 救済・rollbackを保持
→ 確認済み範囲だけ置換率上昇
→ 信頼・運用能力が新系へ移転
→ 旧系依存が低下
→ 旧系を段階縮退
→ 秩序ある置換
```

## Applications
- 公共制度の段階移行。
- 基幹業務システムの切替。
- 決済・評価・価値配分方式の転換。
- 新しい合意形成手続の導入。
- データ・組織・権限構造の移行。

## Measurements and audit
- 旧系の不可欠機能が列挙されているか。
- 新系が代替した機能を実体で確認できるか。
- 新旧の責任境界が明示されているか。
- 失敗時の救済とrollbackが利用可能か。
- 二重運用コストが把握されているか。
- 反発が原因分類され設計修正に接続されるか。
- 旧系依存が実質的に低下しているか。
- デュアル運用に終了条件があるか。

## Validity conditions
- 新旧双方の適用範囲を分けられる。
- 新系の代替対象を具体化できる。
- 実運用を観測できる。
- 不利益・異常・異議を取得できる。
- 救済とrollbackが存在する。
- 置換判断を理念だけで行わない。

## Failure conditions
- 旧系を先に停止する。
- 新制度の存在を代替能力の証拠とみなす。
- 並行運用の責任主体を曖昧にする。
- 反発を一律にノイズとして除去する。
- rollbackを設けない。
- 二重運用を無期限化する。
- 利用率のみで移行完了と判断する。

## Falsification conditions
デュアル運用にもかかわらず機能断絶・不利益が減らない、責任衝突が増える、rollbackが実効性を持たない、二重コストが恒常的に支配する、または置換した範囲で旧系依存が再発する場合、現在の移行設計は棄却または改訂対象となる。

## Required distinctions
- 即時切替 / 秩序ある置換
- デュアル運用 / 永久二重化
- 制度開始 / 実機能代替
- 利用率 / 代替能力
- rollback / 改革放棄
- 反発 / 設計フィードバック
- 旧系維持 / 旧系依存固定
- 制度変更 / 信頼・運用能力移転

## Interpretation constraints
固定の移行期間、置換割合、KPI、閾値を本派生から新設しない。デュアル運用自体を安全性の証明と扱わない。旧系を悪、新系を善とする価値二分法へ縮約しない。中心は実機能を失わず代替能力を検証し、可逆に置換範囲を広げる因果構造である。
