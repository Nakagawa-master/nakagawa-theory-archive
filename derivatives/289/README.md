## 位置づけ
本派生物は、提案を「最後の説得」ではなく、それまでの接触・対話で得た顧客自身の言葉と因果を再編集し、納得が自然に起こる順序へ並べる構造設計として展開する。

## 中心命題
提案の役割は相手を押すことではない。相手が語った現在地、課題、未来像を因果でつなぎ、何を満たすか、なぜ今・なぜこの経路か、どの条件で実行するかを理解可能な順番へ置くことで、意思決定を「理解の完成」として成立させる。

## 因果線
```text
接触・対話で顧客の言葉を取得
→ 現状・課題・未来像を因果網へ整理
→ What: 何を満たす提案かを先に提示
→ Why now / Why us: タイミングと独自性を整理
→ How much: 価値理解の後に価格・条件を提示
→ 社内稟議用に目的適合・工数負荷・回収可能性へ翻訳
→ 顧客自身が組織内で再説明可能になる
→ 理解が結晶化
→ 自律的な決断
```

## 納得の順序
1. **What**: 何を満たすのか、未来像と提供価値の全体像。
2. **Why now / Why us**: なぜ今か、なぜこの支援か。タイミングと独自性。
3. **How much**: 価値と適合性が理解された後の価格・条件。

## 社内稟議への翻訳
提案は担当者一人だけに理解されても閉じない。組織内で再説明できるよう、少なくとも以下を整える。
- 目的適合: 自社方針・目標とどうつながるか。
- 工数負荷: 現場で実行可能か。
- 回収可能性: 費用に対してどの価値・効果が期待できるか。

## 状態モデル
```yaml
- customer_language_preserved
- current_problem_future_causality_mapped
- value_image_presented_first
- timing_and_uniqueness_explained
- price_presented_after_value
- internal_approval_translation_ready
- customer_can_reexplain
- pressure_avoided
- decision_emerges_from_understanding
```

## 適用例
- 提案資料1枚目に顧客自身の言葉で現状と課題を置く。
- 2枚目で未来像と提供価値、3枚目で独自性、4枚目で価格条件を置く。
- 稟議者向けには目的適合、工数、回収可能性を短く再構成する。

## 測定・監査点
- 顧客の言葉が提案書に残っているか。
- 価格が価値像より先に出ていないか。
- 情報量が意思決定帯域を超えていないか。
- 「今だけ」「おすすめ」等の圧迫表現へ依存していないか。
- 担当者が自社内で提案理由を再説明できるか。

## 成立条件
顧客の言葉、因果網、納得順序、社内再説明性、非圧迫、選択肢比較、価格条件の透明性が成立すること。

## 失敗条件
情報過剰、スライド過多、圧迫表現、顧客言語の消失、価値理解前の価格提示、担当者だけに依存する提案。

## 反証・改訂条件
順序設計を用いても理解、稟議通過後の適合、契約後価値が改善せず、むしろ誤解・手戻り・圧迫感が増える場合、提案構造を改訂する。

## 必須の区別
- 提案 ≠ 説得
- 納得順序 ≠ 心理操作
- 独自性 ≠ 他社否定
- 稟議支援 ≠ 顧客組織への介入
- 決断 ≠ 説得の戦利品

## 原典回帰
提案の再定義、What→Why now/Why us→価格の順序、社内稟議への翻訳、禁じ手、実務プレイブックはParent本文を正本とする。
