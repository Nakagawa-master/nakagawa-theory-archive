## 位置づけ
AI倫理をモデル単体の善悪ではなく、開発者、提供者、導入者、利用者、判断者、影響当事者を結ぶ接続経路の責任として整理する。害や誤作動が複数主体の継ぎ目で生じるとき、誰も単独で全責任を負わないことと、誰も責任を負わないことを明確に区別する。

## 中心命題
AIによる結果は、モデル出力だけでなく、目的設定、データ、モデル選択、UI、導入文脈、人間の採用判断、監督、異議処理が連鎖して成立する。責任をモデルや最終利用者一人へ集約すると接続部の失敗が消えるため、各接続点で「何を知り、何を選び、何を止められたか」を記録し、影響当事者からの反証と是正を同じ経路に戻す必要がある。

## 因果線
目的設定 → データ・モデル選択 → 出力生成 → 人間・組織が採用 → 実世界へ作用 → 接続部で誤差・権力差が増幅 → 被影響者が異議 → 責任経路を遡及 → 是正・再設計 → 再接続。

## 構造層
1. 起点層：誰の目的・問いから始まったか。
2. 技術層：データ、モデル、制約、既知限界。
3. 採用層：誰が出力を選び実装したか。
4. 影響層：誰が便益・損害を受けたか。
5. 救済層：異議、停止、訂正、補償、再設計。

## 適用例
1. 採用AIでベンダー・人事・管理職の役割を分ける。
2. 医療支援AIで提案と最終判断責任を区別する。
3. 公共AIで異議申立てと人間再審査を確保する。
4. 生成AIで出力・編集・公開・拡散の責任経路を残す。

## 測定・監査点
責任経路追跡率、既知限界表示率、人間採用記録率、異議受付率、是正時間、被影響者参加率、再発率。

## 成立条件
目的を署名する。モデル限界を明示する。採用主体を記録する。影響当事者を特定する。異議・停止・救済を用意する。再発防止を上流へ戻す。

## 失敗条件
AIへ責任を丸投げする。逆に人間だけへ全責任を押しつける。接続ログを残さない。影響当事者を排除する。異議を受付だけで終える。修正を末端の注意喚起だけにする。

## 反証条件
接続責任の可視化が誤作動減少や救済改善に寄与しない。単一責任主体モデルの方が一貫して迅速・公平に是正できる。接続ログが責任希薄化しか生まない。被影響者参加が改善に寄与しない。上流修正が再発率を下げない。

## 必須の区別
AI寄与/AI責任、生成/採用、技術限界/運用誤り、分担責任/責任希薄化、異議/敵対、説明/救済、ログ/責任確定。

## 誤読禁止
AIを道徳主体と自動認定しない。ベンダー免責に使わない。利用者へ全責任を転嫁しない。ログ量を倫理品質と同一視しない。異議をモデル改善材料だけに収奪しない。派生を法的責任判断の代替にしない。
