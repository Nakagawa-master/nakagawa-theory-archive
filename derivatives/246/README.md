## 位置づけ
本Parentは成立条件論・第1論で対象側の「成立」を定義した後、認識主体側の「理解」を定義する第2論である。中心課題は、情報を知っている、説明を聞いた、専門用語を使える、経験が長い、AIが要約できる、といった状態をそのまま理解成立とみなさず、**対象が成立する条件を、必要な範囲と粒度で把握しているか**へ判定軸を移すことにある。

Parentは「知っている」と「理解している」を分ける一方、説明できないなら理解していないとも定義しない。熟練者が高粒度な条件差を把握しながら十分に言語化できていない場合があり、逆に流暢な説明だけが存在して成立条件を把握していない場合もあるからである。理解は情報量、語彙量、説明の滑らかさではなく、条件変化に対して成立／不成立を扱える構造として定義される。

## 中心命題
**理解とは、対象が成立するための条件を、問い・目的に必要な縦因果範囲と理解粒度で把握し、条件差・因果・例外・未把握範囲を扱える状態である。**

情報は理解の材料であって理解そのものではない。情報が条件へ接続され、条件が因果へ接続され、因果が成立と未成立の差へ接続されたとき、認識主体は対象を再利用可能な形で扱えるようになる。

また「細かければ細かいほど理解が深い」とはしない。必要粒度は目的依存であり、局所処理を改善する問いと制度全体を設計する問いでは必要な縦因果範囲が違う。広く見ても粗ければ条件差は見えず、細かく見ても局所に閉じれば全体理解にはならない。

## 因果線
対象へ接触する → 名称・概要・事例・説明等の情報を得る → 情報だけを理解と同一視すると「分かった感」が先行する → 対象が成立する条件を識別する → どの縦因果範囲まで見る必要があるかを定める → 目的に必要な粒度まで条件差を分ける → 条件間の因果、順序、例外、摩擦、停止点を接続する → 条件変更時に成立／不成立の差を判定する → 未把握条件を不明として保持する → 判断・設計・説明・監査へ再利用する。

## 構造層
1. **情報層** — 名称、事実、説明、事例、経験、AI出力等を得る。
2. **親近感層** — 情報や説明の流暢さから「分かった」と感じる。
3. **成立条件識別層** — 対象が成立するために何が必要かを特定する。
4. **縦因果範囲層** — L1〜L6等、問いに必要な因果範囲を定める。
5. **理解粒度層** — その範囲でどの細かさまで条件差を判定する必要があるかを定める。
6. **因果接続層** — 条件、順序、依存、摩擦、例外、停止点をつなぐ。
7. **観測・反証層** — 条件変更時の結果差や成立しない条件を確認する。
8. **不確実性層** — 自分が把握していない範囲を未知として保持する。
9. **再利用層** — 理解を新しい判断・設計・監査へ使う。

## 状態モデル
未接触相 / 情報取得相 / 分かった感相 / 成立条件識別相 / 縦因果範囲設定相 / 必要粒度適合相 / 因果接続相 / 観測・反証相 / 不確実性保持相 / 再利用可能相。

## 適用例
制度設計では制度目的を説明できるだけでなく、誰が何を担い、どの順序で処理し、どこで例外が発生し、何が変われば結果が変わるかまで必要粒度で把握する。現場の特定処理だけを扱うなら局所理解で足りる場合があるが、その理解を制度全体へ一般化するなら縦因果範囲を広げる必要がある。

AI利用では、LLMが文章を要約できることと、現実化に必要な成立条件を保持していることを分ける。どの条件を落としたか、条件が変わったとき出力がどこまで有効か、未把握部分を不明として保持できるかを見る。

## 測定・監査点
情報量や説明の流暢さを理解の代理指標にしていないか。対象の成立条件を識別できるか。問いに必要な縦因果範囲を明示できるか。必要粒度を粗すぎず細かすぎず設定できるか。条件変更時に結果差を判定できるか。成立しない条件や例外を識別できるか。未把握部分を確定済みへ変換していないか。局所理解を全体理解へ無断で拡張していないか。

## 成立条件
理解が成立するには、対象が成立するための条件を問いに必要な範囲で識別し、その条件を目的に必要な粒度で扱い、条件間の因果と成立／未成立の差へ接続できる必要がある。また、把握していない範囲を未知として保持し、条件が変われば判断を更新できることが必要である。

## 失敗条件
情報量、専門用語、経験年数、要約能力、説明の滑らかさだけを理解と同一視すること。縦因果範囲を示さず局所理解を全体理解として扱うこと。細分化そのものを理解とみなすこと。条件を列挙して因果をつながないこと。未知・例外・未把握範囲を削除すること。

## 反証・改訂条件
成立条件を必要範囲・必要粒度で把握しなくても、条件変更時の成立／不成立を一貫して正しく判定し、設計・予測・検証を同等以上に行えることが継続的に確認される場合、本理解定義の適用範囲を改訂する。また、粒度を高めても判断性能が改善せず、より粗いモデルの方が安定する領域では必要粒度の決定方法を見直す。

## 必須の区別
- 情報 ≠ 理解。
- 説明可能性 ≠ 理解そのもの。
- 経験年数 ≠ 成立条件把握。
- AI要約 ≠ 構造理解。
- 縦因果範囲 ≠ 理解粒度。
- 広い範囲 ≠ 高粒度。
- 局所理解 ≠ 全体理解。
- 細分化 ≠ 必要粒度。
- 未知の保持 ≠ 理解不足の隠蔽。

## 誤読防止／解釈制約
「全部を完全に知るまで理解ではない」「細かく説明できる人ほど必ず理解している」「AIが要約できるなら理解している」と解釈しない。Parentが定義するのは、問いに必要な範囲と粒度で成立条件を扱えるかという構造的理解であり、意識や主観的理解の有無を判定する理論ではない。
