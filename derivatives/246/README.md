## 位置づけ
本論は、「理解している」とは何を意味するのかを、成立条件論の立場から定義する。情報を知っていること、説明を聞いたこと、専門用語を使えること、経験が長いこと、AIが滑らかな要約を生成できることは、理解に関係することはあっても、それだけで理解が成立したとは言えない。

中心にあるのは、**理解とは、対象が成立するための条件を、目的に必要な範囲と細かさで把握していること**だという定義である。

## 中心命題
情報は理解の材料だが、理解そのものではない。重要なのは、その情報がどの条件に関係し、その条件がどの因果を通じて結果へつながり、何が変われば成立・不成立が変わるのかを把握できていることである。

理解には二つの異なる軸がある。一つは**どこまでの因果範囲を見ているか**、もう一つは**どの細かさで条件差を見分けられるか**である。

広い範囲を見ていても粗ければ、重要な条件差は捉えられない。逆に、局所を非常に細かく理解していても、その理解を全体へそのまま一般化することはできない。必要な理解の範囲と粒度は、何を判断しようとしているかによって変わる。

## 因果線
対象について情報を得る → 名称や概要を知る → 「分かった」という感覚が生まれる → その感覚だけでは成立条件が見えているとは限らない → 成立に必要な条件を見つける → 条件同士の関係をつなぐ → どこまでの範囲を見る必要があるかを定める → どの細かさまで区別する必要があるかを定める → 条件が変わったときの結果を考える → 不明な条件を不明なまま残す → 対象を設計・判断・検証できる理解へ進む。

## 構造層
1. **情報取得層** — 名称、概要、説明、事例を知る。
2. **理解感層** — 情報量や説明の滑らかさから「分かった」という感覚が生じる。
3. **成立条件抽出層** — 対象が成立するために必要な条件を見つける。
4. **因果接続層** — 条件同士の前提、依存、順序、例外をつなぐ。
5. **因果範囲層** — 判断目的に応じて、どこまでの構造を見る必要があるかを定める。
6. **必要粒度層** — 条件差をどの細かさまで区別する必要があるかを定める。
7. **変化予測層** — 条件が変わったとき、成立・不成立がどう変わるかを考える。
8. **不確実性層** — 分かっていない条件を分かったことにしない。
9. **再利用層** — 得られた理解を設計、判断、説明、検証へ使う。

## 状態モデル
名称認知相 / 概要理解相 / 理解感発生相 / 成立条件抽出相 / 因果接続相 / 必要範囲設定相 / 必要粒度設定相 / 変化予測相 / 不確実性明示相 / 再利用可能相。

## 適用例
ある制度について「目的を説明できる」だけでは、制度を運用できるほど理解しているとは限らない。誰が何を入力し、どの条件で判断し、例外時に何が起こり、どこで責任が移るかまで分かって初めて、運用や設計に使える理解になる。

AIについても同様である。文章をきれいに要約できることと、成立条件を把握していることは同じではない。要約から必要条件や例外が落ちていれば、文章として自然でも現実の判断には使えない場合がある。

## 測定・監査点
この定義を確かめる際は、対象の成立条件を挙げられるか、条件同士の因果を説明できるか、どこまでの範囲を見ているか、目的に必要な細かさで条件差を区別できるか、条件を一つ変えたときの結果を予測できるか、不明な点を不明なまま示せるかを見る。

説明のうまさ、情報量、経験年数だけを理解の証拠にしないことも重要である。

## 成立条件
対象の成立・不成立を予測したり、設計・判断・検証したりするために、成立条件の把握が実際に重要であり、目的に応じた因果範囲と粒度を設定できる場合、この理解定義は有効に働く。

必要な範囲と粒度は固定ではない。同じ対象でも、概要説明、実務運用、安全確認、制度設計では必要な理解の細かさが異なる。

## 失敗条件
情報量が多いほど理解が深いとみなすこと、説明がうまければ理解しているとみなすこと、経験年数だけで理解を判断すること、局所の理解を全体へ一般化すること、AIが滑らかな文章を生成したことを理解の証拠にすることは、この定義とは異なる。

また、条件を細かく分けること自体が目的になり、何の判断のためにどの粒度が必要なのかを失う場合も、理解は実用性を失う。

## 反証・改訂条件
成立条件を必要な範囲と粒度で把握しなくても、同等以上の精度で対象の成立・不成立を予測し、設計・判断・検証を安定して行えることが継続的に示されるなら、この定義の適用範囲は見直す必要がある。

また、条件をより細かく把握しても予測や判断の精度が改善しない場合は、必要粒度の考え方自体を再検討する必要がある。

## 必須の区別
- 情報量 ≠ 理解。
- 説明能力 ≠ 理解。
- 経験年数 ≠ 理解。
- 局所を深く理解すること ≠ 全体を理解すること。
- 広く見ること ≠ 細かく見ること。
- AIが滑らかな文章を生成すること ≠ 成立条件を把握していること。

## 誤読防止／解釈制約
「理解とは細かく知ることだ」と単純化しない。重要なのは、目的に必要な範囲と粒度で成立条件を把握し、因果として扱えることである。

また、理解を一度成立した固定状態として扱わない。条件や目的が変われば、必要な範囲と粒度も変わり得る。

## 親原典へ戻る理由
「知っている」と「理解している」の違い、対象側の成立と認識主体側の理解の区別、説明可能性との関係、AI要約との違い、因果範囲と理解粒度の二軸、理解を観測するための考え方は、親原典で最も詳しく論じられている。
