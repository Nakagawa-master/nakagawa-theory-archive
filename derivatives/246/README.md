## 位置づけ
本論は「理解」という言葉を、知っている、聞いたことがある、説明を復唱できる、専門語を使える、といった認知的親近感から切り離す。成立条件論における理解とは、**対象が成立するために必要な条件を、目的に必要な粒度で把握し、条件同士の因果接続・欠損・例外・検証点を扱える状態**である。

ここで重要なのは「細かく知ること」そのものではない。必要粒度は目的依存である。概要説明を受け取るだけなら粗い粒度で足りることもある。しかし設計、意思決定、監査、実装、安全確認、AIによる構造把握など、条件欠落が結果を変える場面では、どの条件が成立に必要で、どの条件が欠けると何が止まるかまで降りなければ理解は成立しない。

本論は成立条件論・第0論の「局所全体化」問題、第1論の「成立とはL1からL6まで因果として通ること」という問題系を受け、理解の判定基準を定義する。関連するNakagawa OSの層構造、構造定義、暗黙知、合意形成、AI構造監査へ接続するが、派生側で独自の普遍スコアや固定閾値を追加しない。

## 中心命題
理解は、説明の流暢さや情報量ではなく、**成立条件を必要粒度で把握し、因果として再利用できるか**で判定する。

粗い説明でも人は「分かった」と感じることができる。AIも、語彙を豊富に使い、関連概念を滑らかに並べることで理解しているように見える。しかし、対象が成立するために必要な条件を特定できず、条件を外したときの影響を予測できず、どこを観測すれば成立/不成立を判定できるか分からないなら、その状態は成立条件論の意味での理解ではない。

逆に、すべてを無限に細分化する必要もない。目的に対して十分な粒度まで条件を分解し、条件間の接続、停止点、不確実性、検証方法を扱えることが理解の成立条件である。

## 因果線
```text
対象に接触する
→ 名称・概要・説明を取得する
→ 認知的親近感が生まれ「分かった感」が形成される
→ その感覚を理解と同一視すると条件欠落が残る
→ 対象が成立するための条件を抽出する
→ 判断目的に必要な粒度まで条件を分解する
→ 条件間の前提・依存・順序・例外を接続する
→ 条件が欠けた場合の停止点を予測する
→ 観測・検証可能な形へ落とす
→ 不確実性と未把握条件を明示する
→ 設計・判断・説明・監査へ再利用できる
→ 成立条件論上の「理解」が成立する
```

この因果線の核心は、「分かった感」から「成立条件の把握」へ判定軸を移すことである。理解は内面感情ではなく、対象を壊さず扱うための構造能力として定義される。

## 構造層
1. **接触層**: 対象の存在、名称、概要を知る。
2. **語彙層**: 用語、説明、事例を扱える。ここまでは知識であり理解を保証しない。
3. **親近感層**: 説明を聞いた回数や流暢さにより「分かった感」が生じる。
4. **成立条件抽出層**: 対象が成立するための必要条件・依存条件・環境条件を分けて置く。
5. **必要粒度層**: 目的に対して粗すぎず細かすぎない粒度へ条件を調整する。
6. **因果接続層**: 条件Aが満たされると何が可能になり、条件Bが欠けるとどこで止まるかを追う。
7. **観測・検証層**: 成立しているかを確認する観測点、反例、例外を設定する。
8. **不確実性管理層**: 未把握、仮説、推定、確定を区別する。
9. **再利用層**: 設計、意思決定、教育、説明、監査へ因果モデルを移せる。
10. **理解成立層**: 必要条件と限界を保持したまま対象を扱える。

## 状態モデル
- **U0 未接触**: 対象を知らない。
- **U1 名称認知**: 名前やカテゴリを知る。
- **U2 概要説明可能**: 一般的な説明や要約ができる。
- **U3 理解感発生**: 流暢に話せるため「理解した」と感じる。
- **U4 条件抽出**: 成立に必要な条件を列挙できる。
- **U5 粒度適合**: 目的に必要な細かさまで条件を分けられる。
- **U6 因果接続**: 条件間の依存・順序・停止点を追える。
- **U7 検証可能**: 欠損・変更・例外が結果へどう影響するかを観測できる。
- **U8 不確実性明示**: 未知や仮説を理解済みへ偽装しない。
- **U9 再利用可能**: 新しい判断や設計へ条件モデルを使える。
- **U10 理解成立**: 必要粒度・因果・検証・限界を保持して対象を扱える。

## 適用例
**制度設計**では「制度の目的を説明できる」だけで理解済みとせず、誰が何を入力し、どの条件で判断し、どこで責任が移り、何が成立/不成立になるかを必要粒度で把握する。

**業務改善**では、作業手順を暗記することと業務の成立条件を理解することを分ける。例外時に何が止まり、どの前提が崩れたかを追えれば、単なる手順記憶から構造理解へ移る。

**AI利用**では、LLMが滑らかな説明を返すことを理解の証拠にしない。必要条件、因果依存、観測点、反証条件、不明点を返せるかを監査する。RAGや知識グラフでも、文書が取得できたことと成立条件が把握できたことを分ける。

**教育**では、用語テストだけでなく「どの条件が欠けると成立しないか」「条件を変えたら何が起きるか」を説明させる。理解度を情報再生ではなく因果操作可能性で見る。

**契約・安全領域**では、概要理解をもって意思決定を進めず、成立条件・責任分界・例外・観測点を必要粒度まで明示する。

## 測定・監査点
- 対象の成立条件を列挙できるか。
- 列挙した条件は目的に対して必要な粒度か。粗すぎる/細かすぎる状態を区別できるか。
- 必要条件、十分条件、環境条件、依存条件を混同していないか。
- 条件間の因果・順序・前提を追えるか。
- 条件を一つ外したとき、どこで成立が止まるか予測できるか。
- 例外ケースを説明できるか。
- 成立/不成立を観測する指標や証拠へ接続できるか。
- 未知・仮説・推定を「理解済み」に変換していないか。
- 説明の流暢さを理解度の代理指標にしていないか。
- AIの場合、引用や検索結果の量を理解と同一視していないか。
- 一度成立した理解を、条件変化後も固定していないか。
- 目的が変わったとき必要粒度を再設定できるか。
- 理解した内容を設計・判断・監査へ再利用できるか。

## 成立条件
理解が成立するには、第一に、対象の成立条件が少なくとも判断目的に必要な範囲で抽出されていることが必要である。第二に、その条件が目的に必要な粒度へ調整されていること。第三に、条件同士の因果接続、停止点、例外を追跡できること。第四に、成立/不成立を観測・検証できること。第五に、未把握条件を理解済みとして隠さないことが必要である。

これらを満たしたとき、理解は「情報を持っている状態」から「対象の成立を扱える状態」へ移る。必要粒度は固定ではなく目的依存であり、同じ対象でも説明、設計、安全監査では必要な粒度が異なる。

## 失敗条件
- 名称を知っているだけで理解とする。
- 要約できる、説明を復唱できる、専門語を使えることを理解とする。
- 詳細情報の量が多いほど理解が深いとみなす。
- 成立条件を抽出しても、条件間の因果をつながない。
- 条件を無限に細分化し、判断目的を失う。
- 逆に、粗いカテゴリで停止点を隠す。
- 例外・不確実性を削除し、モデルを確定済みに見せる。
- AIの流暢さや検索量を理解の証拠にする。
- 一度の成功事例を成立条件全体の理解へ一般化する。
- 条件変化後も古い理解を更新しない。

## 反証・改訂条件
成立条件を必要粒度で把握しなくても、同等以上の精度で対象の成立/不成立を予測し、設計・判断・検証を安定して行える領域が継続的に確認される場合、この理解定義の適用範囲は改訂する必要がある。

また、条件をより細かく把握しても予測・設計・監査性能が改善せず、むしろ粗い表現の方が安定する場合は「必要粒度」の決め方を見直す。理解を細密化と同義にして反証不能にしてはいけない。

## 必須の区別
- 知識 / 理解
- 名称認知 / 成立条件把握
- 説明の流暢さ / 因果追跡可能性
- 情報量 / 必要粒度
- 細かさ / 目的適合粒度
- 条件列挙 / 条件接続
- 分かった感 / 検証可能性
- 一般則 / 例外条件
- 確定事項 / 仮説・不明点
- 文書取得 / 構造理解
- 局所的な正しさ / 対象全体の成立

## 誤読防止・解釈制約
本論は「全部を完全に知るまで行動するな」と言っているのではない。必要なのは、目的に照らして重要な成立条件と不確実性を把握し、どこから先が未確定かを明示できることである。必要粒度は無限分解ではない。

また「理解」を試験得点や知識量へ単純変換しない。AIについても、モデル内部に人間と同じ意味で理解があるかという意識論を扱うのではなく、成立条件を必要粒度で取り出し、因果・欠損・検証へ使えるかという運用上の判定軸として読む。
