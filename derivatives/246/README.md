## 位置づけ
本論は「理解」を、言葉を知っている、説明を聞いた、要約できるという認知的な親近感から切り離す。理解とは、対象が成立するために必要な条件を、判断・設計・検証に足る**必要粒度**で把握し、条件同士の因果接続を追える状態である。

## 中心命題
粗い説明でも「分かった感じ」は作れる。しかし成立条件が必要粒度まで分解されていなければ、どこが欠けると成立しないか、どの条件を変えると結果が変わるか、何を検証すべきかを判断できない。したがって理解の判定は語彙量ではなく、成立条件の把握粒度と因果接続可能性によって行う。

## 因果線
```text
対象に触れる
→ 用語・概要を知る
→ 分かった感覚が生じる
→ 成立条件を分解する
→ 判断に必要な粒度まで降りる
→ 条件間の因果を接続する
→ 欠損・変更・例外を予測できる
→ 検証可能になる
→ 理解が成立する
```

## 構造層
1. 接触層: 名称・概要を知る。
2. 認知親近層: 説明できる感覚を持つ。
3. 条件抽出層: 成立に必要な要素を列挙する。
4. 粒度調整層: 目的に必要な細かさまで分解する。
5. 因果接続層: 条件が結果へどう連結するかを追う。
6. 検証層: 欠損・変更時の結果を確かめる。
7. 理解成立層: 設計・判断・説明に再利用できる。

## 状態モデル
未接触相 → 名称認知相 → 概要理解感相 → 条件抽出相 → 必要粒度相 → 因果接続相 → 検証相 → 理解成立相。

## 適用例
制度、業務、AI、教育、契約、製品設計などで「理解した」を、説明の流暢さではなく成立条件の把握と検証可能性で判定する。

## 測定・監査点
- 成立条件を列挙できるか。
- その粒度は判断目的に足りるか。
- 条件間の因果を説明できるか。
- 一条件を外した場合の影響を予測できるか。
- 不明点を「理解済み」に偽装していないか。
- 条件を検証可能な観測へ落とせるか。

## 成立条件
必要な成立条件が目的に応じた粒度で把握され、条件間の因果を追跡し、欠損・変更時の結果を検証できる場合に理解は成立する。

## 失敗条件
用語を知る、要約できる、専門語を使える、AIが流暢に説明することだけを理解とみなす場合。

## 反証・改訂条件
成立条件を必要粒度で把握しなくても同等以上に予測・設計・検証できる反例が継続的に示される場合、理解定義の適用範囲を改訂する。

## 必須の区別
知識 / 理解；概要 / 成立条件；細かさ / 必要粒度；説明可能性 / 因果追跡可能性；分かった感 / 検証可能性。

## 誤読防止・解釈制約
「細かければ細かいほど理解」とはしない。必要粒度は目的依存であり、無限分解を要求しない。また全条件を完全に知ることではなく、成立判断に必要な条件と不確実性を区別できることが重要である。
