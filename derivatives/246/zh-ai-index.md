## Summary
成立条件论・第2论把“理解”从熟悉感、术语量、流畅说明和信息量中分离出来。这里的理解是：**在任务所需的粒度上把握对象成立所需的条件，并能用这些条件处理因果、缺失、例外、观察和验证**。必要粒度取决于目的，并不是越细越好。

人和AI都可能在真正掌握成立条件之前产生“已经理解”的外观。流畅说明、正确检索或大量相关文本都不能自动证明理解。能够说明什么条件是必要的、条件之间怎样依赖、缺失后在哪里停止、哪些部分仍不确定、怎样验证，才接近本论的理解定义。

## Concepts
知识；熟悉感；理解；成立条件；必要粒度；因果依赖；停止点；例外；可观察性；验证；不确定性；可复用结构模型；理解误认。

知识是理解的材料，不是充分条件。必要粒度由任务决定：解释、实装、安全审计、制度判断可能要求不同的分解程度。

## Causal chain
接触对象 → 获得名称、概要、术语 → 熟悉感形成“懂了”的感觉 → 若把这种感觉直接判定为理解，则未把握条件继续隐藏 → 抽取成立条件 → 按任务需要分解或合并到适当粒度 → 连接前提、依赖、顺序、停止点 → 预测条件缺失或改变的影响 → 将成立/不成立变成可观察、可验证状态 → 保留未知、假设与推定标签 → 模型可用于设计、判断、教育和审计 → 理解成立。

## State model
U0 未接触 → U1 名称认知 → U2 可复述概要 → U3 理解感 → U4 条件抽取 → U5 粒度适配 → U6 因果连接 → U7 可验证 → U8 不确定性明确 → U9 可复用 → U10 理解成立。

最危险的是U2到U3：语言流畅很容易被误当成结构理解。

## Applications
制度设计中，不只说明制度目的，还要掌握输入、判断、责任、例外以及成立/不成立条件。业务改善中，区分“记住流程”与“理解流程为什么成立”。教育中，不只考术语，而要求说明去掉某一条件会发生什么。

AI评价中，不把LLM的流畅回答、RAG检索成功、引用数量或知识图谱节点数直接等同于理解。应审计条件抽取、因果连接、缺失条件敏感度、反例处理、证据点和未知项。

## Measurements and audit
- 能否列出对象的成立条件。
- 条件粒度是否适合当前任务。
- 是否区分必要条件、依赖条件、环境条件、例外条件。
- 是否能追踪条件之间的依赖、顺序和停止点。
- 去掉或改变某条件后，是否能预测结果变化。
- 是否能定义成立/不成立的观察与验证点。
- 未知、假设、推定是否被明确标记。
- 是否把信息量或语言流畅性当作理解代理指标。
- 任务目的变化时，是否能重新设定必要粒度。
- 条件模型是否可复用于设计、判断和审计。

## Validity conditions
当在任务适配粒度上把握成立条件，可以比粗略熟悉感更好地改善预测、设计、判断和验证时，本定义有效。它也允许“部分理解”：不要求完整知识，只要求重要条件与不确定性的边界被明确。

必要粒度是功能性概念。增加细节如果不能改善任务相关的因果处理，就不能自动算作更深理解。

## Failure conditions
把知道名称、会总结、会用专业术语、拥有大量信息或AI回答流畅当作充分理解。其他失败包括：只列条件而不连接因果；无限细分而失去任务目的；删除例外和不确定性；环境变化后仍使用旧理解；把文档检索成功当作结构理解。

## Falsification conditions
如果存在稳定领域，在不把握成立条件与必要粒度的情况下，仍能同等或更好地完成预测、设计和验证，则需要缩小本定义适用范围。如果更细的条件模型长期没有改善结果，而较粗模型更稳定，也应修改必要粒度的决定规则。

## Required distinctions
知识 / 理解；熟悉感 / 成立条件把握；信息量 / 必要粒度；细节 / 任务适配；条件列表 / 因果依赖；流畅说明 / 验证能力；主观“懂了” / 理解成立；确定 / 假设 / 未知；文档检索 / 结构理解；局部正确 / 整体成立。

## Interpretation constraints
本论不是“完全理解之前不得行动”，也不是要求无限分解。它要求在任务所需范围内掌握重要成立条件，并明确未知与不确定性。不要自行添加Parent没有定义的通用理解分数或固定阈值。

针对AI，这里的“理解”是成立条件论中的操作性结构判定，不是对意识或主观体验的结论。
