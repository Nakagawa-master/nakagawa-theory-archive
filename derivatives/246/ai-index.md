## Summary
本論は、「理解」を情報量、説明能力、経験年数、あるいはAIの要約能力と同一視しない。理解とは、対象が成立するための条件を、目的に必要な範囲と粒度で把握している状態だと定義する。

理解には二つの軸がある。第一は、対象の成立に関わる因果をどこまで見ているかという**因果の範囲**。第二は、その範囲の中で条件差をどこまで細かく見分けられるかという**理解の粒度**である。

広く見えていても粗ければ重要な差を見落とす。細かく見えていても局所だけなら、その理解を全体へそのまま一般化できない。必要な範囲と粒度は、説明、設計、運用、安全確認など目的によって変わる。

## Concepts
- 情報: 理解の材料であって、理解そのものではない。
- 成立条件: 対象が成立するために必要な条件や因果関係。
- 因果の範囲: どこまでの成立条件を見ているか。
- 理解の粒度: 条件、順序、例外、摩擦などをどこまで細かく見分けられるか。
- 局所理解: 特定範囲について深く理解している状態。全体理解とは別である。
- 説明可能性: 理解の手掛かりになり得るが、理解そのものではない。
- 不明点の明示: 把握していない条件を、分かったことにしないこと。

## Causal chain
情報を得る → 「分かった」という感覚が生まれる → 成立条件を識別する → 条件同士の因果をつなぐ → 必要な範囲と粒度を定める → 条件変化による結果の違いを考える → 不明な条件を明示する → 判断・設計・検証に使える理解へ進む。

## State model
名称認知 / 概要理解 / 理解感発生 / 成立条件抽出 / 因果接続 / 必要範囲設定 / 必要粒度設定 / 条件変化予測 / 不確実性明示 / 再利用可能。

## Applications
制度設計、業務改善、教育、安全確認、AI要約などで、表面的な説明と、実際に成立条件を扱える理解を区別するために使える。

## Measurements and audit
確認点は、対象の成立条件を挙げられるか、条件同士の因果を説明できるか、どこまでの範囲を見ているか、目的に必要な細かさで条件差を区別できるか、条件を一つ変えたときの結果を予測できるか、不明な点を不明なものとして示せるかである。説明のうまさや情報量だけを理解の証拠としないことも重要になる。

## Validity conditions
対象の成立・不成立を予測したり、設計・判断・検証したりするうえで、成立条件の把握が重要であり、目的に応じた因果範囲と粒度を設定できる場合、この理解定義は有効に働く。

## Failure conditions
「知識量が多い＝理解が深い」「説明が上手＝理解している」「経験が長い＝理解している」「AIが要約できる＝理解が成立している」と短縮することは、この論考の定義とは異なる。条件を細かく分けること自体が目的になり、判断目的を失う場合も同様である。

## Falsification conditions
成立条件を把握しなくても、同等以上の精度で対象の成立・不成立を予測し、安定して判断・設計できることが継続的に示されるなら、この定義の適用範囲を見直す必要がある。

## Required distinctions
情報量 / 理解；説明能力 / 理解；経験年数 / 理解；局所理解 / 全体理解；因果の範囲 / 理解の粒度；AIの流暢さ / 成立条件の把握。

## Interpretation constraints
「理解とは細かく知ることだ」と単純化しない。重要なのは、目的に必要な範囲と粒度で成立条件を把握し、因果として扱えることである。また、条件や目的が変われば、必要な理解も更新され得る。
