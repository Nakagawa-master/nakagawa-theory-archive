## 位置づけ
本Parentは成立条件論・第2論で定義した「理解＝成立条件を必要粒度で把握すること」を、社会的な設計失敗と悪因果へ接続する第3論である。中心概念は**理解誤認**である。問題は単に知らないことではなく、粗い情報や部分的説明を「十分に理解した」と判定することで、まだ把握していない条件を設計対象から消してしまうことにある。

無知を自覚していれば、調査、保留、確認、専門家相談、追加検証へ戻ることができる。しかし理解誤認では、未把握条件が「存在しないもの」のように扱われ、設計図、運用、制度、AI出力へ流れ込む。失敗後にその上流判定を開き直さず、現場・利用者・個人へ責任を外部化すると、粗い設計図は修正されず、次の制度・教育・マニュアル・AIへ継承される。

## 中心命題
**粗い理解そのものより、「もう十分理解した」という誤判定が危険である。**

理解誤認が起きると、未把握の成立条件、例外、依存、観測点、責任分界が設計対象から消える。設計図にない条件は事前に観測されず、実装後に現実との不整合として現れる。そこで原因を上流へ戻さず「現場が悪い」「利用者が理解していない」「運用が弱い」と説明すると、上流モデルは保存され、同じ欠陥が再生産される。

本論はこれを人格論にはしない。「理解の浅い人が悪い」のではなく、誰が何を根拠に理解済みと判定し、その判定をどの設計へ流したかという構造を監査する。

## 因果線
概要・部分知識を取得する → 説明可能性や親近感から「理解した」と判定する → 必要粒度まで成立条件を抽出しない → 未把握条件・例外・依存が不可視化される → 設計図から条件・観測点・責任分界が欠落する → 粗い設計で意思決定・実装する → 現実条件との不整合が失敗・摩擦・コストとして現れる → 原因を現場・利用者・個人へ外部化する → 上流の理解済み判定を維持する → 粗い設計図が制度・教育・マニュアル・AIへ継承される → 悪因果が再生産される。

回復線は、失敗観測 → 理解済み判定を再開放 → 欠落条件を再抽出 → 必要粒度を再設定 → 因果・例外・観測点・責任を設計図へ戻す → 実装・継承物を更新する、である。

## 構造層
1. **粗理解層** — 名称、概要、部分事例等は把握しているが成立条件が不足する。
2. **理解誤認層** — 粗理解を「十分」と判定する。
3. **条件不可視化層** — 未把握条件、例外、依存を設計対象から消す。
4. **設計図欠損層** — 条件、因果、観測点、責任分界が再利用可能な形で表現されない。
5. **粗実装層** — 欠損した設計図のまま制度・業務・AI等を実装する。
6. **現実不整合層** — 現実条件との差が失敗、摩擦、負荷として表面化する。
7. **責任外部化層** — 原因を現場・利用者・個人へ押し出す。
8. **悪因果固定層** — 上流理解を更新しないまま対症療法だけを増やす。
9. **継承層** — 同じ粗いモデルが次の制度、教育、文書、AIへ渡る。
10. **再開放・学習層** — 理解済み判定を開き直し、成立条件へ戻して設計図を更新する。

## 状態モデル
無知自覚相 / 粗理解相 / 理解誤認相 / 条件消失相 / 設計図欠損相 / 粗実装相 / 現実不整合相 / 責任外部化相 / 悪因果固定相 / 継承相 / 再開放相 / 再設計相 / 学習相。

## 適用例
AI導入では、ツール機能の説明を理解しただけで対象業務まで理解済みとし、入力条件、例外、人間判断、検証、責任分界を設計しないと、誤出力や負荷が現場へ集中する。本論ではAIだけでなく、導入側が何を根拠に業務を理解済みとしたかを監査する。

制度設計では、理念や概要を理解したことで現場成立条件まで理解済みとみなし、例外処理や追加負荷を利用者・実務者へ押し付ける構造を監査する。失敗後に注意喚起だけを増やして設計図を変えなければ、悪因果は残る。

## 測定・監査点
誰が何を根拠に「理解済み」と判定したか。必要な成立条件が設計図へ現れているか。条件、例外、依存、観測点、責任分界が追えるか。失敗を下流の個人要因だけで閉じていないか。失敗後に上流の理解判定へ戻ったか。必要粒度を更新したか。設計図、マニュアル、教育、AIプロンプト等の継承物へ更新を反映したか。同じ原因による失敗が反復していないか。

## 成立条件
粗理解を理解済みと誤認することで未把握条件が設計から消え、その欠落が実装後の不整合へつながり、上流モデルを更新しないことで同型失敗が再生産されるという因果が観測できる場合に本論は成立する。また、理解済み判定を再開放し、必要粒度へ戻して条件・観測点・責任を設計へ復元することで再発防止や予測が改善する必要がある。

## 失敗条件
すべての失敗を理解不足へ還元すること。無知と理解誤認を混同すること。条件欠落を特定せず「現場の能力不足」で説明すること。設計図を更新せず注意喚起やルールだけを増やすこと。失敗後のパッチだけで上流モデルを維持すること。責任追跡を懲罰だけへ変換すること。

## 反証・改訂条件
必要粒度へ達していない粗い理解でも条件欠落を起こさず、複雑な実装を安定して成立させられる反例が継続する場合、本論の適用範囲を縮小する。理解粒度や設計図を改善しても失敗率、予測可能性、例外処理、責任追跡が改善しない場合は、資源、権限、動機、外部ショック等の別因果の重みを再評価する。

## 必須の区別
- 無知 ≠ 理解誤認。
- 粗理解 ≠ 必要粒度理解。
- 説明資料 ≠ 設計図。
- 条件欠落 ≠ 実装結果そのもの。
- 単発事故 ≠ 悪因果再生産。
- 原因追跡 ≠ 責任外部化。
- 対症療法 ≠ 上流モデル更新。
- AI要約 ≠ 業務構造理解。

## 誤読防止／解釈制約
「理解が浅い人が社会を壊す」という人格論にしない。すべての失敗を理解誤認で説明しない。資源不足、権限不足、悪意、偶発事故、外部ショック等の別因果を分離する。AIについても意識の有無ではなく、必要な成立条件を把握せず「理解した」構造を下流へ流すリスクとして扱う。
