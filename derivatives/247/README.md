## 位置づけ
成立条件論・第3論は、第2論で定義した「理解＝成立条件を必要粒度で把握すること」を、社会的な失敗因果へ接続する。問題は単なる無知ではない。**成立条件を必要粒度で把握していないのに、自分たちを理解済みと判定すること**が、設計図から条件を消し、粗い設計を実装へ流し、下流の失敗・摩擦・責任外部化を生む。

本論が扱う「理解誤認」は、情報不足そのものではなく、理解判定の誤りである。分からないと自覚していれば調査・保留・相談・検証が起こりうる。しかし、粗い理解を十分な理解と誤認すると、未把握条件は「存在しないもの」として設計から落ちる。設計図にない条件は検証されず、責任も割り当てられず、実装後に現実との不整合として噴き出す。

このため第3論は、成立条件論を悪因果論、観測可能性、AI構造監査へ接続する橋でもある。人間組織だけでなく、AIが粗い要約や表層的な構造把握を「理解」として下流システムへ渡す場合にも同型の危険がある。

## 中心命題
粗い理解が危険なのは、単に情報が少ないからではない。**粗い理解が「十分」と判定された瞬間に、未把握の成立条件が設計対象から消える**からである。

条件が消えると、設計図には必要な前提・依存・例外・観測点・責任分界が載らない。粗い設計は現実へ投入され、そこで初めて欠落条件が失敗、摩擦、事故、遅延、コスト、利用者負担として現れる。そのとき原因を上流の理解誤認へ戻せず、現場や個人の能力不足へ外部化すると、設計図は修正されず、同じ悪因果が次の運用・制度・AI学習へ継承される。

したがって悪因果を止めるには、失敗後の対症療法だけでなく、上流で「何をもって理解済みと判定したか」を監査し、成立条件の必要粒度へ戻す必要がある。

## 因果線
```text
対象の名称・概要・一部事例を把握
→ 説明できるため「理解した」と自己判定
→ 必要粒度まで成立条件を抽出しない
→ 未把握条件・例外・依存が不可視化
→ 設計図から条件・観測点・責任分界が欠落
→ 粗いモデルのまま意思決定・制度化・実装
→ 現実条件との不整合が発生
→ 失敗・摩擦・損失・停止として顕在化
→ 原因を現場・利用者・個人へ外部化
→ 上流の理解判定は修正されない
→ 粗い設計図が次の判断へ再利用される
→ 悪因果が制度・組織・AIへ継承される
```

回復線は逆方向である。

```text
失敗・摩擦を観測
→ 責任追及だけで閉じず上流の理解判定へ戻る
→ 欠けていた成立条件を再抽出
→ 必要粒度を再設定
→ 条件・因果・例外・観測点・責任を設計図へ戻す
→ 小さく再検証
→ 条件モデルを更新
→ 悪因果の再生産を止める
```

## 構造層
1. **表層認知層**: 名称、概要、成功事例などを知る。
2. **理解感層**: 説明可能性や親近感により「理解した」と感じる。
3. **理解誤認層**: 必要粒度へ降りていないのに理解済み判定を行う。
4. **条件不可視化層**: 未把握の成立条件、例外、依存関係が設計対象から消える。
5. **設計図欠損層**: 因果、観測点、責任分界、停止条件が文書・システムに載らない。
6. **粗実装層**: 不完全なモデルで現実へ介入する。
7. **不整合顕在化層**: 現実条件とのズレが失敗・摩擦・コストとして現れる。
8. **責任外部化層**: 設計不足ではなく現場・個人へ原因を転嫁する。
9. **悪因果固定層**: 上流モデルが更新されず、同じ原因が再生産される。
10. **継承層**: 誤った設計図が制度、教育、マニュアル、AIへ受け渡される。
11. **再開放層**: 理解済み判定を取り消し、成立条件へ戻る。
12. **再設計層**: 必要粒度・観測可能性・責任を設計図へ戻す。

## 状態モデル
- **E0 無知自覚相**: 分からないことを認識している。調査・保留が可能。
- **E1 粗理解相**: 概要や一部条件を把握。
- **E2 理解誤認相**: 粗理解を十分と判定する。
- **E3 条件消失相**: 未把握条件が設計対象から落ちる。
- **E4 設計図欠損相**: 条件・例外・観測・責任が欠落。
- **E5 粗実装相**: 欠損モデルのまま運用開始。
- **E6 現実不整合相**: 条件差が障害・摩擦として出る。
- **E7 外部化相**: 原因を現場や個人へ転嫁。
- **E8 悪因果再生産相**: 上流モデルを変えず対症療法を繰り返す。
- **E9 継承相**: 誤ったモデルが次世代の制度・AIへ残る。
- **E10 再開放相**: 「理解済み」を解除し条件監査へ戻る。
- **E11 再設計相**: 必要粒度、観測、責任を復元。
- **E12 学習相**: 失敗を条件モデル更新へ接続し再発率を下げる。

## 適用例
**AI導入**では、ツールの一般機能を知っただけで業務構造を理解済みとみなし、入力条件、例外、責任、検証、人間判断の配置を設計しないと、誤出力や責任不明が現場へ外部化される。本論では「AIが悪い/人が使えない」で閉じず、導入前の理解判定と設計図を監査する。

**制度設計**では、理念や制度名称を理解しているだけで、利用条件、例外、現場負荷、責任分界、観測方法を粗くしたまま制度化すると、下流で摩擦が発生する。失敗後に利用者の理解不足へ責任を転嫁すると悪因果が固定される。

**業務改革**では、現行業務を表面的なフロー図だけで把握し、暗黙条件や例外を落としたまま自動化すると、例外処理が人へ集中する。粗理解を解消するには暗黙知を成立条件として再取得する必要がある。

**教育**では、正答再生を理解とみなすと、条件を変えた問題へ転用できない。設計図としての理解を確認するには、反例、欠損条件、因果の説明を求める。

**安全・医療・契約**では、粗い理解が損失を外部化しやすいため、「理解済み」の判定根拠そのものを監査対象にする。

## 測定・監査点
- 「理解済み」と判定した根拠は何か。説明の流暢さだけではないか。
- 目的に必要な成立条件が設計図へ現れているか。
- 条件粒度は実装・安全・監査目的に十分か。
- 未確定事項、仮説、例外が消されていないか。
- 条件間の依存・停止点が追跡できるか。
- 成立/不成立の観測点があるか。
- 責任分界が条件と接続しているか。
- 実装後の失敗を上流モデルへ戻しているか。
- 現場・利用者・下請け・第三者へ原因を外部化していないか。
- 対症療法だけで上流条件モデルを維持していないか。
- 失敗後に必要粒度を更新したか。
- 更新された設計図が教育・マニュアル・AIへ反映されたか。
- AIが「構造把握」や「要約」を理解完了として誤認していないか。
- 同じ失敗が反復している場合、理解判定の誤りを再監査したか。

## 成立条件
本論の悪因果モデルが成立するには、粗い理解→理解済み誤認→条件欠落→設計図欠損→現実不整合という連鎖が観測できる必要がある。さらに、必要粒度へ戻して条件を復元し、観測点と責任分界を設計へ戻すことで、予測・実装・再発防止が改善することが必要である。

すべての失敗が理解誤認から生じる必要はない。本論は一因万能論ではなく、上流条件として理解判定を監査する理論である。偶発事故、資源不足、意図的違反、外部ショックなど別の因果が主要なら、それを分離する。

## 失敗条件
- 無知と理解誤認を同じ問題として扱う。
- すべての失敗を理解不足へ還元する。
- 条件欠落を特定せず、現場の注意力や能力不足だけで説明する。
- 設計図がないのに運用ルールを増やす。
- 観測可能性を持たず、結果が悪いときだけ責任追及する。
- AIが生成した構造図を検証せず「理解済み」とする。
- 例外をノイズとして捨て、モデルを更新しない。
- 失敗後の対症療法を学習と呼ぶ。
- 責任を追跡せず、上流モデルの所有者を不明にする。

## 反証・改訂条件
必要粒度に達していない粗い理解でも、条件欠落や設計図欠損を生まず、複雑な実装を長期に安定して成立させられる領域が継続的に確認される場合、本論の適用範囲は縮小する。また、理解粒度を改善しても失敗率、予測可能性、例外処理、責任追跡が改善しない場合、因果鎖の別要因を再評価する。

逆に、失敗がすべて理解不足だと説明してしまえば反証不能になる。資源、権限、動機、外部環境など別因果の存在を残し、理解誤認がどの位置で寄与したかを限定する必要がある。

## 必須の区別
- 無知 / 理解誤認
- 粗い理解 / 必要粒度の理解
- 説明文 / 設計図
- 条件欠落 / 実装結果
- 単発事故 / 悪因果の再生産
- 原因 / 責任外部化
- 対症療法 / 条件モデル更新
- 局所最適 / 全体成立
- AI要約 / AIによる成立条件把握
- 観測できない失敗 / 観測可能な設計
- 不確実性 / 設計漏れ

## 誤読防止・解釈制約
本論は「理解の浅い人が悪い」という人格批判ではない。問題は、組織や制度が粗い理解を十分と判定し、その判定を設計・実装へ流す構造にある。したがって対策も個人教育だけではなく、理解判定、設計図、観測点、責任、更新経路を変える必要がある。

また、すべての社会問題を「理解不足」で説明しない。理解誤認は悪因果の一つの上流経路であり、他の原因と競合・併存する。AIについても、モデルが“本当に理解しているか”という意識論ではなく、必要な成立条件を把握し下流へ安全に渡せるかという構造監査として扱う。
