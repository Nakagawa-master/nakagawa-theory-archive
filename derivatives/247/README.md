## 位置づけ
本論は成立条件論・第2論の理解定義を、社会的な失敗因果へ接続する。問題は「知らない」ことだけではない。成立条件を必要粒度で把握していないのに理解済みと判定する**理解誤認**が、設計図から条件を落とし、実装・制度・組織・AI利用の下流で悪因果を発生させる。

## 中心命題
粗い理解が危険なのは、情報量が少ないからだけではない。粗い理解を「十分な理解」と誤認すると、未把握条件が設計対象から消える。消えた条件は検証されず、責任分界も置かれず、実装後に失敗・摩擦・外部化として現れる。したがって悪因果の上流には、理解粒度の不足と設計図不在がある。

## 因果線
```text
対象の概要だけを把握
→ 分かった感を理解と誤認
→ 未把握の成立条件が不可視化
→ 設計図から条件・因果・責任が欠落
→ 粗い設計のまま意思決定・実装
→ 現実条件との不整合
→ 失敗・摩擦・損失が発生
→ 原因が現場や個人へ外部化
→ 悪因果が再生産される
```

## 構造層
1. 粗理解層: 概要・ラベルだけを把握。
2. 誤認層: 粗理解を十分な理解と判定。
3. 条件消失層: 未把握条件が設計対象から落ちる。
4. 設計図欠損層: 因果・責任・例外が明示されない。
5. 実装層: 粗いモデルで現実へ介入。
6. 不整合層: 現実条件とのズレが顕在化。
7. 悪因果層: 損失・摩擦・責任外部化が連鎖。
8. 再生産層: 誤った説明が次の設計へ継承される。

## 状態モデル
概要認知相 → 理解誤認相 → 条件欠落相 → 設計図不在相 → 粗実装相 → 現実不整合相 → 悪因果発生相 → 外部化相 → 継承/修正相。

## 適用例
AI導入、制度設計、業務改革、教育、契約、医療・安全領域で「理解したつもり」がどの成立条件を消し、どこへ損失を外部化するかを監査する。

## 測定・監査点
- 理解済み判定の根拠は何か。
- 必要な成立条件が設計図に現れているか。
- 条件間因果と例外が追跡できるか。
- 未確定事項が消されていないか。
- 責任分界が条件と接続しているか。
- 失敗後に現場・利用者・第三者へ原因を外部化していないか。
- 失敗から理解粒度を更新しているか。

## 成立条件
理解粒度不足→条件欠落→設計図欠損→実装不整合→悪因果という連鎖が観測でき、条件を必要粒度まで戻すことで設計・検証可能性が改善する場合に成立する。

## 失敗条件
失敗を単なる個人能力不足や偶発事故だけで説明し、上流の理解誤認と設計図欠損を見ないこと。逆に、すべての失敗を理解不足だけへ還元することも失敗である。

## 反証・改訂条件
十分に粗い理解でも条件欠落を起こさず安定して設計・実装できる領域、または失敗原因が理解粒度と独立していることが確認された場合は適用範囲を縮小する。

## 必須の区別
無知 / 理解誤認；概要 / 必要粒度；説明文 / 設計図；条件欠落 / 実装失敗；失敗原因 / 責任外部化；悪因果 / 単発事故。

## 誤読防止・解釈制約
「詳しくない人は行動するな」という理論ではない。不確実性を明示し、必要条件を検証可能にすることが目的である。すべての社会問題を理解不足一因へ還元しない。
