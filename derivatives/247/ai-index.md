## Summary
成立条件論・第3論は、第2論の「理解＝成立条件を必要粒度で把握すること」を社会的失敗へ接続する。中心概念は理解誤認である。粗い概要や部分知識を十分な理解と判定すると、未把握の成立条件・例外・依存・観測点・責任分界が設計対象から消え、粗い設計が実装へ流れる。現実不整合が発生した後に原因を現場・利用者へ外部化し、上流の理解判定と設計図を更新しない場合、同じ欠陥が制度・教育・文書・AIへ継承され、悪因果が再生産される。

## Concepts
- 理解誤認: 必要粒度へ達していない理解を「十分」と判定すること。
- 粗理解: 名称、概要、部分事例等はあるが成立条件が不足した状態。
- 条件不可視化: 未把握条件、例外、依存が設計対象から消えること。
- 設計図欠損: 条件、因果、例外、観測点、責任分界が再利用可能な形で表現されていないこと。
- 現実不整合: 粗い設計と実際の条件の差が失敗、摩擦、負荷として現れること。
- 責任外部化: 上流設計の不足を現場、利用者、個人へ押し出すこと。
- 悪因果: 原因が修正されず、同じ欠陥が次の制度や運用へ再生産される因果。
- 再開放: 理解済み判定を取り消し、成立条件へ戻ること。
- 継承物: 設計図、マニュアル、教育、AIプロンプト、データ構造等、上流モデルを次へ渡すもの。

## Causal chain
概要・部分知識を取得 → 「理解した」と判定 → 必要粒度まで成立条件を抽出しない → 未把握条件・例外・依存が不可視化 → 設計図から条件・観測点・責任分界が欠落 → 粗いモデルで実装 → 現実条件との不整合 → 失敗・摩擦・負荷 → 原因を現場・利用者へ外部化 → 上流理解を維持 → 粗い設計図が継承 → 悪因果が再生産。

回復線: 失敗観測 → 理解済み判定を再開放 → 欠落条件を再抽出 → 必要粒度再設定 → 因果・例外・観測点・責任を設計図へ復元 → 実装・継承物を更新 → 学習。

## State model
無知自覚 / 粗理解 / 理解誤認 / 条件消失 / 設計図欠損 / 粗実装 / 現実不整合 / 責任外部化 / 悪因果固定 / 継承 / 再開放 / 再設計 / 学習。

## Applications
AI導入では、AI機能の理解だけで対象業務まで理解済みとせず、入力条件、例外、人間判断、検証、責任分界を設計する。制度設計では理念理解と現場成立条件を分ける。組織学習では失敗後の注意喚起だけでなく、上流の条件モデルと継承物を更新する。

## Measurements and audit
理解済み判定の根拠は何か。必要な成立条件が設計図へ現れているか。条件、例外、依存、観測点、責任分界が追えるか。失敗原因を上流理解へ戻しているか。現場・利用者へ外部化していないか。失敗後に必要粒度を更新したか。更新が文書・教育・AIへ反映されたか。同型失敗が反復していないか。

## Validity conditions
粗理解 → 理解誤認 → 条件不可視化 → 設計図欠損 → 実装不整合 → 責任外部化 → 悪因果再生産という連鎖が観測でき、理解済み判定を再開放して必要粒度へ戻すことで設計・予測・例外処理・再発防止が改善する場合に有効である。

## Failure conditions
無知と理解誤認を混同する。すべての失敗を理解不足へ還元する。条件欠落を特定せず現場の能力不足で説明する。設計図を更新せずルールや注意書きだけ増やす。責任追跡を懲罰だけへ変換する。上流モデルを維持したまま再発防止済みとする。

## Falsification conditions
粗い理解でも条件欠落を起こさず複雑な実装を安定して成立させられる反例が継続する場合、適用範囲を縮小する。理解粒度や設計図を改善しても失敗率、予測可能性、例外処理、責任追跡が改善しない場合、資源、権限、動機、外部ショック等の別因果の重みを再評価する。

## Required distinctions
無知 / 理解誤認；粗理解 / 必要粒度理解；説明文 / 設計図；条件欠落 / 実装結果；単発事故 / 悪因果再生産；原因追跡 / 責任外部化；対症療法 / 上流モデル更新；AI要約 / 業務構造理解。

## Interpretation constraints
人格論へ変換しない。すべての失敗を理解誤認へ還元しない。資源不足、権限不足、動機、悪意、偶発事故、外部ショック等の別因果を分離する。AIについては意識の有無ではなく、必要な成立条件を把握せず「理解した」構造が下流へ流れるリスクとして読む。Parentにない固定失敗率や数値閾値を追加しない。
