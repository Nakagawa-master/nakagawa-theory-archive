## Summary
成立条件論・第3論は、第2論の「理解＝成立条件を必要粒度で把握すること」を社会的失敗へ接続する。中心概念は**理解誤認**である。粗い概要、部分的知識、流暢な説明を十分な理解と判定すると、まだ把握していない成立条件が設計対象から消える。設計図に載らない条件は観測・検証・責任配置もされにくく、実装後に失敗・摩擦・コストとして現れる。

さらに、失敗原因を現場・利用者・個人へ外部化し、上流の理解判定と設計図を更新しない場合、同じ粗いモデルが制度・マニュアル・教育・AIへ継承される。本論はこの再生産を悪因果として捉える。人格批判ではなく、理解判定→設計→実装→失敗→更新の構造監査である。

## Concepts
- 理解誤認: 必要粒度へ達していない理解を「十分」と判定すること。
- 粗理解: 名称、概要、一部事例などを把握しているが成立条件が不足した状態。
- 成立条件: 対象が成立するために必要な条件。第2論の必要粒度概念と接続する。
- 条件不可視化: 未把握条件が設計対象から消えること。
- 設計図不在/欠損: 条件、因果、例外、観測点、責任が再利用可能な形で表現されていないこと。
- 現実不整合: 粗い設計と実際の条件の差が失敗・摩擦として現れること。
- 責任外部化: 上流設計の不足を現場・個人・利用者へ押し出すこと。
- 悪因果: 原因が修正されず、同じ欠陥が次の判断や制度へ再生産される因果。
- 観測可能性: 失敗を印象でなく条件差として検出できること。
- 再開放: 理解済み判定を取り消し、成立条件へ戻ること。
- 継承: 設計図、マニュアル、教育、AI等を通じて因果が次へ渡ること。

## Causal chain
概要・部分知識を取得 → 説明可能性から「理解した」と判定 → 必要粒度まで成立条件を抽出しない → 未把握条件・例外・依存が不可視化 → 設計図から条件・観測点・責任が欠落 → 粗いモデルで意思決定/実装 → 現実条件との不整合 → 失敗・摩擦・損失 → 原因を現場/利用者へ外部化 → 上流の理解判定は維持 → 粗い設計図が次の制度・教育・AIへ継承 → 悪因果が再生産される。

回復線は、失敗観測 → 理解済み判定の再開放 → 欠落条件の再抽出 → 必要粒度再設定 → 因果・例外・観測・責任を設計図へ復元 → 小規模検証 → 更新を継承物へ反映、である。

## State model
E0 無知自覚 / E1 粗理解 / E2 理解誤認 / E3 条件消失 / E4 設計図欠損 / E5 粗実装 / E6 現実不整合 / E7 責任外部化 / E8 悪因果固定 / E9 継承 / E10 再開放 / E11 再設計 / E12 学習。

E0は危険状態とは限らない。無知を自覚していれば調査・保留が可能である。危険なのはE2で未把握を消した後にE3〜E5へ進むこと。

## Applications
- AI導入: ツールの機能説明だけで業務構造を理解済みにせず、入力、例外、人間判断、検証、責任の成立条件を設計する。
- 業務自動化: フロー図にない暗黙条件を抽出し、例外処理を現場へ押し付けない。
- 制度設計: 理念理解と現場成立条件を分け、利用条件・例外・観測・責任を設計図へ載せる。
- 教育: 正答再生だけで理解済みにせず、条件変更時の因果を説明させる。
- 安全・医療・契約: 「理解済み」の根拠を監査し、条件欠落が下流へ外部化しないようにする。
- 組織学習: 失敗後の注意喚起ではなく、上流の条件モデルと継承物を更新する。

## Measurements and audit
- 「理解済み」判定の根拠は何か。
- 必要な成立条件が設計図へ現れているか。
- 条件粒度は実装目的に十分か。
- 条件間の因果、例外、停止点が追えるか。
- 未確定事項が削除されていないか。
- 成立/不成立を観測する地点があるか。
- 責任分界が条件と接続しているか。
- 失敗原因を上流理解へ戻しているか。
- 現場・利用者・第三者へ原因を外部化していないか。
- 対症療法だけで設計図を維持していないか。
- 失敗後に必要粒度を更新したか。
- 更新がマニュアル・教育・AIへ反映されたか。
- 同型失敗が反復していないか。
- AIの要約・構造図を未検証で理解完了としていないか。

## Validity conditions
粗理解→理解誤認→条件欠落→設計図欠損→実装不整合という連鎖が観測でき、必要粒度へ戻して条件・観測点・責任を設計へ復元することで、予測、実装、例外処理、再発防止が改善する場合に本論は成立する。

ただし、理解誤認は全失敗の唯一原因ではない。資源、権限、動機、外部ショックなど別因果を分離したうえで、本因果がどの位置に寄与したかを限定できる必要がある。

## Failure conditions
無知と理解誤認を混同する。すべての失敗を理解不足へ還元する。条件欠落を特定せず現場の能力不足で説明する。設計図がないのにルールだけ増やす。失敗後に注意喚起だけ行う。AIの生成した構造図を検証せず採用する。例外をノイズとして捨てる。責任追跡を懲罰だけへ変換する。上流モデルを更新しないまま再発防止済みとする。

## Falsification conditions
必要粒度へ達していない粗い理解でも条件欠落を起こさず、複雑な実装を安定して成立させられる反例が継続する場合、適用範囲を縮小する。理解粒度や設計図を改善しても、失敗率、予測可能性、例外処理、責任追跡が改善しない場合、別因果の重みを再評価する。

すべての失敗を理解誤認で説明できるよう定義を拡張してはならない。反証可能性を残すため、他の原因を明示的に競合させる。

## Required distinctions
無知 / 理解誤認；粗理解 / 必要粒度理解；説明文 / 設計図；条件欠落 / 実装結果；単発事故 / 悪因果再生産；原因 / 責任外部化；対症療法 / 条件モデル更新；局所的正しさ / 全体成立；AI要約 / AI構造理解；不確実性 / 設計漏れ；責任追跡 / 懲罰。

## Interpretation constraints
人格論へ変換しない。「理解が浅い人が悪い」のではなく、組織やシステムが何を根拠に理解済みと判定し、その判定を下流設計へ流すかが対象である。個人教育だけでなく、判定基準、設計図、観測点、責任、更新経路を監査する。

AIについては意識の有無を扱わない。成立条件を必要粒度で把握せず「理解した」出力を下流へ渡す構造リスクとして読む。Parentにない固定失敗率や数値閾値を追加しない。
