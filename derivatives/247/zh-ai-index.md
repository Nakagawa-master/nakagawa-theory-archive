## Summary
成立条件论・第3论把第2论的理解定义连接到社会失败。中心概念是**理解误认**：在尚未按任务需要的粒度把握成立条件之前，就把粗略模型判定为“已经充分理解”。一旦做出这种过早完成判定，未被把握的条件会从设计对象中消失。没有进入设计图的条件，也往往不会被设置观察点、验证责任、例外处理或责任归属。

下游可能出现实装不整合、摩擦、失败和成本。如果失败之后只把责任推给现场或使用者，而不回到上游的理解判定和缺失条件，粗略模型就不会更新，并会通过制度、手册、教育或AI继续被继承。本论把这种重复结构看作恶因果。它审计的是“判定—设计—实装—失败—更新”结构，不是个人智力或人格。

## Concepts
理解误认；粗理解；必要粒度；成立条件；条件不可见化；设计图缺失；因果依赖；可观察性；责任边界；实装不整合；责任外部化；恶因果；因果继承；重新开放；模型更新。

必须区分无知与理解误认。明确知道自己不知道，仍可以触发调查和保留；错误地宣布“已经理解”会压制继续验证，并把条件从设计中删除。

## Causal chain
获得概要或部分案例 → 因熟悉和流畅说明而产生“已经理解”的判定 → 未把成立条件分解到任务必要粒度 → 未知依赖、例外、约束被不可见化 → 条件、观察点、责任从设计图中缺失 → 使用粗模型实装 → 现实条件与模型发生偏差 → 出现失败、摩擦、损失 → 原因被外部化给现场或用户 → 上游理解判定不修改 → 同一设计模型被制度、手册、教育或AI继续继承 → 恶因果被再生产。

恢复链：观察失败 → 重新打开“已理解”判定 → 重新抽取缺失成立条件 → 重设必要粒度 → 将依赖、例外、观察点、责任恢复到设计图 → 小范围验证 → 把模型更新传播到继承物。

## State model
E0 自觉无知 → E1 粗理解 → E2 理解误认 → E3 条件消失 → E4 设计图缺失 → E5 粗实装 → E6 现实不整合 → E7 责任外部化 → E8 恶因果固定 → E9 继承 → E10 重新开放 → E11 再设计 → E12 学习。

E0并不一定危险。真正关键的是E2：不完整状态被错误关闭之后，系统进入E3～E5。

## Applications
AI导入中，不能把“了解工具功能”当成“理解目标业务”。应审计输入、例外、人类判断、验证、责任等成立条件。业务自动化中，要把简化流程图丢失的暗默条件重新取得。制度设计中，应区分理解制度理念和理解现场成立条件。教育中，应测试条件变化后的因果推理，而不只测试正确答案复述。

组织学习中，失败后不仅问“怎样补一个规则”，还要问“哪个条件为什么没有进入上游模型、为什么当时模型被判定为足够完整”。

## Measurements and audit
- “已经理解”的判定依据是什么。
- 任务相关成立条件是否进入设计图。
- 粒度是否足够支持实装、安全和审计。
- 依赖、例外和停止点是否可追踪。
- 未知和假设是否仍可见。
- 是否有成立/失败的观察点。
- 责任是否与条件所有权和判断节点连接。
- 失败是否回到上游理解判定，而非只推给现场。
- 失败后是否更新条件模型，而非只增加注意事项。
- 更新是否传播到手册、培训、提示词、数据结构和AI系统。
- 同型失败是否在上游模型不变的情况下反复出现。

## Validity conditions
当可以观察到“粗理解→过早完成判定→条件缺失→设计图缺失→实装不整合”的链条，而且重新打开理解判定、恢复必要粒度条件和观察责任后，预测、实装、例外处理或再发防止得到改善时，本模型有效。

理解误认不需要是唯一原因。资源、权限、动机、故意违反、外部冲击等竞争原因必须保留并分别检验。

## Failure conditions
把无知和理解误认混为一谈；把所有失败都归因于“理解不足”；把问题人格化为“现场人员不懂”；没有设计图却只增加规则；无验证地采用AI生成的结构图；把例外当噪音删除；只做症状补丁；把责任追踪变成惩罚；没有修改上游模型却宣称已经完成再发防止。

## Falsification conditions
如果粗理解长期也能支持复杂实装，而且不会造成条件缺失或设计图不足，应缩小本论适用范围。如果提高理解粒度、增加设计图完整性之后，预测、观察、例外处理、责任追踪、再发率都没有改善，也应重新评估其他因果。

不得通过把所有失败定义成“隐藏的理解误认”来使理论不可反证。

## Required distinctions
无知 / 理解误认；粗理解 / 必要粒度理解；说明文 / 设计图；条件缺失 / 下游结果；单次事故 / 恶因果再生产；原因 / 责任外部化；症状补丁 / 条件模型更新；局部正确 / 整体成立；AI摘要 / 结构理解；不确定性 / 设计遗漏；责任追踪 / 惩罚。

## Interpretation constraints
本论不是“知识少的人会破坏社会”的人格论。对象是组织或系统如何把粗模型判定为足以设计与实装。因此对策不仅是个人教育，还包括理解判定规则、设计图、可观察性、责任和更新回路。

针对AI，应把问题理解为“必要成立条件是否被结构化并安全地传递给下游”的审计，而不是机器意识论。不要自行增加Parent没有定义的通用失败率或数值阈值。
