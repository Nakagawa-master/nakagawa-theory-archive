## Summary
成立条件论第3论把第2论的“理解＝按必要粒度把握成立条件”连接到社会与实施失败。核心概念是“理解误认”：把粗略概要或部分知识判断为已经足够，于是尚未把握的成立条件、例外、依赖、观察点与责任边界从设计对象中消失。粗糙设计进入实施后，现实条件差异会表现为失败、摩擦或负荷。如果事后只把原因推给现场或使用者，而不重新打开上游的理解判断，同一缺陷模型就可能通过制度、手册、教育、AI等继续继承，形成恶因果再生产。

## Concepts
- 理解误认：把未达到所需粒度的理解判断为“已经足够”。
- 粗理解：只有名称、概要或部分案例，成立条件仍不足。
- 条件不可视化：未把握条件、例外、依赖从设计对象中消失。
- 设计图缺损：条件、因果、例外、观察点、责任边界没有以可复用形式表达。
- 现实不一致：粗糙设计与实际条件之间的差表现为失败、摩擦或负荷。
- 责任外部化：把上游设计不足推给现场、使用者或个人。
- 恶因果：上游原因未被修复，同一缺陷在后续系统中再生产。
- 再开放：撤销“已经理解”的判定，重新回到成立条件。
- 继承物：把上游模型传递下去的文档、规则、教育、提示词、数据结构等。

## Causal chain
获取概要或部分知识 → 判断“已经理解” → 未按必要粒度抽取成立条件 → 未把握条件与例外不可见 → 设计图缺少条件、观察点与责任边界 → 粗糙实施 → 与现实条件不一致 → 失败、摩擦、负荷 → 把原因外部化到现场／使用者 → 维持上游理解判定 → 缺陷模型被继承 → 恶因果再生产。

恢复线：观察失败 → 重新开放理解判定 → 再抽取缺失条件 → 重新设定必要粒度 → 把因果、例外、观察点、责任恢复到设计图 → 更新实施与继承物 → 学习。

## State model
无知自觉 / 粗理解 / 理解误认 / 条件消失 / 设计图缺损 / 粗糙实施 / 现实不一致 / 责任外部化 / 恶因果固定 / 继承 / 再开放 / 再设计 / 学习。

## Applications
AI导入中，不要把理解AI功能等同于理解目标业务；要明确输入条件、例外、人类判断、验证与责任。制度设计中，要把理念理解与现场成立条件分开。组织学习中，失败后不能只增加注意事项，而要更新上游条件模型与文档、教育、提示词等继承物。

## Measurements and audit
检查“已经理解”的判定依据是什么；必要成立条件是否出现在设计图中；例外、依赖、观察点、责任边界是否可追踪；失败原因是否返回上游；是否向现场／使用者外部化；失败后是否更新必要粒度；文档、教育、AI等继承物是否同步更新；同型失败是否持续反复。

## Validity conditions
当“粗理解 → 理解误认 → 条件不可视化 → 设计图缺损 → 实施不一致 → 责任外部化 → 恶因果再生产”的链条可以观察到，并且重新开放理解判定、按必要粒度恢复条件后，设计、预测、例外处理或再发防止得到改善时，本理论有效。

## Failure conditions
把无知与理解误认混同；把所有失败都归结为理解不足；不找缺失条件而只归咎现场能力；不更新设计图却只增加规则和警告；把责任追踪变成单纯惩罚；上游模型不变却宣称再发防止已经完成。

## Falsification conditions
如果粗理解也能持续稳定地支持复杂实施而不发生条件缺失，应缩小适用范围。如果提高理解粒度或改善设计图并不能改善失败率、可预测性、例外处理或责任追踪，应重新评估资源、权限、动机、外部冲击等竞争因果。

## Required distinctions
无知 / 理解误认；粗理解 / 必要粒度理解；说明文档 / 设计图；条件缺失 / 实施结果；单次事故 / 恶因果再生产；原因追踪 / 责任外部化；补丁 / 上游模型更新；AI摘要 / 业务结构理解。

## Interpretation constraints
不要把本理论变成“理解浅的人会破坏社会”的人格论。不要用理解误认解释所有失败。要分离资源不足、权限不足、动机、恶意、偶发事故、外部冲击等其他因果。对于AI，问题不是意识，而是未充分把握成立条件的“已理解”结构被传到下游的风险。不得添加Parent没有的固定失败率或数值阈值。
