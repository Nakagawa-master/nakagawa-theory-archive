## Summary
本论讨论的并不只是“知道得不够”，而是**在尚未充分把握成立条件时，却认为自己已经理解了**。当这种粗略理解被直接用于制度设计或判断时，必要条件可能从设计中消失。

这些缺失条件不会从现实中消失。它们往往会以额外劳动、例外处理、个人经验、临场判断等形式由现场补上。因此，一个制度可能表面上“运行了”，但实际上依赖的是人的过度补偿，而不是完整的设计。

如果只看到结果，就可能产生“原来的设计是正确的”这一错误学习，使同样的粗略理解继续被使用，从而形成反复出现的恶性因果。

## Concepts
- 粗略理解：根据部分信息或个别成功案例，把局部当作整体。
- 理解误认：尚未充分把握成立条件，却认为理解已经足够。
- 设计条件缺失：例外、责任、依赖关系、资源、判断条件等没有进入设计。
- 补偿负担：通过额外劳动、个人经验或临场处理来弥补设计不足。
- 责任外部化：结构上的缺失被解释成个人能力或努力不足。
- 恶性因果：粗略理解造成设计缺失，设计缺失造成现场负担，而表面结果又反过来强化原来的粗略理解。

## Causal chain
部分信息或成功案例 → 粗略理解 → 认为自己已经理解 → 成立条件检查不足 → 必要条件没有进入设计 → 现场出现缺口 → 通过额外劳动或个人判断弥补 → 暂时出现结果 → 设计缺失更难被看见 → 责任转移到个人 → 同样的粗略理解被再次使用。

## State model
部分信息接触 / 粗略理解形成 / 理解误认 / 条件不可见 / 设计条件缺失 / 现实不一致 / 现场补偿 / 责任外部化 / 错误学习 / 恶性因果再生产。

## Applications
可用于制度设计、业务运营、组织改善和AI导入等场景，帮助区分“一次运行成功”与“可重复运行所需的条件已经被真正设计”。

## Measurements and audit
可观察的问题包括：哪些成立条件被忽略；由谁在现场补偿这些缺失；表面成功是否依赖过度劳动或属人判断；责任是否被转移到个人；以及是否因为表面结果遮蔽了结构缺失，而继续重复使用同样的粗略理解。

## Validity conditions
当粗略理解进入设计或判断、必要条件被遗漏，并且现实运行通过额外负担或个人应对来补偿这些缺失时，本论的解释成立。

## Failure conditions
如果把本论简化为“理解浅的人有问题”，把所有失败都只归因于理解不足，把一次成功直接等同于可重复成立，或者把现场努力等同于设计完整，都会偏离本论的中心。

## Falsification conditions
如果理解误认、设计条件缺失、现场负担、责任转移和问题反复之间没有稳定关系，或者另一个因果解释持续表现出更强的解释力，那么这一读解需要调整。

## Required distinctions
无知 / 理解误认；一次成功 / 可重复成立；现场努力 / 设计完整度；个人失误 / 结构条件缺失；结果出现 / 对因果条件的理解。

## Interpretation constraints
把本论理解为责备“理解不足的人”，会失去其关于理解误认如何进入设计、缺失条件如何转化为现实负担的中心论点。把所有问题都归因于这一机制也超出本论范围；资源不足、外部环境、偶发因素等其他原因仍需另行区分。
