## Summary
本ParentはAI導入支援の企業紹介ではなく中川構造読解である。AI導入支援、実践会、SaaS等の対象側事実と、Nakagawa Masterがそこから抽出した「意思決定構造を近代化する実装装置」という価値核を分離する。中心は、AI導入によって露出する判断・責任・成果物・品質評価の曖昧さを、as-is / to-be可視化、人間とAIの役割分離、成果物化、業務運用、検証・改善へ接続することにある。なぜ機能・研修紹介ではなくこの価値核を外部記事の主軸へ選んだのかも保持する。

## Concepts
- 対象側事実: AI導入支援、実践会、SaaS、people & operations、field connection等の支援範囲。
- 表層分類: AI研修、AIツール導入、業務効率化。
- 構造不全露出: AI導入によって既存業務の判断点、責任点、成果物、品質基準の曖昧さが見えること。
- as-is / to-be: 現状業務とあるべき業務を分けて可視化する設計。
- 役割分離: AIへ委ねる処理と人間が判断・責任を持つ工程の分離。
- 成果物化: AI出力や学習成果を実務で使える形へ固定すること。
- 意思決定構造の近代化: 判断・実行・検証を再現可能な仕組みへ戻すというNakagawa Masterの価値核。

## Causal chain
AI導入 → 判断工程・責任・成果物の曖昧さ露出 → as-is / to-be可視化 → AI/人間の役割分離 → 判断・責任点明確化 → 成果物化 → 業務運用 → 品質・結果検証 → 改善反映 → 意思決定構造の近代化。

## State model
導入前曖昧相 / 構造露出相 / 可視化相 / 役割設計相 / 成果物化相 / 運用接続相 / 検証改善相 / 構造近代化相。

## Applications
AI研修、生成AI導入、業務改善支援を評価するとき、利用者数や速度だけでなく、誰が判断するか、AIと人間の役割が明示されているか、何が成果物として業務へ戻るか、品質と結果を検証して改善できるかを監査する。同型の構造不全がある他領域への比較は、対象事実が整合する範囲に限定する。

## Measurements and audit
対象側事実／表層分類／判断主体／AIと人間の役割／責任点／成果物定義／業務運用への接続／品質・結果の検証／改善循環／価値核／価値核選択理由／外部記事執筆理由／企業公式見解との境界を分けて確認する。原典にないROI・生産性向上率・時間削減率等を固定KPIとして追加しない。

## Validity conditions
判断・役割・成果物・運用・検証・改善が接続し、それが単なるAI利用や速度向上よりParentの価値核を説明する場合に有効である。中川構造読解として、対象事実とNakagawa Masterの読解、価値核、外部記事の構成判断を別層で保持する。

## Failure conditions
AI研修・ツール導入・効率化一般論へ平坦化する、受講や導入を成果と同一視する、成果物と検証を消す、Nakagawa Masterの読解をプリマベーラの公式企業定義へ誤帰属する、価値核選択理由または外部記事執筆理由を削除する場合は失敗する。

## Falsification conditions
AI導入成果が判断・役割・成果物・検証の仕組み化と無関係に継続し、別の因果が支援品質をより強く説明する場合は価値核の適用範囲を狭める。仕組み化しても運用品質や再現性へ接続しない場合も改訂が必要である。

## Required distinctions
対象側事実 / Nakagawa Masterの読解；AI導入支援 / 意思決定構造近代化；作業速度 / 判断品質；AI出力 / 業務成果物；学習完了 / 運用接続；導入 / 検証改善循環；価値核 / 企業公式見解；価値核選択理由 / 外部記事執筆理由。

## Interpretation constraints
「プリマベーラが意思決定構造の近代化装置と公式定義している」としない。AI導入すれば自動的に組織構造が改善するとしない。効率化の実益を否定せず、それと意思決定・責任・検証の構造を分ける。「社会翻訳」等の一般語だけで外部記事執筆理由を置換しない。
