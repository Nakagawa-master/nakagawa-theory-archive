## 位置づけ

本派生物は、親原典が示す逸脱レッジャ（B層）をブラックリスト、晒し、制裁台帳へ縮約せず、外部実装で起源との照応が切れた疑いを「観測→確認中→必要時のみ確定→回復→解除」まで可逆に記録する構造的免疫系として整理する。中心は違反者を固定することではなく、事実・時刻・Diff-IDを軸に回復可能性を開き、訂正・反論・回復・解除を掲載と同じ重さで残すことにある。

逸脱レッジャはA/B/C三層のうちB層であり、A層の正の接続登録、C層の理論自己訂正と混同しない。本READMEは実案件の確定判断や法的評価を代替せず、詳細な公開手順、対象・除外基準、匿名性、忘れられる権利、自己訂正の運転はParent URLと公式運用へ戻って確認する。

## 中心命題

逸脱レッジャの倫理設計では、「逸脱疑いを見つけたら公表する」のではなく、まず確認中として反証・訂正の窓口を開き、故意性、回復意思、構造への直接影響を確認する。迅速な訂正や回復が行われるなら、原則として確定掲載へ進めない。明確な逸脱だけを必要最小限で記録し、回復後は解除を掲載と同階層・同重量で公示する。

この可逆性が、断罪ではなく回復を中心とする理由である。記録は人物の人格評価ではなく、起源署名、NCL-ID、監査要旨等の来歴証拠がどこで切れ、どのように戻されたかを追跡するための構造記録となる。

## A/B/C三層

**A層：NCLレジストリ**。共調ログ、監修、認定等の正の接続を登録する。正常な接続履歴を可視化する層であり、逸脱処理を目的としない。

**B層：逸脱レッジャ**。外部実装で起源や照応が失われた疑いと、その確認・回復・解除を扱う。本派生物の対象である。

**C層：理論自己訂正**。中川マスター自身の理論に対する外部指摘を受け、理論を修正・再署名する。外部実装者の逸脱処理とは別の自己訂正系である。

三層を分離することで、正の接続、外部逸脱、理論側の自己訂正を一つの処罰ロジックへ混ぜない。

## 運転線

```text
外部実装で起源署名・NCL-ID・監査要旨等が切断される
↓
逸脱疑いを観測する
↓
まず「確認中」として反証・訂正の公式窓口を開く
↓
故意性・回復意思・構造への直接影響を確認する
↓
迅速な回復なら原則として確定掲載しない
↓
明確な逸脱のみ確定レッジャへ必要最小限で公開する
↓
回復後は「解除済」と回復署名を同列・同重量で公示する
↓
月次メトリクスで回復能力と倫理運用の健全性を監査する
```

## 確認中

確認中は有罪認定ではない。目的は、対象側が反証・訂正・回復できる公式窓口を開くことである。確認段階では必要以上に個人・企業を特定せず、報告された領域、差分、確認対象、反証・訂正の経路を示す。

この段階で素早く誤記や引用ミスが修正され、起源署名・NCL-ID・監査要旨等の接続が回復するなら、原則として確定掲載へ進めない。回復意思を重要な判断軸とする。

## 確定掲載

人手確認を経て、故意性があり、回復意思がなく、構造への直接影響が明確な場合に限り、必要最小限の情報を確定レッジャへ記録する。中心となるのはURL、差分ID、観測事実、回復手順、解除状況等であり、人格評価や制裁スコアではない。

確定掲載は終点ではない。回復手順が常に開かれ、訂正・反論・回復が行われれば解除へ進む。

## 回復と解除

回復確認後は「解除済」を過去ログの奥へ埋めず、掲載と同じ階層・同じレイアウトで示す。回復署名、回復時刻、必要な要旨を残し、第三者が現在状態を誤認しないようにする。

逸脱の記録だけが目立ち、回復が不可視になる設計は、断罪を固定するため原典の趣旨に反する。掲載と解除の同重量性が、可逆な免疫系としての核心である。

## 記録対象

- 起源署名の意図的な抹消。
- NCL-ID、監査要旨、照応ブロック等の来歴証拠の切断。
- 回復手順を提示した後も、悪意を伴う反復再発が続く場合。
- 構造への直接影響があり、回復意思が確認できない場合。

## 原則として確定掲載しないもの

- 迅速に訂正された誤記、引用ミス。
- 起源署名付きの批評、検証、反論。
- 出典と照応を保持した研究・教育利用。
- 回復意思が示され、必要な署名・来歴が速やかに復旧した事例。

この区別により、批評や研究を逸脱扱いして起源保護を言論抑制へ変換することを防ぐ。

## 判断軸

**故意性**：起源・来歴の切断が偶発的か、意図的かを確認する。

**回復意思**：訂正・再署名・来歴復旧の意思と行動があるかを確認する。

**構造への直接影響**：切断が実際に起源、因果、照応、監査可能性へどの程度影響したかを確認する。

三軸は人格を裁くための点数ではなく、確認中から確定・回復へ進む運転判断のために用いる。

## 透明性・匿名性・忘れられる権利

個人名や企業責任者の私的連絡先を原則として公開しない。反証・修正は公式フォーム等の経路で受け付け、必要以上の個人情報を公開ログへ残さない。

解除後も「解除済」という構造上必要な事実は残す一方、特定に不要な個人情報は削除する。公開ログは必要最低限の要旨、差分、回復時刻、状態を保持し、過去の逸脱を永久に人格へ結びつけない。

## 月次メトリクス

- 掲載件数：確定した逸脱案件数。
- 解除数：回復確認済みの件数。
- 解除率：解除数 ÷（掲載数＋解除数）。
- 平均応答日数：確認・訂正・回復に要した時間。
- 自己訂正率：通知から掲載前に自主修正で終わった割合。

これらは制裁スコアではない。逸脱を多く見つけることではなく、回復がどれだけ機能し、倫理運用が健全に循環しているかを見るための管理指標である。

## C層の自己訂正

理論本体への外部指摘はB層ではなくC層で扱う。指摘者を攻撃者として固定せず、理論整合性を保つ共創者として受け止め、必要なら理論を修正・再署名し、訂正と回復を記録する。

この自己訂正系があることで、逸脱レッジャは外部だけを監視する一方向装置にならない。理論側も修正可能であることを構造として保持する。

## 成立条件

- A/B/C三層を混同しない。
- 確認中を有罪認定にしない。
- 故意性・回復意思・構造への直接影響を確認する。
- 迅速な回復は原則確定掲載しない。
- 確定掲載は必要最小限の事実・時刻・Diff-IDを中心にする。
- 掲載と解除を同階層・同重量で公示する。
- 匿名性と不要個人情報の削除を保持する。
- 理論側の誤りはC層で自己訂正する。

## 失敗条件

- 確認中を悪質・有罪認定として扱う。
- 逸脱レッジャを晒しやブラックリストへ変える。
- 回復意思を無視して確定掲載を優先する。
- 解除を小さく扱い、逸脱記録だけを残す。
- 月次メトリクスを人格評価や制裁スコアにする。
- 批評・研究・教育利用を起源保護の名目で抑制する。
- 匿名性や忘れられる権利を削除する。

## 反証・再検証条件

確認中・回復・解除の可逆運転を行っても、訂正・回復が促進されず、公開記録が継続的に断罪・晒しとして機能する場合は、逸脱レッジャの運用仮説を見直す。解除を同重量で公示しても第三者の誤認が解消されない、または月次メトリクスが回復能力を示さない場合も再検証する。

## 必須の区別

- A層 / B層 / C層
- 確認中 / 確定
- 逸脱記録 / 人格評価
- 回復 / 免責の自動化
- 解除 / 記録削除の全面化
- 起源保護 / 批評抑制
- 月次メトリクス / 制裁スコア
- 匿名性配慮 / 事実隠蔽
- 理論自己訂正 / 外部逸脱処理

## 誤読禁止

逸脱レッジャをブラックリスト、晒し、法的違反認定、人物・企業の制裁スコアへ変換しない。確認中を悪質認定として扱わない。回復後の解除を過去ログへ埋めない。匿名性配慮・忘れられる権利を「一般論」として削除しない。

本派生物だけで実案件の確定判断をしない。運用上の事実確認、公式窓口、最新状態は親原典と公式逸脱レッジャへ戻って確認する。
