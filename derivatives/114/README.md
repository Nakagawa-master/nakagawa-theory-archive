## 位置づけ
本派生物は、逸脱レッジャをブラックリストや制裁台帳ではなく、起源からのズレを事実・時刻・差分として記録し、反証・訂正・回復・解除までを同じ重みで公開する「回復の記録装置」として整理する。NCLレジストリの正の接続記録、外部逸脱を扱うB層、理論本体の自己訂正を扱うC層を混同せず、B層だけを逸脱レッジャとして扱う。

## 中心命題
構造的免疫は、逸脱を見つけて罰することで成立するのではなく、疑いと確定を分離し、個人攻撃を避け、修正可能な差分を示し、回復意思があれば掲載を最小化し、確定掲載後も解除・回復署名を同列に残すことで成立する。記録は感情語ではなく事実・時刻・Diff-IDへ限定し、目的を抑止より可逆な回復路の保証へ置く。

## 因果線
```text
起源逸脱を晒し・炎上で処理する
↓
当事者防御と対立が増え回復路が閉じる
↓
反対に何も記録しないと起源蒸発と再発が残る
↓
疑いを「確認中」として確定案件から分離する
↓
事実・時刻・差分だけを記録する
↓
反証・訂正・回復手順を同じ入口で提示する
↓
確定時のみ必要最小限を公開する
↓
回復後は解除記録を同列で公示する
↓
月次指標で免疫系の健全性を監査する
```

## 構造層
**1.** 層分離：A=NCLレジストリ、B=外部逸脱レッジャ、C=理論自己訂正を区別する。

**2.** 確認層：通報直後を「確認中」とし、悪質認定と分離する。

**3.** 事実層：感情語を排し、事実・時刻・差分・回復条件を記録する。

**4.** 回復層：反証、訂正、解除、回復署名を掲載と対等に扱う。

**5.** 免疫監査層：掲載数、解除数、解除率、平均応答日数、自己訂正率を観測する。

## 適用例
**1.** 起源署名を削除した再利用が報告された際、まず確認中として訂正窓口を開く。

**2.** 引用ミスがすぐ修正された場合、原則として確定逸脱レッジャへ載せない。

**3.** 起源を明示した批評・反論・研究利用は逸脱として扱わない。

**4.** 確定掲載後に回復した案件は「解除済」を同じ階層・同じ重みで残す。

## 測定・監査点
- 確定掲載件数
- 解除数
- 解除率
- 平均応答日数
- 自己訂正率
- 誤掲載率
- 反証受付率
- 個人情報最小化率
- 再発率

## 成立条件
- 確認中と確定を分ける。
- 記録を事実・時刻・差分へ限定する。
- 回復意思を評価する。
- 批評・研究・迅速訂正を逸脱と混同しない。
- 解除と掲載を同じ重みで示す。
- 個人名や私的連絡先を原則公開しない。

## 失敗条件
- 通報だけで悪質認定する。
- 感情語や人格評価を掲載する。
- 解除記録を小さく扱う。
- 回復意思がある事例まで晒す。
- 批評・反論を逸脱として抑圧する。
- 個人情報を不要に公開する。

## 反証条件
- 回復路を設けても訂正・解除率が改善しない。
- 確認中公示が実質的な制裁・晒しとして働く。
- 個人情報最小化をしても対立の個人化が減らない。
- レッジャ運用が批評・研究を萎縮させる。
- より非公開な通知・仲裁方式の方が回復率と公正性で一貫して優れる。

## 必須の区別
- 確認中 / 確定
- 逸脱 / 批評
- 記録 / 断罪
- 回復 / 隠蔽
- 解除 / 削除
- B層 / C層
- 公開透明性 / 晒し
- 免疫 / 排除

## 誤読禁止
- 逸脱レッジャをブラックリストにしない。
- 通報を有罪認定と同一視しない。
- 批判者を攻撃者として扱わない。
- 解除済み事例を永久に罰し続けない。
- 個人名・私的連絡先の公開を正当化しない。
- 派生物を原典の代替にしない。
