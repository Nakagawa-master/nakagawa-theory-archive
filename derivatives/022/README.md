## 位置づけ
親原典AKI-014は、単なる「AI活用失敗」「DX失敗」「コンサル依存」「プロンプト品質」の話ではなく、事業の成立条件を横断して接続する連結責任が空白のまま、局所最適化とAI形式化が再帰的に事業自己認識を汚染する悪因果を扱う。公式派生物022はその構造を第三者が検索できる公開入口である。

原典の焦点は、AIが一度誤った答えを出すことではない。事業価値、顧客判断、営業、マーケティング、広報、プロダクト、経営判断、情報資産、AI参照系の間をつなぐ責任が不在のまま、それぞれの専門領域で「正しそうな成果物」が生成され、それが正式資料・社内ナレッジ・AI参照情報として保存され、次の人間とAIがそのズレを正規情報として再利用することにある。

## 中心命題
構造把握は、図解・フレームワーク・整理された文章が存在することでは成立しない。何が事業価値を生み、誰の判断がどの顧客・商品・営業・広報・運用・経営判断へ接続し、その差分を誰が検証し修復するのかという連結責任が追跡できて初めて、事業構造は自己認識可能になる。

連結責任が空白のまま専門家やAIが局所的な完成度を高めると、形式上の整合性は上がって見える一方、事業全体の成立条件とのズレが見えにくくなる。さらに、その成果物が正規ナレッジとして保存されると、ズレは単発の誤りではなく事業OSの内部状態として再生産される。

## 因果線
連結責任の空白
→ 各専門領域が自己完結的に最適化
→ AIが文章・図表・戦略・分類を高速に形式整備
→ 形式の完成度が「構造理解」の代理になる
→ 事業成立条件とのズレが検出されにくくなる
→ ズレた成果物が社内資料・ナレッジ・テンプレート・AI参照情報として正規化される
→ 人間とAIが正規化されたズレを再参照する
→ 次の企画・営業・マーケ・広報・経営判断へ同じズレが継承される
→ 汚染された事業OSが自己再生する
→ 組織が自社の価値・顧客・判断根拠・責任線を自分で説明できなくなる
→ 事業自己認識を喪失する。

重要なのは、途中の一工程だけを直しても再発し得ることだ。元の参照束が汚染されたままなら、別の担当者・別のAI・別の施策が同じ誤った前提を再利用する。

## 構造層
### 1. 連結責任層
誰が事業価値と顧客判断を、営業・マーケ・広報・プロダクト・経営・情報資産へ接続するのかを固定する。単なる部門横断会議ではなく、成立条件の接続責任が必要である。

### 2. 専門最適化層
各専門家は自領域では妥当な成果物を作り得る。しかし局所妥当性と事業全体妥当性は同じではない。連結責任がなければ、各最適化結果の間に意味差分が蓄積する。

### 3. AI形式化層
AIは入力された前提を高速かつ整然と展開できる。前提の接続責任が欠けている場合、AIはズレを除去するのではなく、ズレを読みやすく・再利用しやすく・正規情報らしくすることがある。

### 4. 正規化層
完成した文書、CRM項目、提案書、FAQ、ブランド文言、戦略資料、AIプロンプト、検索用ナレッジなどへズレが埋め込まれると、後続工程はそれを「既知の事実」として扱い始める。

### 5. 再帰汚染層
人間とAIが内部ナレッジを再参照し、同じ前提から次の成果物を生成することで、事業OS汚染が自己再生する。ここが単発のAI誤答との決定的な違いである。

### 6. 自己認識喪失層
最終的に、組織内部で「なぜこの商品を売るのか」「誰のどの判断を価値としているのか」「何を変えれば成果が改善するのか」「誰が全体接続を修復するのか」が説明できなくなる。

## 測定・監査点
原典にない万能スコアやAI成熟度点数は作らない。監査するのは、事業価値から顧客判断、営業・マーケ・広報・プロダクト・経営判断までの接続線が第三者に追えるか、各成果物の前提と差分が追えるか、正規ナレッジへの登録時に全体成立条件との整合確認があるか、AIが何を参照して生成したかを逆引きできるか、修正後に古いズレた情報が残存しないかである。

特に「成果物数が増えた」「生成速度が上がった」「資料が整った」「部門間で同じ言葉を使っている」は単独では成功判定にならない。これらは連結責任が成立していなくても上昇し得るため、反転評価可能性を持つ。速度や統一感が上がるほど、ズレが正規化されている場合には再帰汚染の速度も上がり得る。

## 成立条件
- 事業価値と顧客判断の接続責任が特定できる。
- 各部門成果物の前提・根拠・差分・責任線が追跡できる。
- AI生成物が正式知識へ入る前に、事業全体の成立条件との接続確認が行われる。
- 修正が局所ファイルだけでなく参照元・派生先まで伝播する。
- 人間とAIの双方が、最終的に原典・一次情報・責任主体へ戻れる。

## 失敗条件
- 「AIを使わなければよい」という反AI論へ縮約する。
- 「プロンプトを改善すれば解決する」という局所技術論へ縮約する。
- 部門横断会議や共通フォーマットの存在だけで連結責任成立と判定する。
- 形式整合性、文章品質、生成速度、資料数を事業理解の代理指標にする。
- 汚染された内部ナレッジを残したまま表層成果物だけを修正する。

## 反証・改訂条件
親原典の統合監査要旨では、企業が構造を生成原理として扱い、専門家間の判断衝突を連結層で再判定し、AI生成物の保存・再利用前に事業価値・顧客判断・社内認識・情報資産・価値関数の整合性を監査している場合、本論の仮説Aは棄却または適用外となる。また観測窓δでAI活用量の増加と同時に顧客判断・営業成立・部門間照応・意思決定精度・現場実装力が改善し、人間側の参照構造が継続検証されている場合も仮説Aを改訂対象とする。

## 必須の区別
- AI活用 ≠ 連結責任
- 構造把握 ≠ 図解・整理・フレームワーク
- 部門横断 ≠ 成立条件の連結層
- 局所最適 ≠ 事業全体最適
- 形式整合性 ≠ 意味整合性
- 生成速度向上 ≠ 事業自己認識向上
- AI生成物 ≠ 正規化してよい事業知識
- 単発誤答 ≠ 再帰的事業OS汚染

## 誤読禁止
本原典をコンサルタント批判、専門家批判、AI批判、DX批判へ変形しない。専門家やAIは、連結責任が正しく設計されていれば有効な実装主体になり得る。問題は主体の属性ではなく、全体成立条件をつなぐ責任が空白のまま、局所的な正しさが正規知識として再帰利用される構造である。

また「AIが事業を理解していない」ことだけを問題にしない。人間側の事業自己認識がすでに断絶していれば、AIはその断絶を形式化して再生産する。したがって修復対象はAI出力だけでなく、人間・情報資産・責任線・参照系を含む事業OS全体である。
