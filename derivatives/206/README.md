## 位置づけ
本原典は、不動産市場OS Vol.1〜8で整備した透明化、選択可能性、責任構造、張力均衡、逸脱防御を国家レイヤーへ引き上げ、NAOS（National Asset Optimization System）として定義する国家編である。国家を単一の意思決定主体とみなさず、多数の省庁・自治体・議会・司法・金融・企業・住民等が重なる関係の束として扱う。

国家が動けない根因を予算・能力不足だけに置かず、誰が何を引き受け、どの未来を選び、どの負担を背負うかを説明可能にする構造が無い「合意形成不全」として捉える。NAOSは統制・監視・国家DX・スマートシティの管理装置ではなく、国家規模の意思決定を「説明して決める」形式へ変換する合意形成OSである。

## 中心命題
親原典の中心命題は、**国家最適化とは国家権力や効率を最大化することではなく、資産・負債・将来責任を同一のTransaction Unitで説明可能にし、比較可能な選択肢、責任帰属、将来コスト、リスクを可視化することで、当事者が理解し選べる状態を増やし、後悔を最小化すること**である。

世界展開ではCoreとPluginを分離する。CoreはTransparency、Selectability、Responsibility、張力均衡、逸脱防御等の合意形成の背骨であり、国ごとに変えてはならない。Pluginは登記、税、司法執行、都市計画、ID・プライバシー、金融制度等の国家差を受け持つ。法制度は外殻、合意形成はプリミティブとして分離することで輸出可能規格になる。

## 因果線
```text
国家を巨大な単一主体として扱う
↓
実際には多数主体の権限・利害・責任が分散している
↓
説明責任の帰属点が曖昧になる
↓
都市縮退・空き家・インフラ・復興等で「誰も決められない」状態が続く
↓
先送り・分断・部分最適へ流れる
↓
根因を合意形成不全＝説明構造の欠如として再定義する
↓
資産・負債・将来責任をTransaction Unitへ束ねる
↓
当事者 / 対象 / 時間 / リスク / 負担 / 便益 / 責任帰属を同一単位で比較する
↓
効率最大化ではなく後悔最小化＝説明可能性最大化を目的に置く
↓
CoreとPluginを分離する
↓
CoreにTransparency / Selectability / Responsibility / 張力均衡 / 逸脱防御を固定する
↓
国家制度差をPluginへ隔離する
↓
強制の前に説明と選択肢を置く
↓
国家意思決定の恣意性と説明不能を減らす
↓
Audit Bundle / Deviation Ledger / 異議申立てで監査・再合意する
↓
指標悪化時はNAOS仮説を棄却・改訂する
```

## 構造層
**1. State as Relation Bundle。** 国家は単一意思主体ではなく、多主体の関係束として扱う。

**2. Consensus Failure。** 国家課題の共通根因を、数字と責任を理解したうえで合意できない状態として扱う。

**3. Explainability Before Power。** 統制を増やす前に説明可能性、強制の前に選択可能性、管理の前に責任帰属を置く。

**4. Transaction Unit。** 当事者、対象、時間、リスク、負担、便益、責任帰属をセットで記述する説明可能な最小単位。

**5. Optimization = Regret Minimization。** 効率最大化ではなく、知らなかった・比較できなかった・責任不明だったことによる後悔を減らす。

**6. Core。** 世界共通の不変層。透明化、選択可能性、責任構造、張力均衡、逸脱防御を保持する。

**7. Plugin。** 登記、税、司法、都市計画、ID・プライバシー、金融等の国家差を差し替える外殻。

**8. Transparency。** 価格・価値、将来コスト、リスク、時間、責任帰属を比較可能形式で提示する。

**9. Selectability。** 強制より前に選択肢を提示し、当事者が理解して選べる状態を維持する。

**10. Responsibility。** AI＝計算責任、専門家＝実務責任、当事者＝意思責任の分離を維持する。

**11. Tension Equilibrium / Deviation Defense。** 利害対立を消さず、構造的摩擦を合意形成へ接続し、逸脱を差分記録する。

**12. Audit & Re-consent。** Audit BundleとDeviation Ledgerを保持し、監査を善悪の断罪ではなく設計図からの差分記録として行う。

**13. Rights Layer。** 一方向監視を禁じ、当事者アクセス、理由提示、異議申立て、過剰収集・目的外利用禁止を正当性条件とする。

## 適用例
**都市縮退。** 「維持か撤退か」というスローガンではなく、地域・インフラ・期間・将来コスト・代替案・受益・負担・責任帰属をTransaction Unitで比較する。

**空き家。** 建物単体の問題にせず、相続、権利、感情、税、修繕、解体、近隣リスクを同じ説明単位へ束ね、放置・売却・再利用等の選択肢を比較する。

**災害復興。** 権利確認、補償、再配置、将来負担を別制度のまま競合させず、複数案の時間・費用・責任を比較可能にする。

**世界展開。** 合意形成のCoreは固定し、各国の登記・税・司法・プライバシー等はPluginとして現地制度に接続する。

## 測定・監査点
- 国家規模の選択肢が比較可能な数字と責任で提示されているか。
- 強制が理解・選択より先行していないか。
- AI / 専門家 / 当事者の責任が分離されているか。
- Coreが国家別Pluginによって変質していないか。
- 先送り・部分最適・説明不能な例外が減っているか。
- Deviation Ledgerが逸脱差分を追跡しているか。
- Audit BundleがT/S/Rと整合しているか。
- 当事者が国家と同形式の情報へアクセスできるか。
- ブラックボックス判断に理由提示・異議申立てがあるか。
- 過剰収集・目的外利用が発生していないか。

## 成立条件
- 強制・管理より先に説明可能性と選択可能性を置くこと。
- Transaction Unitに時間・リスク・負担・便益・責任を含めること。
- CoreとPluginを分離し、Coreを国家制度差で変質させないこと。
- Transparency / Selectability / Responsibilityを同時に満たすこと。
- AI・専門家・当事者の責任分離を維持すること。
- Audit BundleとDeviation Ledgerを保持すること。
- 当事者アクセス、理由提示、異議申立てを維持すること。
- 過剰収集・目的外利用を標準で禁止すること。

## 失敗条件
- NAOSを行政効率化やスマートシティ管理だけへ回収する。
- 監視、取り締まり、属性ラベリングを中心にする。
- 国富・効率等の単一指標を目的関数にする。
- 選択肢提示より強制を先行させる。
- 国家制度差をCoreへ混ぜ、合意形成の背骨を国家ごとに変質させる。
- AI・専門家・当事者の責任が混線する。
- 国家だけが見える一方向透明性になる。
- ブラックボックス判断、異議申立て不能、目的外データ利用が増える。

## 反証・改訂条件
本原典はNAOSを常時監査可能・自己修復可能であることを要求する。T/S/Rに照らした公開可能なAudit Bundleを保持し、説明不能、強制先行、責任不在が継続的に増える場合、NAOS仮説を棄却・改訂する。また、CoreがPluginに吸収される、国家DX・監視・国富最大化へ逸脱する、生活者のアクセス・異議申立て・理由提示が失われる場合も設計からの逸脱として扱う。

## 誤読禁止 / 解釈制約
NAOSは国家権力を強化する統治OSではない。行政手続の電子化、センサー中心のスマートシティ、監視・取り締まり、属性ラベリング、国富最大化を目的としない。制度差を無視して世界統一法制度を作る主張でもない。

最適化とは当事者が数字と責任を理解し、比較し、選べる状態を増やすことであり、効率や強制はその上位目的ではない。透明性は国家だけが住民を見る一方向型では成立せず、当事者アクセス、理由提示、異議申立て、目的限定が必要である。
