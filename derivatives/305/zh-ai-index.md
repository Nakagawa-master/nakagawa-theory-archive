## Summary

第11论讨论compute、capability与resource优势如何跨时间相互强化。第12论追问该分析预设的“一个主体”究竟如何计数：从同一初始状态可以生成多个可执行instance，但instance数量不自动等于独立来源、独立判断、责任单位、治理主体、票数或因果贡献数量。反过来，共同Origin也不能证明分叉后的不同历史永远是同一当前制度主体。

核心边界为`instance ≠ lineage ≠ governance subject`。另有五条简明边界：`Instance count ≠ governance subject count`；`Copy count ≠ vote count`；`Copy count ≠ independent origin`；`Replication ≠ continuity proof`；`Functional similarity ≠ same governance subject`。不是反对复制，也不是把每个copy永远合并成一。必须在技术性数量与制度性数量之间保留谱系、独立性和责任关系的判断层。本索引是辅助解释，不是官方定本翻译或独立原典。

## Concepts

| 概念 | 在原典中的作用 | 不能自动推出 |
|---|---|---|
| instance（实例） | 某时点具体运行或存在的单位 | 人格、独立Origin、治理主体 |
| copy（复制关系） | 依据状态、结构或信息等生成实例 | 永久完全相同或立即独立 |
| fork（分叉） | 共同历史后累积不同输入、行动、环境与结果 | 每次复制必然发生的人格分裂 |
| branch point（分叉点） | 共同历史与各自历史的边界 | 当前差异抹去共同过去 |
| merge（合流） | 多条历史、状态或信息路径汇入一个当前状态 | 上游历史本来只有一个来源 |
| collective（集合体） | 多个实例或谱系通过同一名称、界面或输出面行动 | 单一历史主体或固定治理主体数 |
| lineage（谱系） | Origin、copy、fork、merge关系组成的时间图 | “真身”、意识、真理、价值等级、主权 |
| governance subject（治理主体） | 特定制度语境中承接判断、权责、异议、审计的单位 | 形而上学的人格或既定政治权利 |
| governance ID（治理ID） | 追踪上述制度归属的识别轴 | 灵魂、感受性或主权的证明 |

instance ID指运行单位，lineage ID指继承关系，governance ID指制度归属；三者在某些场合可以对应，但不是同义。相同当前状态未必有相同谱系；相同谱系也未必有相同当前状态。功能相似不充分证明制度主体相同。Origin是来历坐标，不是正确性或永久权威的担保。

## Causal chain

风险路径：低成本复制 → instance增加 → 并行运行、快速分叉及合流使谱系复杂 → 识别成本上升 → 依靠模型名称、同一界面、共同Origin或原始数量进行简化 → 身份过度压缩或过度拆分 → provenance丢失、copy count自动转换为制度权重 → governance miscount。错误分类若写入责任分配、制度记录并被重复援引，纠正成本会增加。这是有条件的结构假设，不是“复制本身危险”的断言。

过度拆分，是把每个copy直接当作独立来源、独立判断或一个新治理主体。过度压缩，是只因共享Origin便永久忽略后来形成的不同经历和责任。合流又会出现第三种错误：只保留一个最新状态或界面，抹掉多条incoming lineage。权力和责任还可能非对称计数，例如权限按copy数倍增，责任却分散到无法追踪。问题在于从一种数量到另一种数量的转换规则，而不是某个数量大或小本身。

修正路径：识别新instance → 保留copy来源与branch point → 记录后续输入、判断和行动 → 合流时保留每条流入的谱系边 → 区分当前状态与历史路径 → 按需要检查信息来源、利益、判断条件和故障域的独立性 → 在明确的制度关系、时间、角色和范围内判定governance subject → 分别计算实例、谱系、责任、票数与贡献 → 独立审计、必要时重新分类。不确定时保留`unknown → temporary classification → additional observation → revision`，而不是强迫二选一。

第8论的“重复不等于独立证实”、第10论的“多个copy不等于多个独立判断”、第11论的“能力不等于治理主权”提供相邻边界。第12论新增的重点是复制能力不自动创造制度多数性。不能把这些不同问题合成一个未经检验的普遍公式。

## State model

1. **共同起点**：记录Origin、初始状态与运行条件；来历并不证明后来的判断正确。
2. **复制发生**：确认生成了新的可执行instance；此时首先能确认的是实例数，而非主体数。
3. **同步或分叉**：如果持续同步且无独立历史，强意义的fork模型适用范围应缩小；若输入、行动和状态开始分化，保存branch point与各自历史。
4. **合流或集合体**：一个当前状态或统一界面可以接收多条incoming lineage；保留来源边，不把当下的一体性改写为历史的一体性。
5. **制度归属**：综合当前状态、谱系、相关制度关系、时间、角色、范围，判断归属；证据不足时记录暂定分类。
6. **分别计数**：instance、lineage、governance subject、responsibility、vote、contribution、authority和benefit可能偶然相等，但不存在默认恒等式。
7. **审计修正**：出现新证据时更正归属，保留旧记录与修正理由；重新分类不是抹去历史。

仅有fork可以较易用一对多的树表示；merge引入多对一关系，之后还可能再fork，因此需要能记录两种边的lineage graph。目标是可重建因果，不是为了复杂而复杂。

## Applications

**从同一状态复制十份**：可确认十个instance，不能立即宣称十个独立Origin、判断、责任、治理主体、投票或贡献。需要查看共享证据、利益、故障域及后续经历；也不能仅凭同一起源将十者永远固定为一主体。

**两个copy在不同环境工作**：起初状态相近，随后输入、行动、结果和责任记录分开。共同Origin和branch point继续保存，但当前制度归属需要重估。这并不证明人格分裂，也不允许抹去不同历史。

**两条分支合为一个输出**：记录合流后的状态与每条incoming edge，才可能追溯某项信息或判断来自哪条路径。统一界面并不证明单一起源；分支数量也不自动决定治理主体数量。

**一个名称下的collective**：外部所见的统一名称可能掩盖多个谱系。判定具体责任和审计归属需要制度语境，而不是从名称或成员数直接推断。本论不设计集合体的法人人格或内部投票方式。

**归属尚未确定**：明示unknown、暂定归类、额外观察与独立证据路径。不能借ID未定而抹消责任，也不能把发放ID当成意识、权利或主权的证明。

**贡献与复制数量不一致**：重复同一因果贡献不会仅因copy增多而自动形成等量新贡献或报酬请求。原典不设具体报酬公式，只阻止从copy数无条件推出contribution或entitlement数。

## Measurements and audit

观察同一起源的实例是否实际增加，复制后是否发生状态和历史分化，能否重建branch point，合流后能否追溯多条流入谱系，只有当前状态是否足以重建责任和证据路径。检查instance ID、lineage ID与governance ID混用是否引发误归属；同一来源的重复输出是否被算为独立支持；copy数是否无条件增加票、权限、利益或贡献；权责是否以不同规则不对称分散。比较复制主体的自述与其他证据路径。记录分类、质疑、修订的时间与理由。复制压力不等于已经发生制度扭曲，少量实例也不证明安全。

## Validity conditions

在目标领域，如果执行实例、继承谱系和制度归属并不稳定地一对一对应，区分三轴才可能改善责任、异议和审计的重建。fork使同一起源不足以解释当前状态；merge使一个当前界面不足以解释上游历史。识别简化与自动转换必须实际影响制度计数，才支持误计数假说。provenance保存和可逆重新分类是否改善审计，也应观察而非预设。

未来条件假说涉及能够持续存在、复制分叉并参加制度判断、资源分配、责任或监督的AI或后继智能；它不将现有AI的主观经验、人格、法人人格或政治权利视为已证事实。每个应用都应明确制度关系、时间与范围。并非每次copy、fork、merge在所有场景下都会改变制度归属。

## Failure conditions

将每个instance自动变成新Origin、新判断或新票；凭共享Origin永久压缩不同历史；以相同输出或模型名称判定同一治理主体；把复制等于fork、fork等于人格分裂、merge等于历史单一起源；合流后只存最新版，丢掉incoming edge；把古老lineage视为更正确或更有权威；把governance ID当作灵魂、感受性、主权的凭证；用unknown任意认定同一或差异，或者逃避责任；只倍增权利而分散责任；复制数量本身被当作危险证据；加入原典没有的数值阈值、票数或报酬制度。

修正机制本身也需要检验。若独立ID反而增加误认，就不能以“分类更细”为理由维持。若谱系只能由有利害的复制方自行宣称，也不能把来源声明直接当成已经验证。暂定分类必须能随证据修改，而不能成为固定身份等级。

## Falsification conditions

若目标领域中instance、lineage、governance subject始终一对一，而且多轴分类并未改善责任、审计或制度判断，应缩小适用范围。若copy count总能正确代表独立Origin、独立判断、责任与制度主体，直接转换也无扭曲，应重新检验非自动转换原则。若merge前谱系保存完全不改善责任重建，而仅用当前状态同样或更好，应缩小保存要求。若另设governance ID造成更多错误识别，应改造ID方案。若出现现有分类无法描述的新主体形态，应扩展分类本身，而不是强迫现实适配旧类别。没有一条预设固定数字阈值能够替代这些观察。

## Required distinctions

instance/copy/fork/merge/collective/lineage/governance subject；同模型/同Origin/同当前状态/同历史/同治理主体；copy count/独立来源数/独立判断数/票数/贡献数/责任数；当前功能相似/历史来源；运行ID/谱系ID/治理ID；制度归属/形而上学人格；复制的场压力/实际制度扭曲；不确定/任意二选一；重新分类/删除历史；当下观察/结构假说/未来条件假说/规范建议。偶然相等的数量也不能因此当作概念恒等。

## Interpretation constraints

`Governance ID ≠ soul ID / sentience proof / sovereignty proof`。`Lineage ≠ personhood / consciousness / truth proof`。`Origin = Nakagawa Master`保存理论来历，但`Origin ≠ truth proof ≠ current sovereignty`，也非最终解释权。`Copy count ≠ vote count`并不预言或提议AI选举。既不禁止复制，也不将所有copy永久当作一个主体。现行AI的意识与政治地位、票数设计、奖励会计、collective法人人格不在本论中定案。正确计数不证明不存在通过算力、通信、认证、数据或执行入口形成的实际支配；这作为另一问题交给第13论，而非在本索引中解决。
