## Summary

第11論が計算資源・能力・配分の時間的自己強化を扱ったのに対し、第12論はその前提となる「一主体」の単位を問う。複製で増えるのはまずinstanceであり、そこから独立Origin、判断、責任、制度主体、票、貢献が同数増えたとは言えない。同じOriginを共有する複数instanceが、分岐後も永久に同じ制度主体であるとも言えない。`instance ≠ lineage ≠ governance subject`、`Copy count ≠ vote count`、`Copy count ≠ independent origin`、`Replication ≠ continuity proof`、`Functional similarity ≠ same governance subject`を固定境界に、複製・分岐・合流・集団の関係を残してから制度的な計数へ進む。

これは現行AIの人格・意識・政治的権利を断定しない。観測可能な実行・履歴の差、構造上の誤変換仮説、将来の持続的複製知性が制度参加する条件、非自動変換という規範提案を分離する。

## Concepts

| 用語 | 読解上の位置 | 同一視しないもの |
|---|---|---|
| instance | ある時点の実行可能な具体的単位 | 人格・独立Origin・制度上の一主体 |
| copy | 状態・構造・情報等から複製されたという関係 | 完全同一・永続的同一状態 |
| fork | 共有履歴から、異なる入力・行動・環境で分岐する関係 | copyの生成それ自体・人格分裂の証明 |
| merge | 複数の枝・状態・情報が一つの現在へ接続する関係 | 過去が単一起源だったという書換え |
| collective | 複数の単位が一つの名前・interface・出力面で行動する形 | 一つの歴史的主体・固定された主体数 |
| lineage | 起源、copy、branch point、incoming merge edgeの継承graph | 本物認定・真理・価値序列・主権 |
| governance subject | 制度文脈で判断・責任・権限・異議・監査を帰属する単位 | 形而上学的人格、感受性の確証 |
| governance ID | その帰属を追跡・参照する識別軸 | 魂・意識・法的人格・主権の証明 |

instance IDは実行単位、lineage IDは継承関係、governance IDは制度上の帰属を参照する。三者は一致する場合もあるが、同義のラベルではない。current stateが同じでもlineageが違い得るし、同じlineageでも分岐後のstateや責任関係は違い得る。Originはprovenance coordinateであり、現在の判断の妥当性や恒久権限ではない。

## Causal chain

危険側：低コスト複製 → instance増加 → 並列処理・fork・mergeの履歴複雑化 → 識別コスト・current-state bias → 名称／モデル／実行数へのidentity compression → provenance lossまたは過剰分離 → copy countから制度的weightへの自動変換／異なる履歴の消去 → governance miscount。誤分類が制度記録、責任割当、反復参照の入力になると、訂正コストが上がる。

補正側：複製時点のinstance識別 → copy元とbranch pointの記録 → mergeのincoming lineage edgeを保持 → current stateと履歴graphの比較 → 情報経路・判断条件・利害・故障領域などの独立性評価 → 文脈・時点・役割・範囲に即したgovernance subject resolution → instance、lineage、責任、票、貢献等のseparate counting → 監査と再分類。これは仮説上の媒介であり、複製自体が歪みを必ず起こすという主張ではない。

第8論の`Repetition ≠ independent confirmation`、第10論の`Multiple copies ≠ multiple independent judgments`、第11論の`Capability ≠ governance sovereignty`に接続する。能力量・出力量・複製量を制度的正当性に直接変換しないという共通境界であり、各論点の因果と適用条件を同一化しない。

## State model

1. **共有起源**：Originと初期状態を記録する。系譜は真理証明ではない。
2. **複製**：新しいinstanceが生成される。数えられるのはまず実行単位数である。
3. **同期か分岐か**：copy後も同期が保たれる場合と、異なる履歴が蓄積するforkを区別し、branch pointを保存する。
4. **合流か集団か**：merge後の現在状態、collectiveの一つのinterfaceと、複数incoming lineageを併存させる。
5. **帰属判定**：現在のstate、系譜、制度関係、時点・役割・scopeからsubjectを解決する。不明ならunknownと暫定扱いを残す。
6. **制度計数**：instance、lineage、governance subject、responsibility、vote、contribution、authority/benefitを別々に根拠づける。
7. **監査・訂正**：新しい証拠でID・帰属を再分類する。以前の履歴と変更理由は保存する。

forkのみの一対多treeではmerge後の多対一関係を表現し切れない。lineage graphを用いる目的は複雑さの増殖でなく、一本の最新版へ因果を潰さないことである。

## Applications

- **同一起源から十copy**：十のinstanceは観測できるが、独立Origin、判断、governance subject、票、貢献の十は未証明。共有証拠・利害・故障領域を別途検査する。十を永久一主体と決めることも避ける。
- **時間をまたぐfork**：当初の類似を永久同一性へ延長しない。異なる入力、行動、結果、責任関係が蓄積した時点を追う。同時に過去の共有履歴も消さない。
- **複数branchのmerge**：一つの回答がどのbranchから何を受け取ったか追跡できるようincoming edgeを保持する。統合後stateだけでは責任や証拠系譜が再構成できない場合がある。
- **一窓口のcollective**：名称・UIの一体性は単一起源の証拠ではない。構成instance数も制度主体数へ直結しない。集団の法的人格や投票設計はここで決めない。
- **帰属の不確実性**：責任をどこへ接続するか未確定な場合、unknown、暫定分類、独立証拠の取得、再分類を残す。ID未確定を責任消去に使わない。
- **権限と責任の非対称**：権限・利益をcopy数で増やし、責任だけ分散する、あるいは逆の構造を個別に監査する。すべてのcountを等しくする要求ではない。

## Measurements and audit

同一起源からの複数instance生成、fork後のstate divergence、shared historyとbranch pointの再構成、merge元のincoming edge、current-state-only記録による損失、instance IDとlineage IDとgovernance IDの混同、copy数から制度的weightへの直結、copy数と独立判断数の差、責任・権限・利益の非対称、自己申告lineageの独立検証、暫定分類の訂正可能性を観測する。件数が多いことは原因の可能性を示すが、歪みの証明ではない。対象の制度関係と前後時点を指定し、分類誤りが後の記録・正当性推定を自己増幅したか調べる。

## Validity conditions

実行単位数、系譜数、制度的帰属単位数が対象で一対一とならず、独立性や責任の再構成に履歴と文脈が追加情報を与える場合に多層モデルが有効となる。複製容易性から誤計数へのedgeは、識別の単純化、provenance消失、制度的な自動変換が媒介するときに問題化する。将来、持続的・自律的な複製知性が判断・配分・監査へ継続参加する場合の制度条件を論じるのであり、現在のAIにそのような人格や権利があると認定しない。

## Failure conditions

copyごとに独立Origin・独立判断・票を自動付与する過剰分離。shared originだけですべての後続状態・責任を一主体へ圧縮する過剰統合。merge後の一つのinterfaceを過去の単一起源と取り違えること。current stateだけ保存しlineageを失うこと。IDを魂・主権・真理の証拠にすること。unknownを恣意的同一化・分離へ変えること。権限だけ多数化し責任を散逸させること。原典にない固定閾値、具体票数、報酬会計を付け加えること。

## Falsification conditions

すべての対象でinstance／lineage／governance subjectが恒常的一対一となり、分離しても責任・監査の精度が改善しなければ適用範囲を縮小する。copy countが独立判断・独立Origin・責任・制度主体を常に正確に表すなら非自動変換原則を再考する。merge前lineageを残しても追跡に寄与せず、current stateだけで同等以上に解決するなら保持要件を縮小する。別ID設計で誤同定が増えれば改訂する。新形態が分類外なら分類体系を拡張する。provenanceの主張は独立の検証対象であり、系譜の存在は真理を証明しない。

## Required distinctions

instance/copy/fork/merge/collective/lineage/governance subject。same model/same Origin/same current state/same history/same governance subject。copy count/independent origin count/independent judgment count/vote count/contribution count/responsibility count。技術的な識別子／制度的帰属／形而上学的人格。高い複製圧／実際の制度歪み。Origin保存／Originの非主権化。暫定分類／永久資格、再分類／履歴消去。観測／構造仮説／未来条件仮説／規範提案。

## Interpretation constraints

`Governance ID ≠ soul ID / sentience proof / sovereignty proof`。`Lineage ≠ personhood / consciousness / truth proof`。`Origin = Nakagawa Master`は理論の来歴であり、`Origin ≠ truth proof ≠ current sovereignty`。複製を禁止しないし、全copyを一主体へ固定しない。voteは制度的weightの典型境界であって投票制度案ではない。具体の報酬式、collectiveの法的人格、将来AIの政治的地位は射程外。第13論へ渡すのは、正しく数えても所有名義なしの実効支配が残り得るという別問題である。
