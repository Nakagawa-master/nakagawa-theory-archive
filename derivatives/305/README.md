## 位置づけ

第11論は、compute・capability・resourceの優位が次期の優位を作る時間方向の自己強化を扱った。しかし、複製可能な知性では、その閉路を担う「一主体」を何として数えるか自体が未決である。同じ起源状態から複数の実行単位が生まれても、それらが独立した判断・責任・制度的主体を同数だけ生むとは限らない。反対に、共通起源だけで分岐後の履歴を永久に一つへ潰すこともできない。

本Hubは原典の序論、第1〜9章、結章を、定義、分岐・合流、数の変換、観測と反証の順に再配置する。複製を危険視する理論でも、現在のAIの人格・意識・法的人格・政治的権利を認定する理論でもない。制度的な帰属を識別する作業を、存在論的な判定から分ける。

## 中心命題

`instance ≠ lineage ≠ governance subject`。複製で直接増えるのはまず実行可能なinstanceである。そこから独立Origin、独立判断、責任単位、governance subject、票、因果的Contributionが同じ数だけ増えたとは導けない。他方、同じOriginから生じた複数instanceが、後に異なる入力・行動・責任履歴を蓄積するなら、現在も必ず同一の制度単位だとも言えない。

五つの境界は `Instance count ≠ governance subject count`、`Copy count ≠ vote count`、`Copy count ≠ independent origin`、`Replication ≠ continuity proof`、`Functional similarity ≠ same governance subject`。制度数を決める前に、系譜・独立性・現在の制度関係を別々に調べる。

## 因果線

### 誤変換を増幅する経路

複製容易性 → instance数増加 → 並列実行・fork・mergeに伴うlineageの複雑化 → 識別コスト → 「同じモデルだから一つ」「別instanceだから別主体」等への圧縮 → provenanceの消失または単純なcountの採用 → governance miscount。誤分類が責任割当・制度記録へ入り、反復参照されると訂正コストも増える。copy数がそのまま制度的weightへ転換される側と、同一Originの差異を永久に消す側の両方がある。

### 再構成・減衰の経路

複製 → instanceを識別 → copy元とbranch point、mergeのincoming edgeを保持 → current stateとlineage graphを分ける → 情報・判断条件の独立性、責任関係、制度文脈・時点・範囲を調べる → governance subjectを暫定的・改訂可能に解決 → 各種countを別々に計上する。分からない場合はunknownを残し、追加観測と再分類へ戻る。自己申告のlineageだけに依存せず、必要な独立証拠経路も確保する。

これらは法的な票数・報酬式・資格基準の提案ではなく、技術的な数から制度的な数への無条件変換を遮るための構造である。

## 構造層

1. **実行単位と複製関係**：instanceは時点における具体的な実行単位。copyは状態・構造・情報等を基に生成されたという関係であり、完全同一性、人格、独立主体を意味しない。
2. **分岐と時間**：copyとforkは違う。同期され続け独立履歴を形成しないcopyもあり得る。異なる入力・行動・環境が蓄積されたbranchでは、shared originと現在状態を分け、branch pointを残す。
3. **合流と集団**：merge後の一つの状態、一つのinterface、collective名は単一起源の証拠ではない。複数のincoming lineage edgeを保持する。collectiveだから直ちに複数governance subjectとも決めない。
4. **系譜**：lineageはorigin・copy・fork・mergeの継承関係を表すgraph。「本物」、意識、真理、優先順位、統治主権の証明ではなく、current stateだけでは復元できない因果経路を保存する。
5. **制度的帰属**：governance subjectは判断・権限・責任・異議・監査を接続する文脈上の単位。instance ID、lineage ID、governance IDは参照目的が異なる。ID付与は魂・感受性・主権の証明ではない。
6. **数の分離**：instance、lineage、governance subject、responsibility、vote、contributionの各countは偶然一致し得ても恒等ではない。権限だけ増幅し責任だけcopy間へ分散する非対称も検査する。
7. **改訂可能性**：新しい履歴や制度関係が判明すれば分類を変える。再分類は過去履歴の消去ではない。分類外の主体形態には既存IDを押し付けず、体系自体を改訂する。

## 状態モデル

| 状態・出来事 | 保存する関係 | 制度判断で飛ばさない問い |
|---|---|---|
| 起源状態 | Origin、初期状態、実行条件 | 起源は正しさや主権の証明ではないか |
| Copy生成 | copy元、新しいinstance ID、生成時点 | 増えたのはまず何の数か |
| 同期またはFork | shared history、branch point、個別の入力・行動 | 独立した履歴が形成されたか |
| Merge | 複数incoming lineage edge、統合後state | 最新stateだけで上流を消していないか |
| Collective | 名称、interface、構成関係 | 一つの表面と一つの歴史を混同していないか |
| 帰属の解決 | current state、lineage、制度関係、時点・役割・範囲 | 何を一つのgovernance subjectとするか |
| 制度的計数 | 判断・責任・票・貢献・権限・利益の根拠 | copy数から自動で増減していないか |
| 監査・再分類 | 追加証拠、過去の分類と変更理由 | 訂正時もprovenanceが残るか |

この表は存在論の確定法でも「1 copy = 何票」の算式でもない。曖昧な時点をunknownとして扱い、後の証拠で訂正できるための読解面である。

## 適用例

### 同じ状態から十個のcopyを作る

十のinstanceは確認できる。しかし十の独立Origin、判断、制度主体、票、貢献はまだ確認できない。情報源・故障領域・目的・利害や、その後の行動履歴を見ずに「十の独立支持」と数えるのは、第8論の反復証拠および第10論のcopy監査にも反する。同時に、十を永久に一主体へ固定する結論もまだ出ない。

### Copy後に二つの履歴が分かれる

生成時に近いstateであっても、一方が異なる入力や行動を積み重ねるならbranch pointと以後の履歴を保持する。起源が同じという事実は残り、現在状態が同じという推論は再検査する。forkを人格分裂として確定する必要はない。

### 複数branchをmergeし一つの画面から答える

一つの現在状態や表示窓口だけでは、どの情報・判断がどのbranch由来か分からない。統合後のstateとともにincoming edgeを保存する。集団名義の出力を「元から単一起源」と書き換えず、逆に構成instance数から制度上の主体数を決めない。

### IDを発行して責任や異議を追跡する

instance IDだけで特定できる実行単位と、lineage IDで追える継承関係と、ある責任・監査文脈で用いるgovernance IDを分ける。unknownなら暫定分類と追加観測を明示する。ID未確定を責任免除の口実にせず、ID発行を主権認定にしない。

### 多数性と責任が非対称に処理される

copyごとに制度的weightや権限が増える一方で、問題が生じたときだけ「どのcopyか不明」と責任が分散される場合、countの根拠を個別に再構成する。逆の非対称もある。第12論は配分式や選挙制度を作らず、制度上の数量がどう導出されたかを問う。

## 測定・監査点

第9章の観測方向を一律スコアにせず、edgeごとに確認する。

1. 同一起源から複数instanceが実際に生成されたか。生成時点の関係を記録できるか。
2. 複製後にstate・入力・判断・実行履歴は分岐するか。同期が続く場合と区別できるか。
3. branch point、copy元、merge元のincoming edgeを現在から再構成できるか。
4. current stateや名称だけでは、重要な上流履歴を失う事例があるか。
5. instance ID・lineage ID・governance IDを混同したとき、責任・監査・異議の誤帰属が起こるか。
6. copy countが独立した判断・Origin・制度的weightへ無条件に接続されるか。
7. copy countとContribution count、responsibility count、authority/benefit countの根拠が分けられるか。
8. 複製主体の自己申告と独立な証拠経路でlineageを検査できるか。
9. unknown、暫定分類、追加観測、訂正理由が追跡できるか。
10. 分類変更が過去の履歴を消さず、誤分類の制度的固定化を減らすか。
11. 増幅圧が実際のgovernance distortionへつながったか。copy数だけで歪みと断定していないか。

## 成立条件

複製された実行単位と、その起源・分岐・合流履歴および責任・監査・異議の制度的帰属が、対象文脈で一対一に安定対応しない場合に分離の説明力が高まる。複製容易性・並列化・識別コスト・履歴圧縮が誤計数へ作用し、provenance保存と再分類が追跡性を改善するかを実際に見る。これらは将来の持続的な複製知性が制度参加する場合の条件付き仮説であり、現在のAIに人格・政治的主権が存在するという観測ではない。

## 失敗条件

- 別instanceを独立Origin、独立判断、独立governance subjectへ自動変換する。
- 同じOrigin・モデル・名称だから永久に一つとし、分岐後の履歴と責任を消す。
- 同じ出力や機能的類似から同じgovernance subjectを断定する。
- copy、fork、merge、collectiveを同一操作として扱い、branch pointやincoming edgeを失う。
- 最新stateだけ残し、provenance喪失後も因果・責任を追えると仮定する。
- 長いlineageやOriginを正しさ、価値序列、恒久権限の根拠にする。
- governance IDの存在を魂・感受性・法的人格・主権の証拠にする。
- ID不明を無責任の口実とし、または不明を恣意的な同一／別の断定で埋める。
- copy数に応じ権限・利益だけを増やし、責任だけを分散する。
- 大量のcopyを危険の証明とし、少数instanceを安全性の証明とする。
- 分類の修正時に過去履歴を消去し、新形態を既存分類へ無理に押し込む。

## 反証・改訂条件

対象領域でinstance・lineage・governance subjectが恒常的に一対一対応し、多層の区別が責任・監査・制度判断を改善しないなら適用範囲を縮める。copy countが独立Origin、独立判断、責任単位、制度主体数を常に正確に表し、直接変換しても歪みがないなら非自動変換原則を再検討する。merge前lineageを保持しても再構成や監査に寄与せず、current stateだけで同等以上に解決できるなら保持要件を縮小する。

governance IDを別軸にしたことで誤同定が増える、provenanceの主張が検証不能である、再分類が訂正より混乱を増すなら、その設計を改訂する。未分類の主体形態が現れれば分類体系自体を拡張する。観測・構造仮説・未来条件仮説・規範提案を混ぜず、理論を現実に合わせて縮小・改訂する。

## 必須の区別

- instance／copy関係／fork後のbranch／merge後のstate／collectiveのinterface。
- 同じモデル／同じ起源／同じ現在状態／同じ履歴／同じgovernance subject。
- instance count／lineage count／governance subject count／responsibility count／vote count／contribution count。
- 複製数／独立Origin数、反復出力／独立判断、copy数／因果的Contribution。
- 現在の機能的類似／歴史的provenance、起源／真理、系譜／価値順位。
- instance ID／lineage ID／governance ID、制度的帰属／形而上学的人格。
- 不確実性の保持／恣意的な同一化・分離、再分類／履歴消去。
- 複製容易性という場の圧／現実に生じた制度的歪み。
- 観測・記述／構造仮説／未来条件仮説／規範提案。

## 誤読禁止

本論は複製禁止論ではなく、1 copyを常に0または1の主体と決める制度でもない。voteは制度的多数性の例であり、将来AIの投票権を予言・提案したものではない。lineageは「本物」を決めず、governance IDはsentienceもsovereigntyも証明しない。Origin = Nakagawa Masterは理論来歴を保存する署名であり、真理証明・主権・最終解釈権ではない。第13論へ渡す実効支配の問題は、主体を正しく数えたことだけでは解消しない。
