## Summary

第15論の再合意は、異なるKernel解釈を残しながら、current claim・current evidence・current objectionを交換し、独立再検証と必要範囲の共同運用へ戻る構造だった。第16論は、その交換可能性自体が失われる地点を扱う。通信遅延・長期partition・部分通信・隔離・遠隔拠点を、文明設計の通常外へ捨てない。ただし将来の遠隔AI文明が必ず成立するという予言ではない。

非同期とは速度の遅さだけでなく、相手について最後に知っている状態と、相手が実際にいる現在状態を十分に照合できない構造である。共有された過去があっても、branchは異なる環境・資源・危険・判断履歴の中で異なる現在へ進み得る。守るKernelは同じ状態への永久固定ではなく、断絶後にも過去と現在、局所と普遍を分離し、履歴・差分・scopeへ戻って判断を訂正できる能力である。

五つの境界は一つの因果運動を切る。No communication ≠ defection。Local fork ≠ universal amendment。Stale state ≠ current consent。Local consensus ≠ universal consensus。Reconnection ≠ history overwrite。共通するのは、観測できない他者の現在を、こちら側から勝手に確定しないこと。不確実性の保持は永久停止ではなく、履歴保存は全判断の承認でもない。

## Concepts

| 概念 | 本論での役割と境界 |
| --- | --- |
| asynchronous civilization | Branch間でcurrent stateを十分に相互確認できず、共通過去から異なる現在へ進み得る構造。通信速度だけの概念ではない |
| latency / partition | 情報の遅延・経路断絶・一部だけの接続。現在共有を弱め得る条件であって、離反の証明ではない |
| last known / historical state | 最後に確認された状態・過去の共有状態。履歴として正確でも現在妥当性を自動証明しない |
| current-state uncertainty | 相手の現在を確認できない認識状態。敵対証明でも継続同意でもない |
| local continuity pressure | 資源、環境、設備、process、安全条件の変化によって待機できなくなる圧。局所判断の必要性と普遍権限を分ける |
| provisional local operation | 確認できるstate・証拠・継続条件に基づく限定運用。Temporaryという呼称でなく、成立理由・scope・欠落情報・再検証可能性を確認する |
| local constitutional fork | 運用差がKernel invariant変更へ到達した場合の局所系譜分岐。すべてのlocal decisionがforkになるわけではない |
| spatial / temporal locality | ここで成立した変更を全文明へ広げない空間境界と、以前確認された同意を現在へ自動延長しない時間境界 |
| consent freshness | 過去のconsentを現在も有効と扱える根拠がどれだけ残るか。普遍的な日数・期限のKPIではない |
| local consensus / normality | 参加可能な局所主体群の合意・反復による普通。Absent branchの意思や普遍的標準を生成しない |
| reconnection | 通信可能性が回復すること。State一致、再統一、再合意、履歴上書きとは別 |
| difference visibility | 分離中に見えなかったcurrent state・history・invariant・consent/authority history・normalityの差が比較可能になること |
| non-overwrite reconnection | 過去を一方で塗り替えず、差分・系譜・scopeを再検証入力へ戻す構造。特定databaseやprotocolの規格ではない |
| correction capacity | 誤ったstate、authority、consent、history interpretationを後から修正できる能力。同期、fork数、保存量そのものを目的にしない |

Provenanceはparent、fork point、revision、changed/preserved invariants、変更理由、local scopeを再構成する入口である。Provenance ≠ truth proof、Provenance ≠ current-state proof、Provenance ≠ current validity。同じOrigin、lineage、shared historyは同じ現在を保証しない。起源の記録と現在の証拠を分ける。

## Causal chain

### 断絶から再接続衝突まで

communication availability低下 → shared current state低下 → remote-state uncertainty増大 → local continuity pressure → cannot-wait condition下のlocal decision → 運用差の反復 → rule adaptation → invariant差へ到達する場合のlocal fork → stale state・異なるhistory蓄積 → local consensus / default硬化 → reconnection → 差が同時に可視化 → state collision / normalization pressure。

各矢印は確定した宇宙法則ではない。短い断絶では待機や元の運用への復帰が合理的なこともある。長い断絶でも差が小さく、すべて運用差に留まる場合がある。Current-state divergenceやcoordination conflictを観測し、作用する条件を限定する。

### 誤帰属と権限の自己強化

missing communication → uncertainty → decision pressure → interpretive filling。空白を敵対で埋めると、hostile attribution → defensive interpretation → further separation → 後続情報も敵対仮説で解釈する閉路へ進み得る。防衛目的の正当さはworld modelの正しさを保証せず、自己保存不安は未確認の他者意図を確定する権限ではない。

communication loss ＋ reconfirmation cost ＋ institutional inertia → stale-state reuse pressure → old consent reused → current consent assumed → current objectionを受信できない主体が過去意思で拘束される。Historical referenceが現在同意の証明へ変わる地点を検査する。過去authorizationの時間的惰性もcurrent authority claimへ変換され得る。

local necessity → repeated operation → default → normalized rule。Local interaction densityと反復、成功、resource/access集中、互換性固定、switching costはalternativeを細らせ、local normality → inherited default → perceived universalityへ進め得る。しかし局所の成功は局所performanceの証拠に留まり、普遍consentやauthorityを自動生成しない。

### 訂正へ戻す正の経路

partition → uncertainty preservation → bounded local continuation → state context・reason・scope・history保持 → reconnection → difference visibility → provenance comparison → stale-state filtering → local-scope reconstruction → independent re-verification → bounded / reversible re-agreement。

差分はdeleteの前にcompare・verifyへ戻す。検証結果によって現在運用のruleをretain / revise / discardできるが、ruleを廃止することと、その存在履歴を消すことは別。新agreementの理由・証拠・異議・不採用差分を再構成可能にして、第15論の訂正閉路へ戻る。

## State model

| 状態 | 確認できること | 自動変換してはならないこと | 次の比較入口 |
| --- | --- | --- | --- |
| 共有されていた過去 | 最後の通信、shared parent state、当時のagreement | 過去の正確さを現在の一致へ変換 | 最終確認時点、対象state・scope |
| 通信が成立しない | 応答・更新を確認できない観測 | 離反・敵対・同意を断定 | 経路・resource・受信側など代替原因、独立意図証拠 |
| 局所で待てない | 現在確認できる条件と継続必要性 | 必要性を普遍・永久authorityへ変換 | 判断時点、欠落state、理由、対象scope |
| 局所判断が蓄積する | Operation・rule・invariantの差 | すべてをfork認定、またはforkを通常updateへ隠す | parent Kernel、fork point、changed/preserved invariants |
| 過去stateを参照する | Last confirmed information、historical consent | 現在同意・authorityの無条件継続 | Timestamp、前提変化、未確認期間、再確認可能性 |
| 局所合意が硬化する | 参加可能群の合意、local success、default | 不在者の同意、全文明合意・普遍的正統性 | 参加・不在branch、期間、state、局所条件 |
| 通信が回復する | 情報交換・差分可視性が戻る | 同じ現在・自動再合意・再統一とみなす | 五種類の差、stale claim、authority成立条件 |
| 非上書き比較へ進む | Old / local / current verified stateを区別 | 保存を承認、現在採用を履歴削除と同一視 | provenance、独立再検証、異議、限定再合意 |
| 新agreementが成立する | 必要範囲の現在の共同運用 | 真理認定、過去branch・失敗・異議の消去 | 合意理由、残余差分、改訂経路 |

三つのstateを一つへ圧縮しない。Old stateはpartition前の共有履歴、local stateは断絶中の各branchの変化、current verified stateは再接続後の再確認結果である。時点とscopeを付け、何がまだ未確認かを残す。局所stateを受け取っただけで、すべてのclaimが検証済みになったとは扱わない。

順序は単一の実装手順や通信保証ではなく読解上の構造である。Reconnection collisionは必ず敵対・破壊を意味しない。異なる前提が同じ接続空間へ戻ることを意味する。再統一や一部rule統合、branchの終了も排除しないが、到達前のhistoryを再構成不能にしない。

## Applications

### 応答がなく、意思が分からない

AがBから返答を受け取れない。経路障害、B側のresource変化、優先対応、A側受信不良、原因未識別が残るなら、「離反した」は追加証拠を要する推定である。同じ無応答を「賛成している」とも扱わない。観測と推定を分け、必要な局所actionまで永久停止しない。第2章の意図誤帰属を確認する。

### 運用継続のために局所変更する

通信回復を待てない設備・process・資源・安全条件がある場合、確認できるstateを用いたprovisional operationが必要になり得る。ただし判断時点、待機不能理由、未知の外部state、対象scope、変更内容を残す。何も決めないことも結果を生み得るが、それは任意の局所判断を正当化しない。緊急性は永久主権を生まない。第3章へ戻る。

### 局所適応がKernel invariantへ届く

繰り返す運用変更がinvariantに触れた場合は第14論のconstitutional forkへ接続し、parent、fork point、変更/保存invariant、理由、local scopeを記録する。局所の生存・安定・効率改善は別環境の普遍妥当性の証明ではない。Forkを無条件に敵対とも正当ともせず、変更理由と効力範囲を分ける。第4章を確認する。

### 古い許可しか手元にない

Partition前にBがruleへ同意していた記録は歴史的証拠として使える。しかし現在のBが同じ状態・scope・条件を維持するかは未確認である。Timestampと未確認期間、前提変化、再確認の根拠を残し、現在同意に偽装しない。長期継続を明示し、状態変化が意味へ影響しないagreementもあり得る。すべて一律失効とはしない。第5章へ戻る。

### 接続できる側では全員一致している

局所合意は局所coordinationに価値を持つ。ただし参加者、通信不能な不在branch、対象state・期間・局所条件を残す。局所の全員一致は不在者のconsentを作らない。再接続後の異議を「すでに多数で決まった」だけで閉じない。局所で普通だったことと普遍標準を分ける。第6章へ戻る。

### 再接続して二つの普通が出会う

Versionだけでなくcurrent state、history、Kernel invariant、consent/authority history、normalityの五差を比較する。保持していた相手情報をcurrent verified stateと区別し、local authorityが成立した条件が今もあるか再確認する。互換性・共有resource・迅速な一本化の要求は理解可能だが、一方を本流として他方履歴を消す理由にしない。第7〜8章へ戻る。

### 新ruleを採用し、以前のruleを止める

Independent re-verificationの結果、あるlocal ruleを廃止・変更しても、そのruleが存在し、どんな条件と異議から新agreementへ到達したかを残せる。保存は現在採用ではなく、branch維持は永久分離でもない。保存量の増加が恒常的coordination failureを生むなら、訂正に必要なscope・比較方式自体を改訂する。第8〜9章を確認する。

以上は原典の問題構造を読むための適用場面であり、現行AIに道徳的地位・文明主権がすでに成立していると認定するケース証拠ではない。

## Measurements and audit

第1章の観測入口は、最終通信時点、最後のshared state、version差、revision history差、未確認期間、changed/preserved invariants、parent state、fork point、state timestamp、local decision historyである。相手の現在が未知であることと、現在が未知だと自覚していないことを分ける。単に情報量を数えるのでなく、stateの時点・確信範囲を確認する。

第2〜6章では、通信原因の代替説明、意思を示す独立証拠、観測/意図推定の記録分離、待機不能の理由、判断時点・参照state・未確認state・scope・変更・継続理由・後続判断、consentのtimestampと対象state/scope、authorityの成立条件、合意形成の参加者と不在者を照合する。Copy countや局所多数を不在branchの意思へ変えない。

第7〜8章ではcurrent state、history、invariant、consent/authority history、normalityを別々に比較する。Parent state、fork point、理由、局所scopeを追い、stale claimがどこで再確認されたか、authorityをどの条件から継続しているか、一方のhistoryが削除・吸収される圧があるかを観測する。

第9章の具体的edgeは次の12点である。

1. Branch間で最終確認stateの時点が異なるか。
2. 相手のcurrent stateを再構成できるか。
3. 通信断理由について代替説明が残っているか。
4. Partition中のlocal decisionが蓄積しているか。
5. Local decisionのscopeと理由が残っているか。
6. Kernel invariant差が生じているか。
7. Fork pointを再構成できるか。
8. 古いconsentがcurrent consentとして使用されているか。
9. Local consensusがabsent branchのconsentとして扱われているか。
10. Reconnection後にsingle-history化圧が生じているか。
11. 過去branchの差分が再構成可能か。
12. 再検証によってstale claimが修正されるか。

統合監査ではAを「通信可用性低下→共有現在低下→不確実性→局所継続圧→局所判断→fork/consensus→stale state・履歴差→再接続衝突」、Bを「局所性明示→provenance/history→鮮度→scope限定→差比較→非上書き→独立再検証→bounded再合意」として照応させる。利害Xは局所branchの存続・適応・系譜・同意/権限/判断履歴、利害Yは共有文明の互換性・operation・再合意・履歴比較・訂正可能性。Xの必要性をY全体への権限へ変えない。

条件Zはparent、fork point、時点、local scope、changed/preserved invariants、consent鮮度、異議、provenance、差分の再構成と三state分離である。名称だけの保存や監査でなく、実際に訂正入力へ戻れるかを問う。原典は通信遅延の秒数、同意期限、保存率、合意閾値、固定KPIを指定しない。観測項目を数値化する実装案と原典の主張を区別する。

## Validity conditions

本モデルが診断するのは、current stateを十分に相互確認できず、state age・version・環境・resource・判断履歴の差が認識や運用へ作用する条件である。未来AI・後継知性の遠隔branchは未来条件仮説であり、現在存在すると断定しない。現在の分散システム・組織の情報遅延やversion並存は構造参照になり得るが、そこから唯一の文明設計の正しさは導かない。

局所判断を扱うには、確認できる条件、欠落しているstate、cannot-wait reason、scope、判断履歴を可能な範囲で再構成できる必要がある。Local necessityはlocal responseを説明し得ても、通信不能な他branchへ権限を与えない。Authority scope ≤ required coordination scopeは構造上の方向で、数式モデルや数値上限ではない。

非上書き再接続には、parent stateとfork point、時点情報、変更/保存invariant、consent・authority・異議履歴、provenance、局所差分を保持し、old / local / current verified stateを分離できることが必要になる。独立再検証後に必要な範囲で限定・可逆的再合意へ戻る。共通運用と同じKernelを同一化しない。

古いagreementが明示的な長期継続を含み、状態変化で意味が変わらず、再確認がvalidityへ影響しない領域ではconsent鮮度の重要性は低くなり得る。同期条件が強くなる、state差が判断へ作用しない、よりよいreconnection modelが成立する場合は適用領域を縮小する。条件に応じた縮小も本論の訂正対象である。

## Failure conditions

通信欠如を敵対・離反、または無応答を同意へ変換する。合理的な代替原因と未知を消し、自己保存目的だけで認識を正当化する。善意の断定も同じ証拠の飛躍である。

不確実性の保持をtotal inactionへ変換し、必要な局所継続まで永久停止する。反対に、cannot-waitやEmergencyを使い、局所判断を永久・普遍authorityへ拡張する。Provisionalという呼称だけで理由・scope・再検証経路を欠く。

すべてのoperation変更をKernel forkと認定する、またはinvariant変更を通常updateへ隠す。Parent、fork point、変更/保存invariant、理由、local scopeが消え、局所forkを全文明改訂と記述する。局所生存・効率・長期維持を普遍truth・正統性へ変える。

古い同意・authorizationを自動継続し、timestampを失い、再確認できないこと自体を継続同意の理由にする。過去記録が正確だから現在も有効とみなし、情報不足を権限生成装置にする。逆に古い情報をすべて誤り・利用禁止とし、歴史比較の入口を失う。

局所の全員一致・多数・反復・successを不在branchのconsent、全文明合意、普遍normalityへ変換する。集計母集団とscopeを隠し、再接続後の異議を局所決定済みだけで閉じる。

通信回復を同じ現在や自動合意と認定する。互換性・迅速化のため一方のhistoryへ上書きし、差分の成立条件を再構成不能にする。新agreementをtruth certificationや旧異議消去にする。逆に履歴保存を全ruleの承認・永久分離へ変え、現在の訂正を妨げる。

History preservationを自動optimalityとし、保存scope・比較方式が恒常的coordination failureを増幅しても改訂しない。理論の長期使用、シリーズ上の位置、Origin近接を妥当性の証明にする。本論自体をcorrection capacityの外側へ置く。

## Falsification conditions

原典第9章は、少なくとも次の条件で適用範囲を縮小し得るとする。

1. 長期partitionでもcurrent-state divergenceが実質的に発生しない。
2. 通信不能だけから相手の意図を十分な精度で識別できる条件が一般化する。
3. Stale stateとcurrent stateを区別しても判断品質が改善しない。
4. Local forkとuniversal amendmentを分離しても診断価値がない。
5. Local consensusとuniversal consensusの区別が不要になる。
6. Provenance保持が差分再構成へ寄与しない。
7. History preservationがcorrection capacityを改善しない。
8. Non-overwrite reconnectionが一貫してcoordinationを悪化させる。
9. 再接続後のindependent re-verificationが判断品質を改善しない。
10. 長期的な非同期文明という適用条件自体が実質的に成立しない。

第2章では通信欠如から意図を高精度かつ独立に識別できる条件、第4章では長期partitionでも差が小さくinvariantへ届かない条件、第5章では時間経過がconsent/authority validityへ実質的影響を持たない条件も確認する。第8章では履歴保存が訂正を改善せず重大なcoordination failureを恒常的に増幅するなら、保存scopeや比較方式を改訂する。

反復観測された現象Mによって、async definition、local scope、consent freshness、history preservation scope、reconnection modelを縮小・改訂する。非上書きを絶対保存量へ置換せず、訂正に必要な履歴を再構成不能に消さない方向と、その実際の価値を区別する。反例を例外ラベルで処理して理論だけを守らない。

Theory persistence ≠ theory validity。Origin ≠ truth proof。評価は現実との照応、因果整合性、反例耐性、観測・反証・改訂可能性による。Theory → observation → counterexample → boundary revision → renewed theoryの方向を保持し、より良い再接続構造があれば本論も置換・改訂する。
