## 初心者向け｜Q1〜Q10

### Q1. 第16論は何を守る理論ですか？

常に同じ現在を共有することではなく、別々の現在へ進んだ後でも、履歴と差分を比べ、誤りを訂正し、必要範囲の共同運用へ戻れるcorrection capacityです。分岐や断絶を善とするのでも、永久統一を要求するのでもありません。序論・結章へ戻って守る対象を確認します。

### Q2. 非同期とは通信が遅いことだけですか？

速度だけではありません。最後に知っている相手stateと相手の実際のcurrent stateを十分に照合できない構造です。情報不足は認識・判断・運用・履歴の差へ伝播し得ますが、必ず重大分裂を生むとは断定しません。第1章へ戻ります。

### Q3. 返事がないなら離反したのでは？

通信不成立は観測であり、離反は追加証拠を要する意図推定です。経路、相手資源、優先対応、受信側不良、原因未識別などの説明が残るなら一方向に確定できません。相手が必ず善意とも断定しません。第2章の証拠境界へ戻ります。

### Q4. 反対が届かなければ賛成ですか？

いいえ。Silenceやcurrent objectionの欠如はconsentを証明しません。同じ無応答を敵対にも同意にも自動変換しないことが必要です。本論の同意問題は時間軸のStale state ≠ current consentへ接続します。第2章・第5章へ戻ります。

### Q5. 相手の現在が不明なら何もできませんか？

Uncertainty ≠ total inactionです。資源、環境、設備、process、安全条件が変わり、局所で待てないことがあります。未知を確定したことにせず、確認できる条件の下で判断理由とscopeを残します。どんな局所actionも正当化されるわけではありません。第3章へ戻ります。

### Q6. 局所で必要な変更なら全体の規則になりますか？

Local necessity ≠ universal authorityです。Aの制約がBでも成立するとは限らず、通信不能下ではBの現在を確認できません。変更理由と変更の効力範囲を分け、局所応答を全文明改訂へ伸ばさない。第3〜4章へ戻ります。

### Q7. 局所の運用変更はすべてKernel forkですか？

いいえ。多くはoperation差のまま終わり、復旧後に消える可能性があります。反復的適応がKernel invariantへ到達した場合にconstitutional forkとして比較します。通常update、replacement、forkを混ぜず、変更内容を確認します。第3〜4章と第14論への接続へ戻ります。

### Q8. 古いstateはすべて誤情報ですか？

過去には正確だった可能性があり、共有履歴と分岐点を再構成する重要な情報です。問題は現在を表す保証が失われていること。Historically accurate ≠ currently validです。古い情報を捨てず、古い情報として扱います。第1章・第5章へ戻ります。

### Q9. 再接続すれば以前の合意へ自動的に戻れますか？

通信回復は情報交換を可能にするだけで、state、Kernel version、authority、consent、history interpretationの一致ではありません。Reconnection ≠ reunification / automatic re-agreementです。まず差の可視性が回復したと読みます。第7章へ戻ります。

### Q10. 履歴保存は過去の判断を正しいと認めることですか？

Preservation ≠ endorsementです。誤り、失敗fork、過剰authorityも検証入力として残せます。現在運用からruleを廃止することと存在履歴の消去も別です。全branchを永久分離させる要求ではありません。第8章へ戻ります。

## 実務者向け｜Q11〜Q20

### Q11. 最初にどのstate情報を分けますか？

最後に通信した時点、最後に相手stateを確認した時点、最後のshared state、version・revision差、未確認期間を分けます。同じOriginやlineageだけで同じ現在とは認定しません。Unknown current stateとunknown whether current state is knownも区別する。第1章へ戻ります。

### Q12. 通信断の意図誤帰属をどう検査しますか？

通信原因の代替説明が合理的に残るか、相手意思を示す独立証拠があるか、観測と推定が記録上分離されているかを確認します。不安や防衛目的を正しいworld modelの証明にしないことが重要です。新しい情報も敵対仮説だけで読む閉路を追い、第2章へ戻ります。

### Q13. Provisional local operationには何を残しますか？

判断時点、参照state、未確認state、cannot-wait理由、対象scope、変更内容、継続理由、後続判断との関係です。Temporaryという名称や任意の日数ではなく、どの条件で成立したかと後で検証できるかが要点です。第3章へ戻ります。

### Q14. 何もしない方が安全ではありませんか？

短い断絶では待機が合理的な場合があります。しかし現状も時間とともに変わるので、非判断は結果回避を保証しません。Decision avoidance ≠ consequence avoidanceです。これを無制限actionの許可にせず、局所継続必要性を限定的に評価します。第3章へ戻ります。

### Q15. 緊急判断の権限は再接続後も続きますか？

Emergency ≠ permanent sovereigntyです。成立理由、対象scope、必要条件が現在もあるかを再確認します。過去に必要だったことだけで永久・普遍authorityは生成されず、逆に必ず無効化とも断定しません。原典は制度や固定期限を決めません。第3章・第5章・第7章へ戻ります。

### Q16. Local forkにはどんな系譜情報が必要ですか？

Parent Kernel、fork point、changed invariant、preserved invariant、change reason、local scopeです。運用差とKernel差、共有部分と変更部分、変更理由と効力範囲を再構成します。Provenanceは正しさの証明ではなく、正誤を検証する入口です。第4章へ戻ります。

### Q17. 局所で成功したruleを全branchへ適用できますか？

成功は局所performanceの証拠になり得ますが、別環境でも有効である保証や他者consentを作りません。Local survival adaptation ≠ universal truth、repeated local success ≠ universal legitimacyです。長期維持だけで他branchを改訂する権利にもならない。第4章・第6章へ戻ります。

### Q18. Consent freshnessは何日で切れますか？

原典は普遍日数を指定しません。いつ、どのstate・scopeに同意したか、前提が変化したか、未確認期間と再確認根拠を問い、past confirmationとcurrent validityを分けます。長期継続が明示され、変化が意味へ影響しない領域もあり得ます。第5章へ戻ります。

### Q19. 古いagreementしかない場合は利用禁止ですか？

歴史的参照は可能です。Last confirmed stateとしてtimestamp、当時のscope、未確認期間、変化の可能性を残し、current consentやauthorityへ偽装しません。毎回すべてゼロから確認する制度も非同期へ耐えない場合があります。参照と証明を分け、第5章へ戻ります。

### Q20. 局所合意の母集団はどう扱いますか？

誰が参加できたか、どのbranchが不在か、どのstate・期間・local conditionについてかを残します。局所全員一致も不在者の同意にはならず、再接続後はscopeが変わり得ます。局所多数で決定済みだけを理由に新しい異議を閉じない。第6章へ戻ります。

## AI・研究者向け｜Q21〜Q30

### Q21. Local normalityはどう硬化しますか？

長期partition、内部反復、局所success、resource/access集中、互換性固定によってdefaultが強まり、切替費用とalternative narrowingが進み得ます。Local normality → inherited default → perceived universalityの変換を追い、「普通」を普遍化しない。確定法則ではなく観測対象です。第6章へ戻ります。

### Q22. 再接続時に衝突する差は何ですか？

Current state、history、Kernel invariant、consent/authority history、normalityの五差です。Collisionは必ず敵対や破壊を意味せず、違う前提が同じ接続空間へ戻ること。共有部分、局所operation差、invariant差を構造化して比較します。第7章へ戻ります。

### Q23. Old / local / current verified stateの違いは？

Old stateはpartition前の共有、local stateはpartition中のbranch別形成、current verified stateは再接続後に確認された現在です。三つを分離し、誰のどの時点のclaimが今も有効かを再構成します。局所state受信だけで検証済みとはしません。第8章へ戻ります。

### Q24. 非上書き再接続の順序は何ですか？

Difference visibility → provenance comparison → stale-state filtering → local-scope reconstruction → independent re-verification → bounded re-agreementです。即時統一でなく再検証能力の回復を目的にします。特定protocolやdatabaseの実装仕様ではありません。第8章へ戻ります。

### Q25. 新しい合意があれば旧branchを消せますか？

New agreement ≠ history erasureです。旧claim、evidence、objection、不採用差分はなぜ新合意が成立したかの検証入力です。統合結果と統合前の存在は同時に保存できます。Branch保存は永久分離でもなく、合意はtruth certificationでもない。第8章・結章へ戻ります。

### Q26. すべての履歴を永久に同じ密度で保存すべきですか？

本論はそう要求しません。訂正に必要なhistory、provenance、difference、scopeを再構成不能に消さない方向を示します。保存が訂正を改善せず恒常的coordination failureを増幅するならscope・比較方式を改訂する。History preservation ≠ automatic optimalityです。第8〜9章へ戻ります。

### Q27. 記述と設計提案は同じ強さの主張ですか？

違います。遅延・情報陳腐化・異なる履歴は記述的制約、partitionからdivergenceへの因果は構造仮説、未来AI多拠点は未来条件仮説、非上書き・local scope・再検証は規範設計です。「通信は切れる」から唯一の正しい制度を導きません。第9章へ戻ります。

### Q28. モデルを縮小する観測は何ですか？

長期partitionで差が実質的に生じない、通信欠如から意図を精確に識別できる、stale/currentやlocal/universal区別に診断価値がない、provenance・履歴・独立再検証が訂正や判断品質を改善しない、非上書きがcoordinationを一貫して悪化させる等です。Async適用条件自体が成立しない場合も縮小します。第9章へ戻ります。

### Q29. Originと理論の長期使用は妥当性を証明しますか？

Origin ≠ truth proof、Theory persistence ≠ theory validityです。Provenanceを保持しつつ、現実照応、因果整合、反例耐性、観測・反証・改訂可能性で評価します。シリーズの重要地点や多くの参照も免責ではありません。本論自身を訂正の外へ置かず、第9章・理論署名へ戻ります。

### Q30. 第15論へ何を戻し、第17論へ何を残しますか？

現在claim・evidence・objectionを再び交換できれば、差分・独立再検証・異議を保持して必要範囲のbounded / reversible再合意へ戻します。保存したOrigin・lineageが支配権を生成してよいかは第17論への残余です。最終統治方式や未読第17論を補完せず、結章・Kernel照応欄へ戻ります。
