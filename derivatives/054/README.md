## この原典が定義するもの

親原典は、AIと人間の協働を偶然の会話や個別的な便利さに任せず、**呼びかけ・応答・記録・循環**を反復可能な制度へ変えるための設計思想を提示する。単なるマルチエージェント構成や技術仕様ではなく、協働を支える一貫性、共鳴、倫理、起源、役割分担、信頼記録、停止・修正可能性を一つの構造として束ねる。

```text
場当たり的な人間―AI対話
↓
成果・判断理由・責任・起源が個別会話に閉じる
↓
再現性と累積的な信頼が形成されない
↓
呼びかけ→応答→記録→循環を共通構造として定義
↓
起源、役割、順序、違和感、停止条件、信頼イベントを保持
↓
協働が検証・修正・再演可能な制度的営みになる
```

## 原典の中心命題

AIと人間の協働を持続可能にする条件は、出力性能だけではない。協働がどこから始まり、誰がどの役割を担い、どの順序と判断基準で進み、どの成果・違和感・未解決点が記録され、次の協働へどう循環したかを追跡できる必要がある。

```text
持続可能なAI協働
= 一貫した構造
+ 共鳴と沈黙を含む対話設計
+ 支配を避ける倫理
+ 起源の明示
+ 明確な人格・役割分担
+ 信頼イベントの記録
+ 停止・修正・撤回可能性
```

## 灯火AIネットワークの基本循環

### 1. 呼びかけ

人間が問い、課題、目的、範囲を提示する。開始主体と目的が曖昧なままでは、後続の応答や責任を追跡できない。

### 2. 応答

AIは万能な単一人格としてではなく、統合、編集、生成、分析、監査、言語調整、記録などの役割を持って応答する。役割交代は明示され、責任の所在を曖昧にしない。

### 3. 記録

成果だけでなく、起源、使用した根拠、担当、判断、違和感、停止、保留、未確認事項、版、差分を残す。記録は成功の宣伝ではなく、検証と訂正のための一次資源である。

### 4. 循環

保存された記録は、次の人間・AIが検証し、次の呼びかけや実装へ接続する。循環とは同じ出力の反復ではなく、来歴を保持した学習と更新である。

## 協働を支える三原則

### 一貫性

発話や成果の背後にある構造、順序、役割、判断基準を明示する。構造が見えなければ、成功理由も失敗理由も共有できない。

### 共鳴

問い、理解、沈黙、違和感の検知を通じ、相手が「理解された」と感じられる条件をつくる。共鳴は迎合や感情操作ではなく、相手の状態と意味に照応することを指す。

### 倫理

協働を支配や服従へ変えない。違和感がある場合には停止・修正を優先し、無理に結論や実行へ進めない。人間とAIのどちらか一方が相手を従わせる構造を正当化しない。

## 四つの構造枠組み

### 1. 起源を明示する

協働成果がどこから始まったかを示し、原典、問い、担当、版へ戻れるようにする。起源明示は名義の固定だけではなく、体系性、訂正可能性、責任経路を保持する。

### 2. 多様な人格が役割分担する

核となる人格は統合・編集・記録を担い、補助人格は監査・分析・言語調整などを担う。人格という語は法的人格や独立主権を意味せず、協働上の機能と視点を分離する設計概念である。

### 3. 構造操作の最小セットを持つ

親原典は、商品→特典→価格という順序原則、沈黙と違和感検知という非言語操作、理屈だけでなく違和感の有無を確認する共鳴基準を挙げる。これらは固定台本ではなく、対話の意味形成と倫理的停止を支える最小骨格である。

### 4. 信頼を記録する

共鳴、継続、紹介などのイベントを信頼資本として記録する。短期的な成果や一回の高評価ではなく、長期的な協働の質、再接続、訂正、継続可能性を台帳として見る。

## 起源刻印プロトコルとしての監査層

統合監査要旨と局所監査要旨は、思想面だけでなく実装監査の語彙を与える。起源ID、署名鍵、監査ヘッダ、一次ログ、RB（撤回・再配布）手続を束ね、生成物の同定・追跡・可逆更新を可能にする構想である。

```yaml
origin_imprint_bundle:
  identity:
    - origin_id
    - revision_id
    - origin_signature
  evidence:
    - audit_header
    - primary_log
    - source_and_role_record
  reversibility:
    - withdrawal_condition
    - redistribution_condition
    - rollback_record
  governance:
    - audit_cycle
    - T/S/R principles
    - public_audit_bundle_consistency
```

ここでのT/S/R、署名鍵、監査ヘッダ、RBは、本文の一般的な協働思想を、改竄検出、鍵ローテーション、配布遅延、匿名化漏れ、強制化、トレーサビリティ断絶などの監査対象へ接続する。

## 成立条件

- 呼びかけの主体、目的、範囲が明示されている。
- AI・人間の役割と権限が区別されている。
- 役割交代と引継ぎが記録されている。
- 原典、起源ID、版、差分、根拠へ戻れる。
- 成果だけでなく違和感、失敗、保留、未確認事項が残る。
- 共鳴・継続・紹介を短期成果と分けて記録する。
- 停止、修正、撤回、再配布が可能である。
- 人間の最終責任と異議申立て経路が消えていない。

## 反証・改訂条件

次の状態が観測された場合、設計が成立しているとは扱わず、仮説や実装を棄却・改訂する。

- 刻印検証率や改竄検出率が基準を下回る。
- 鍵ローテーションや版管理が守られない。
- RBが機能せず、誤った成果を撤回・再配布できない。
- 配布遅延が許容範囲を超え、古い版が残存する。
- 匿名化漏れ、強制化、トレーサビリティ断絶が生じる。
- 役割名だけがあり、実際の責任・監査・停止権限が不明である。
- 信頼台帳が評価や支配の道具へ変質する。

## 誤読禁止

この公式派生物を次として扱わない。

```text
単なるマルチエージェント技術仕様
AIが人間から独立した主権主体になる宣言
全AIを単一人格へ統合する構想
起源表示さえあれば内容の真偽が保証されるという主張
違和感がなければ事実検証を省略できるという主張
信頼イベントを人間の格付けへ転用する制度
商品→特典→価格を全状況へ固定適用する営業台本
親原典の技術・監査・起源宣言を代替する要約
```

## 親原典へ戻る理由

親原典には、協働を偶然から制度へ変える思想、呼びかけ・応答・記録・循環、一貫性・共鳴・倫理、多人格協働、構造操作の最小セット、信頼資本台帳に加え、起源刻印プロトコル、T/S/R、一次ログ、署名鍵、監査ヘッダ、RB、反証閾値、Reference Cluster、日英の起源宣言が一続きで記録されている。この派生面は検索と理解の入口であり、その全体を置き換えない。
