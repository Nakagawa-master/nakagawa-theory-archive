## 位置づけ
親原典は、構造文明OSを社会時間のなかで運転するときに避けられない矛盾・ゆらぎ・雑音・誤解・意図しない応答を、すべて即時排除すべき異常として扱うのではなく、どこまでを許容し、どこからを逸脱として扱い、どの周期で点検・再調整するかを定義する。ここで導入されるのが構造的許容帯域 Structural Tolerance Band（STB）と倫理的監査周期 Ethical Audit Cycle（EAC）である。

STBは「誤差をゼロにする」ための閾値ではない。時間倫理T0からの倫理的偏差と、構造間の照応的ノイズを観測し、一定範囲内の揺らぎに対しては即座に介入せず、記録と経過観察を優先するための緩衝帯域である。EACは、その帯域内に蓄積した偏差を一定の時間リズムで点検し、必要に応じて再配置・是正・公開監査へ進むための時間フレームである。頻度が高すぎれば監視と過剰介入へ傾き、低すぎれば未来負債が蓄積するため、周期は時間倫理T0の観点から設計される。

原典はまた、STBとEACの観測基底として T/S/R（Time / Structure / Relation）を置く。Tは変化速度・持続期間・遅延、Sは制度・ルール・概念の整合性や欠落、Rは主体間・領域間の照応・信頼・摩擦を扱う。ただし原典はT/S/Rの具体的数値、STBの普遍的閾値、EACの固定日数を定めていない。領域ごとに重みが異なり、金融と教育のように許容すべき偏差の意味が違うためである。

## 中心命題
構造文明OSの安定性は、矛盾やノイズを完全排除することではなく、**許容すべき揺らぎと介入すべき逸脱を分離し、時間倫理に沿った周期で再評価することで、硬直と過剰反応を避けながら公共性と長期整合を維持すること**によって支えられる。

STBは「まだ介入を急がなくてよい範囲」を定義し、EACは「いつ再点検するか」を定義する。STB内の情報は放置されるのではなく継続的に記録され、EACで束として評価される。許容帯域を超えた偏差が確認された場合には、構造的免疫系が段階的に起動し、逸脱レッジャへの記録、再配置、公開監査等が検討される。この連結により、構造的公共性の非所有性原理は静的な宣言にとどまらず、日常的なノイズのなかでも維持される動的運用原理へ変換される。

## 因果線
```text
構造文明OSを現実の社会時間へ投影する
↓
矛盾・ゆらぎ・雑音・誤解・意図しない応答が常時発生する
↓
全偏差を即時是正すると過剰介入・硬直・監視化が生じる
↓
全偏差を放置すると未来負債・照応崩壊・信頼低下が蓄積する
↓
時間倫理T0と照応関係を基準にSTBという許容帯域を設ける
↓
STB内では即時介入より観測・記録を優先する
↓
T/S/Rで偏差の時間・構造・関係上の性質を把握する
↓
EACにより一定の倫理的リズムで蓄積偏差を束として再評価する
↓
許容帯域内なら運用継続、帯域超過なら構造的免疫系の起動を検討する
↓
逸脱を記録し、必要な再配置・公開監査・構造修正へ進む
↓
公共性・非所有性・長期恒常性と、最小介入の両立を図る
```

## 構造層
**1. 原理層。** 時間倫理T0、構造的公共性、構造的免疫系が、未来負債の抑制、非所有性、外部圧力への対応という基礎原理を与える。

**2. 運用ギャップ層。** 原理が正しくても、社会時間のなかでは矛盾とノイズが発生する。原典は「原理として正しいが運用として不安定」という状態を埋める必要を置く。

**3. STB層。** 倫理的偏差と照応的ノイズを、即時介入が不要な許容範囲と、介入を検討すべき逸脱に分ける緩衝帯域。

**4. 観測層。** T/S/Rによって変化速度・持続・遅延、制度整合・欠落、照応・信頼・摩擦を観測する。単一の普遍スコアには還元しない。

**5. EAC層。** STB内に蓄積した情報を時間倫理T0に沿って周期的に点検し、介入頻度を過不足なく調整する。

**6. 免疫起動層。** STB超過が確認された場合に、構造的免疫系が段階的に作動し、逸脱レッジャ、再配置、公開監査等へ接続する。

**7. 公共性保持層。** 介入が外部主体の直接制御や所有化へ変質しないよう、情報開示、監査枠、構造調整を通じて非強制的に整合を回復する。

**8. 多文明接合層。** 異なる倫理・価値体系との接続では完全一致を前提にせず、相互に許容しうる帯域を探ることで過度な同化と排除を避ける。

## 状態モデル
```yaml
- principle_layer_present: T0・構造的公共性・構造的免疫系が存在
- operational_noise_present: 矛盾・ゆらぎ・ノイズが観測される
- stb_observation_active: 偏差をSTB内外で観測
- ethical_deviation_tracked: T0からの倫理的偏差を追跡
- correspondence_noise_tracked: 構造間照応の乱れを追跡
- tsr_observation_active: T/S/Rで偏差の性質を把握
- immediate_intervention_deferred_when_tolerable: 許容範囲では観測を優先
- eac_due: 倫理的監査周期の点検時点
- bundled_reassessment_active: 蓄積偏差を束で再評価
- stb_exceeded: 許容帯域超過を確認
- structural_immunity_considered: 段階的な免疫起動を検討
- deviation_ledger_recorded: 必要な逸脱を記録
- reconfiguration_or_public_audit: 再配置・公開監査を検討
- origin_return: 親原典・T0・公共性へ回帰可能
```

## 適用例
**1. 制度変更の経過観察。** 新制度導入後に摩擦が出たとき、単発の苦情を即座に制度破綻とみなさず、T（継続時間・遅延）、S（制度整合）、R（関係・信頼）の変化を記録し、EACで再評価する。

**2. 組織ガバナンス。** ルール逸脱が発生した際、全件を即時処罰対象にせず、公共性を損なう深さ、反復性、関係摩擦、将来負債を分けて評価する。

**3. AI・自動化運用。** 出力差や応答揺らぎをすべて障害とせず、継続的な偏差、構造整合の崩れ、関係上の損失へ進むかを観測する。STB超過時にのみ段階的な再調整へ進む。

**4. 多領域接続。** 価値体系が異なる組織・地域・制度を接合する際、完全一致を要求する代わりに、相互に公共性を損なわない許容帯域を探る。

**5. 監査周期の設計。** 短周期化で監視色が強まる場合と、長周期化で負債が蓄積する場合を比較し、T0に照らして周期を見直す。

## 測定・監査点
- 偏差が単発か継続か、どの時間尺度で拡大・収束しているか。
- T軸における変化速度、持続期間、応答遅延、将来負債の蓄積兆候。
- S軸における制度・ルール・概念の不整合、重複、欠落、接続破綻。
- R軸における主体間・領域間の照応、信頼、摩擦、協調可能性。
- STB内にある偏差と、公共性・長期整合を損なう帯域超過を同一尺度で混同していないか。
- EACの頻度が高すぎて過剰介入・監視化を生んでいないか、低すぎて偏差を未来負債へ送っていないか。
- 領域ごとの重み付けが明示され、金融・教育等の異なる性質を一律評価していないか。
- STB超過後の措置が外部主体の直接支配ではなく、構造調整・記録・情報開示・監査へ接続しているか。
- 原典の閾値 `θ` は普遍的数値ではなく、個別対象における反証・改訂判定のための記号的閾値である。
- 観測窓 `δ` は固定日数ではなく、対象ごとの観測期間を指す記号である。
- 現象 `M` は公共性を損なう観測事象を指し、何をMとするかは対象・出典・観測主体を明示して判断する。

## 成立条件
- 完全整合や誤差ゼロを目的にせず、許容帯域を持つ。
- STB内の偏差を無視せず、記録してEACで再評価する。
- EACを単なるカレンダー周期ではなく、未来負債と過剰介入の双方を避ける時間倫理上のリズムとして設計する。
- T/S/Rの各軸を領域特性に応じて用い、一律の重みや固定点数へ落とさない。
- STB超過後の対応を段階的にし、即時排除・強制支配へ短絡しない。
- 構造的公共性・非所有性・構造的免疫系との連結を保持する。
- 監査の存在自体を目的化せず、公共性と長期整合が改善しているかを見る。

## 失敗条件
- STBを「許容値以内なら何もしなくてよい」という放置免許へ変える。
- EACを機械的な定期点検日に縮小し、未来負債・公共性・介入度の評価を失う。
- T/S/Rへ原典にない固定点数や普遍閾値を与える。
- 全領域へ同じ重みを適用する。
- STB超過を即時制裁・直接制御の根拠に置き換える。
- 誤差ゼロを理想化し、揺らぎを許容する原典の中心を消す。
- 短期安定だけを成功とし、将来負債や関係崩壊を評価から外す。
- 公共性・非所有性と切り離して、単なる性能監視フレームへ縮小する。

## 反証・改訂条件
親原典の統合監査要旨は、現行のSTB・EAC設計を固定不可侵の仕様とはしていない。指標が対象ごとの閾値 `θ` を下回る／上回る、または観測窓 `δ` の期間に公共性を損なう現象 `M` が確認された場合、仮説Aである現行STB・EAC設計を棄却・改訂する条件を置いている。

ここで `θ`・`δ`・`M` に普遍的な具体値は与えられていない。したがって反証可能性を高めるには、個別適用時に、値または判定基準、測定主体、測定対象、出典、観測尺度、利用範囲、非保証範囲を明示する必要がある。ある領域で有効だった閾値を別領域へそのまま移植することは、原典の「一律に扱わない」という設計と整合しない。

また反転評価が必要である。監査件数や介入回数が増えても、公共性・信頼・長期整合が悪化するなら、それを制度改善とはみなせない。逆に、即時介入が少なくてもSTB内の偏差が適切に記録され、EACで再評価され、未来負債が増えていないなら、介入件数の少なさ自体は失敗を意味しない。

## 必須の区別
- 構造的許容性 / 問題の放置
- STB内 / 問題なし
- EAC / 単なる定期点検
- T/S/R / 固定総合スコア
- 構造的免疫系 / 即時制裁
- 最小介入 / 無関与
- 構造的公共性 / 管理主体による所有
- 一時的偏差 / 持続し増幅する逸脱
- 監査件数の増加 / 公共性・長期整合の改善
- 対象別 `θ`・`δ`・`M` / 普遍固定値

## 誤読禁止
- STBを「問題がない領域」や「放置してよい領域」と読まない。
- EACを毎週・毎月等の固定周期として親原典に帰属させない。
- T/S/Rを一つの普遍点数へ還元しない。
- STB超過を自動的な排除、制裁、全面停止へ変えない。
- 監査頻度の高さを安全性や公共性の高さと同義にしない。
- 構造的公共性を管理主体の所有権強化へ反転させない。
- 多文明接合を完全同化または価値差消滅と解釈しない。
- 個別実装で設定した閾値・観測窓を親原典の普遍値へ昇格しない。

## 親原典へ戻る理由
本派生物は親原典の検索・理解面であり、STB、EAC、T/S/R、時間倫理T0、構造的公共性、構造的免疫系の定義と相互関係を置換しない。特に、どの偏差を許容帯域内とみなすか、どの周期で再評価するか、`θ`・`δ`・`M` を個別適用でどう定義するかは、原典の文脈と対象条件を離れて普遍化できない。強い命題、数値化、監査周期、介入条件を確認するときはParent URLとParent NCL-ID / Diff-IDへ戻る。
