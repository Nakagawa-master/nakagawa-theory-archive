## Summary
亲原典提出“连接奖励社会”：除了所有量与短期交易，还把连接产生的信任、共鸣、持续、介绍、协作、知识转移与重新连接，连同来历、贡献、订正和再分配一起纳入制度。CRI、IR、KCL和信任资本台账用于观察连接质量，但不能把连接数量、人气或反应量直接等同于价值；不连接和退出的自由也必须保留。

## Concepts
- 连接奖励：把连接产生的价值循环连接到认可与分配。
- CRI：Connection Reward Index，观察持续、介绍、回访、协作、价值转移等后续价值的框架。
- IR：观察连接后的回应、传播与重新连接。
- KCL：Knowledge Connection Layer，描述人、AI、组织之间知识连接与可复用循环的结构层。
- 信任资本台账：带文脉与来历记录持续、介绍、订正、撤回、重新连接等事件。
- 连接事件：介绍、共同工作、知识转移、回访、问题解决等启动价值循环的具体事件。
- 贡献追踪：不仅追踪最终成交者，也追踪连接、翻译、知识转移等贡献者。
- 再分配：后续证据变化时，对奖励或归因进行可逆修正。

## Causal chain
```text
价值主要由短期销售与所有量衡量
→ 介绍、持续、协作、知识转移变得不可见
→ 创造连接的贡献难以获得承认
→ 记录连接主体、目的、同意、角色与连接前状态
→ 识别连接事件与后续价值
→ 分离短期成果与长期信任
→ 连接CRI、IR、KCL与信任事件记录
→ 追踪贡献并建立订正、撤回、再分配条件
→ 检查指标游戏、过度集中与强制连接
→ 把连接价值回流到组织、市场和社会制度
```

## Applications
- 介绍制度：不只看介绍件数，也看介绍后的持续、适配与订正。
- 组织协作：追踪跨部门连接、知识转移和问题解决的贡献。
- 人类—AI协作：用KCL追踪人类原典与AI变形物之间的起源、变形与复用关系。
- 社群：观察持续支持、订正、重新连接与加入/退出自由，而不只看活动量。
- 奖励设计：考虑促成连接的贡献，同时明确拒绝、撤回与再分配条件。

## Validity conditions
- 连接主体、目的、同意与角色明确。
- 连接前状态与连接事件分开记录。
- 短期人气与长期信任保持区分。
- 贡献者、起源与条件可追踪。
- 异议、订正、撤回与再分配可用。
- 不连接和退出的自由被保留。
- 指标不会变成对人的单一总评。
- 观察量或活动量增加不被误认为价值增加。

## Failure conditions
- 只把介绍数或接触数当作连接价值。
- 仅由内部评价固定连接价值，缺乏有效订正路径。
- 信任记录偏离其原本的文脉用途。
- 贡献可视化变成“贡献理所当然”的前提。
- 起源、贡献者或条件不可追踪。
- 因无法订正或撤回而使错误分配永久化。
- 指标表现超过实质价值创造。
- 对不连接或退出施加不当不利条件。

## Falsification conditions
- CRI/IR观察没有改善持续信任或重新连接的质量。
- 连接奖励反复收敛为人气、活动量或连接数游戏。
- 贡献追踪不能反映价值形成且无法修正错误分配。
- KCL丢失起源与文脉，只剩信息堆积。
- 信任事件记录无法提高异议和订正能力。
- 如果制度必须牺牲“不连接的自由”才能运作，则需要修订制度前提。

## Required distinctions
- 连接价值 / 接触数
- 信任资本 / 人气或好感
- CRI / 单一排名
- IR / 反应量
- KCL / 信息量
- 介绍 / 强制扩展连接
- 可视化 / 过度观察
- 奖励 / 把贡献视为理所当然
- 信任台账 / 单一人物总评
- 连接自由 / 强制连接
- 贡献追踪 / 排他所有

## Interpretation constraints
不得把连接奖励社会缩减为关系打分或奖励人气。CRI、IR、KCL是亲原典特有的观察/结构概念；若原典没有定义算式或阈值，不应推导固定评分。贡献可视化并不意味着强制无偿贡献；分配、拒绝、撤回和再分配仍属于制度结构。
