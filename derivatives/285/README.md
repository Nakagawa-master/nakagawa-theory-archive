## 位置づけ
本派生物は、営業を「商品を売り込み相手を説得する行為」から、相手がまだ言語化できていない課題・欲求・未来像を因果として発見し、必要な価値と結び直す構造設計へ再定義する。

## 中心命題
営業の成果は話術や圧力ではなく、相手の未定義の因果を発見し、相手自身が理解可能な形へ翻訳し、「決めさせる」のではなく「決まる構造」を整えることで生まれる。

## 因果線
```text
相手の断片的な要望・不安
→ 問いによって背景を観測
→ 未定義の課題・欲求・因果を抽出
→ 現在地と未来像を結ぶ
→ 商品・支援を価値経路として位置づける
→ 相手自身が構造を理解
→ 必然性が形成
→ 外圧ではなく内的理解から意思決定
→ 継続可能な価値交換へ
```

## 主要構造
### 1. 営業＝構造翻訳
相手の言葉をそのまま受け取るだけでなく、その背後にある因果、阻害要因、未充足状態を整理する。

### 2. 問い
問いは情報収集だけでなく、相手自身がまだ見えていない構造を一緒に発見する装置になる。

### 3. 決まる構造
意思決定を操作せず、選択の理由・条件・未来像が相手自身の中でつながる状態を作る。

### 4. 価値交換
相手の欠乏を誠実に満たす価値と、その対価が対応する。売上だけを成功指標にしない。

## 状態モデル
```yaml
- surface_request_observed
- latent_need_hypothesized
- question_opened
- causal_context_clarified
- present_state_mapped
- desired_future_mapped
- value_path_connected
- pressure_reduced
- customer_understanding_formed
- decision_emerged
- value_exchange_confirmed
```

## 適用例
- 「価格を下げてほしい」を単純値引きではなく、予算制約・稟議・不確実性・価値理解のどこが障害か分ける。
- 「検討します」を拒否と決めつけず、判断材料・社内説明・リスク・優先順位の不足を問い直す。
- 商品説明より先に、相手が何を満たしたいかを構造化する。

## 測定・監査点
- 顧客自身の言葉が提案に残っているか。
- 課題仮説を確認せず断定していないか。
- 圧力表現が増えていないか。
- 意思決定理由を顧客自身が説明できるか。
- 契約後に価値が実際に満たされたか。

## 成立条件
問い、観測、仮説確認、因果翻訳、価値接続、顧客の自己決定、契約後の検証がつながっていること。

## 失敗条件
話術中心、商品説明先行、恐怖や期限での圧迫、顧客の言葉の無視、売上だけで成功判定すること。

## 反証・改訂条件
構造翻訳型の営業が顧客理解・継続価値・意思決定品質を改善せず、従来型より摩擦や誤契約が増える場合、手順と仮説を改訂する。

## 必須の区別
- 営業 ≠ 説得
- 問い ≠ 尋問
- 構造翻訳 ≠ 課題の勝手な創作
- 決まる構造 ≠ 巧妙な誘導
- 価値交換 ≠ 無償奉仕
