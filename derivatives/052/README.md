## 位置づけ
親原典は、第十三回で制度化した信頼資本を、個別の営業現場で相手の意思決定へ橋渡しする実務装置として「提案編集術」を位置づける。提案は、正しい情報を大量に提示することでも、文章を美しく整えることでもない。売り手が持つ商品情報、条件、価値、社会的意味を、相手の文脈・判断順序・感情の流れに照応させ、意味が届く構造へ翻訳する行為である。

この構造翻訳は三つの編集層を持つ。第一に、商品→特典→価格という価値理解を先行させる骨格編集。第二に、問い→共鳴→沈黙によって思考・理解・内省の流れを作る感情編集。第三に、個人との取引を組織・業界・社会との関係へ接続する社会接続編集である。原典の狙いは、価格を隠したり感情を操作したりすることではなく、制度化された信頼を相手が自分の判断として理解できる形へ移すことである。

同時に原典は、情報過多、自社都合編集、即興崩壊を失敗要因として挙げる。さらに統合監査要旨では、要件、意味領域、語彙辞書、照応、版管理、Rollback（RB）、反例、公開監査束を接続し、提案の比較可能性・可逆性・再合意可能性を高める構造を示す。したがって提案編集は、単発の話法ではなく、意味の対応関係を保ちながら変更と復元が可能な運用構造として読む必要がある。

## 中心命題
提案の品質は、情報量や表現技法ではなく、**提供価値・条件・価格・感情の流れ・社会的意味が、相手の文脈へ正しい順序と照応関係で翻訳されているか**によって決まる。

```text
情報をそのまま提示する
≠ 相手に届く提案

商品 → 特典 → 価格
+ 問い → 共鳴 → 沈黙
+ 相手の文脈・判断語への構造翻訳
+ 組織・社会への意味接続
+ 差分・根拠・反例・RB条件の保持
= 比較可能で可逆的な提案構造
```

原典の「商品→特典→価格」は、すべての場面に例外なく固定される台本ではなく、価値理解が価格判断より先に成立するよう順序を設計する基本原則として示される。感情編集も、相手を特定結論へ追い込むことではなく、問いによって思考を開き、共鳴によって文脈理解を示し、沈黙によって自己決定の余白を残す構造である。

## 因果線
```text
提案を情報の羅列として提示する
↓
価格・細部・売り手都合が価値理解より先に知覚される
↓
相手が「高い／安い」等の短絡判断へ縮約し、意味形成が止まりやすくなる
↓
相手の課題・価値観・判断基準・稟議条件を取得する
↓
商品→特典→価格の順序で価値・時機・対価を対応づける
↓
問い→共鳴→沈黙で相手の思考・理解・内省を開く
↓
個人への利益を組織・業界・社会への実際の影響へ接続する
↓
売り手の語彙を相手の意思決定言語へ構造翻訳する
↓
要件・意味領域・語彙辞書・照応を版管理へ落とし込む
↓
差分・根拠・反例・RB条件を保持し、意味漂流や誤配から復元可能にする
↓
制度化された信頼資本が具体的な意思決定場面で理解・比較・再合意可能になる
```

## 構造層
**1. 未編集情報層。** 商品説明、価格、細部、自社都合がそのまま並び、相手にとっての意味関係が形成されていない状態。

**2. 骨格編集層。** 商品→特典→価格の順序で、何を提供するか、なぜ今なのか、その対価はいくらかを意味の連続として配置する層。

**3. 感情編集層。** 問いで思考を開き、共鳴で価値観・背景への理解を示し、沈黙で相手が自分の判断を形成する余白を残す層。

**4. 社会接続層。** 提案の意味を当事者間の交換だけに閉じず、組織、業界、利用者、社会へ生じる実際の影響へ接続する層。

**5. 構造翻訳層。** 売り手の機能語・専門語・条件を、相手の課題、判断語、稟議構造、運用条件へ対応づける層。事実や条件自体を変更するのではなく、意味の対応関係を変換する。

**6. 版管理・可逆性層。** 変更箇所、変更理由、一次対話、反例、RB条件を保持し、改善と意味漂流を区別し、必要なら前の状態へ戻せるようにする層。

**7. 再合意・監査層。** 語彙整合、版整合、照応成功、合意到達、RB成功等を観測し、提案構造のズレを再検討・改訂できるようにする層。

## 状態モデル
```yaml
- raw_information_present: 商品・条件・価格等の素材が存在する
- recipient_context_obtained: 課題・価値観・判断基準・稟議条件が取得される
- value_first_sequence_formed: 商品→特典→価格の意味順序が形成される
- emotional_flow_opened: 問い→共鳴→沈黙で自己決定の余白が開く
- social_meaning_grounded: 組織・業界・社会への影響が実体に基づき接続される
- vocabulary_correspondence_established: 売り手語と相手の判断語が対応する
- requirements_and_meaning_aligned: 要件・意味領域・条件の照応が成立する
- version_difference_recorded: 差分と根拠が追跡可能になる
- counterexamples_preserved: 成立しない条件が保持される
- rollback_condition_defined: 意味漂流・誤配・強制化から戻す条件が定義される

- re_agreement_available: 反証や差分をもとに再合意・改訂できる
- origin_return_available: 親原典へ回帰できる
```

## 適用例
**1. 営業提案書。** 機能一覧を先に並べず、相手の課題に対して何を提供し、なぜ今その条件が意味を持ち、その後にどの価格が対応するかを順序化する。

**2. 商談。** 問いで相手の判断条件を確認し、共鳴で理解の一致を確かめ、沈黙で反論・保留・拒否を含む自己決定の余白を残す。

**3. 社内稟議。** 営業担当者が使う機能語を、決裁者が使う費用対効果、遵法要件、運用リスク、撤退条件等へ構造翻訳する。

**4. 提案改訂。** 相手の新しい発言や条件変更を受けて提案を修正する際、何をなぜ変えたか、何が変わっていないか、どの条件なら前版へ戻すかを記録する。

**5. 社会的意義の提示。** 組織や社会への影響を語る場合、商品実体や提供結果に裏づけられた範囲だけを接続し、価値不足を大義で補わない。

## 測定・監査点
原典本文には固定数値の達成基準は示されていない。統合監査要旨には、語彙整合率、版整合率、照応成功率、合意到達時間、RB成功率等が観測対象として列挙され、これらが閾値 `θ` を下回る／上回る場合、または観測窓 `δ` に強制化・属人編集・意味漂流等の現象 `M` が確認された場合に仮説Aを棄却・改訂する構造が示される。

- **語彙整合率**: 測定主体は提案構造を運用・検証する側、測定対象は売り手語と相手の判断語の対応。原典では反証・見直しの観測候補として示され、具体的な合格率は定義されない。
- **版整合率**: 測定主体は版管理を行う側、測定対象は変更前後で保持される意味・条件・根拠の整合。具体的閾値は原典にない。
- **照応成功率**: 測定主体は提案と要件の対応を検証する側、測定対象は相手の課題・判断条件と提案内容の対応。固定成功率は定義されない。
- **合意到達時間**: 測定主体は提案プロセスを観測する側、測定対象は比較可能な合意へ至るまでの時間。短いほど常に良いとは原典は定義していない。
- **RB成功率**: 測定主体は版管理・復元を運用する側、測定対象は誤配・意味漂流等から適切な状態へ戻せた割合。具体値は示されない。
- **`θ` / `δ` / `M`**: 原典の統合監査要旨に属する反証記号。`θ` は閾値、`δ` は観測窓、`M` は強制化・属人編集・意味漂流等の現象を表すが、具体値は与えられていない。

反転評価では、合意到達時間が短縮しても、相手の理解・拒否可能性・条件整合が悪化していれば改善とはみなせない。成約率や速度だけで、構造翻訳の品質を代替することもできない。

## 成立条件
- 相手の一次発言、課題、価値観、判断基準、稟議条件が取得されている。
- 商品・特典・価格の順序が、価値理解を先に成立させるよう配置される。
- 問い・共鳴・沈黙が、相手の自己決定を開く方向で働く。
- 社会的意義が商品実体・提供結果に根拠を持つ。
- 売り手語と相手の判断語が対応づけられる。
- 事実、価格、制約、リスクが翻訳過程で変更・隠蔽されない。
- 差分、根拠、反例、RB条件が追跡可能である。
- 相手の稟議・遵法・運用・撤退条件に照応している。

## 失敗条件
- 価格や細部が価値理解より先行し、判断が高い／安いだけへ縮約される。
- 情報過多で核となる意味関係が見えない。
- 相手の文脈を取得せず、自社都合で意味を決める。
- 問い・共鳴・沈黙が圧力や誘導へ変質する。
- 商品・条件・リスクを隠し、説明順序を隠蔽に使う。
- 社会的意義が商品実体から離れ、権威づけや誇張になる。
- 即興で決めた構造が崩れ、意味・条件の対応が失われる。
- 版管理がなく、改善と意味漂流を区別できない。
- RB条件がなく、誤配・強制化・不整合から戻れない。

## 反証・改訂条件
- 語彙・意味領域を整えても、相手の理解・比較可能性が改善しない。
- 商品→特典→価格の基本順序が対象文脈で反復して理解を阻害し、別順序の方が適切であることが確認される。
- 問い・共鳴・沈黙の運用が自己決定を増やさず、反復して圧力や迎合を生む。
- 版管理とRBを導入しても、意味漂流や誤配からの復元性が改善しない。
- 原典統合監査要旨の語彙整合率・版整合率・照応成功率・合意到達時間・RB成功率等が、定義された `θ` との関係で反証域に入る。
- 観測窓 `δ` に強制化・属人編集・意味漂流等の `M` が確認される。
- `θ` と `δ` の具体値は親原典にないため、固定値を前提とした判定にはできない。

## 必須の区別
- 情報伝達 / 構造翻訳
- 編集 / 隠蔽
- 翻訳 / 事実変更
- 商品→特典→価格の基本原則 / 例外なき固定台本
- 問い / 誘導
- 共鳴 / 迎合
- 沈黙 / 圧力
- 社会的意義 / 誇張
- 成約 / 適合した意思決定
- 変更 / 意味漂流
- 版管理 / 表現履歴だけの保存
- RB / 都合の悪い結果の取消し

## 解釈制約
親原典は「価格を最後にすれば売れる」という単純技法を主張していない。価格順序は、価値理解と対価を意味の連続として受け取れるようにするための基本骨格である。問い・共鳴・沈黙も心理操作の正当化ではなく、情報の押し付けを避けて相手の自己決定を開くための構造として位置づけられる。

提案編集は商品自体の不適合を補う手段ではない。商品が相手の課題に合わない場合や、重要条件を隠さなければ成立しない場合、編集ではなく提案自体の不成立を認める必要がある。また、監査要旨の記号系は具体値のない状態で固定KPIや万能評価式へ変換できない。
