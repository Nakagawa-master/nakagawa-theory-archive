## この原典が定義するもの

本稿は、営業提案を情報の羅列や表現上の言い換えではなく、制度として蓄積された信頼を、相手の文脈・判断順序・感情の流れ・社会的意味へ接続する「構造翻訳」として定義する原典である。

```text
商品情報をそのまま並べる
↓
価格や細部が先に知覚される
↓
価値の意味づけが形成される前に拒否反応が起きる
↓
相手の課題・判断基準・稟議構造を確認する
↓
商品 → 特典 → 価格の順序へ骨格を編集する
↓
問い・共鳴・沈黙で感情と内省の流れを設計する
↓
個人利益を組織・業界・社会的意味へ接続する
↓
提案が相手の意思決定言語へ翻訳される
↓
比較可能で可逆的な合意形成が進む
```

## 中心命題

```text
提案編集 ≠ 美文への修正
提案編集 ≠ 説得力の演出
提案編集 ≠ 情報量の増加

提案編集 = 提供価値、相手の文脈、感情の流れ、社会的意味を
順序と照応を保ったまま意思決定可能な構造へ翻訳すること
```

## 三つの編集層

### 1. 骨格編集──順序の設計

基本順序は「商品 → 特典 → 価格」である。まず何を提供するのかを明確にし、次に今選ぶ意味や条件を示し、最後に対価を置く。価格を先に出すと、価値との関係が形成される前に高い・安いだけの短絡判断へ縮約される。

### 2. 感情編集──問い・共鳴・沈黙

問いは思考を開き、共鳴は相手の価値観と背景が理解されていることを示し、沈黙は相手が自ら考え決定する余白を残す。これらは心理操作ではなく、相手の自己決定を壊さずに意味を形成する条件である。

### 3. 社会接続編集──提案を閉じない

提案を売り手と買い手だけの交換へ閉じず、組織、業界、利用者、社会へどのような影響を生むかを接続する。ただし社会的意義は商品実体や成果に根拠が必要であり、壮大な物語で価値不足を隠してはならない。

## 構造翻訳としての運用

親原典の監査要旨まで含めると、提案編集は次の運用対象を持つ。

- 要件: 相手が解決したいこと、避けたいこと、決裁条件。
- 意味領域: 商品機能が相手の文脈で何を意味するか。
- 語彙辞書: 売り手の専門語と相手の判断語の対応。
- 照応: 提案内容が相手の課題、価値観、制度条件に対応しているか。
- 版管理: 何を、なぜ、どの根拠で変更したか。
- 反例: 提案が成立しない条件や対象。
- Rollback条件: 誤配、意味漂流、強制化が起きたときに戻す基準。
- 監査束: 差分、根拠、一次対話、反証、再合意条件をまとめた記録。

## 未編集と編集後の差

### 未編集

- 価格が冒頭に来る。
- 機能説明が過剰で相手にとっての意味が不明。
- 売り手の都合で即決を迫る。
- 相手の稟議、利用環境、撤退条件が反映されない。

### 編集後

- 課題に対する提供価値を先に示す。
- 今選ぶ条件や特典を文脈に合わせて説明する。
- 価格を価値と条件の後に配置する。
- 問いと沈黙により相手自身の判断を残す。
- 組織・社会への影響と運用条件を明示する。
- 差分と根拠が記録され、必要なら戻せる。

## 成立条件

- 相手の一次発言、課題、判断基準が取得されている。
- 商品・特典・価格の順序が、価値理解を先行させる形になっている。
- 問い・共鳴・沈黙が自己決定を支え、圧力へ変質していない。
- 社会的意義が商品実体と提供結果に裏づけられている。
- 削除した情報と残した情報の理由が説明できる。
- 提案の版、差分、根拠、反例、Rollback条件が追跡可能である。
- 相手の稟議構造・遵法要件・撤退条件に照応している。

## 失敗条件

- 情報過多で核が見えない。
- 自社都合の物語へ相手を押し込む。
- その場の圧力で型と検証順序が崩れる。
- 表現だけ整え、商品実体や条件が変わっていない。
- 意味領域や語彙が途中で漂流する。
- 社会的意義を権威づけに使う。
- 差分記録がなく、誤りから戻れない。

## 誤読禁止

この公式派生物を、次として扱わない。

```text
価格を最後に隠せば売れるという技法
相手の感情を操作するストーリーテリング
情報を少なくすればよいという単純化論
商品・特典・価格の順序を例外なく固定する台本
社会的意義を付ければ価値が増すという主張
相手ごとに事実を変えるパーソナライズ
営業担当者の即興力だけを称揚する方法論
```
