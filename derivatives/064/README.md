## この原典が定義するもの
第一印象は、単なる好感・不快感ではない。相手が短時間に形成する期待、警戒、役割認識、責任認識、選択可能性の仮説である。合意設計は、この初期仮説を演出で固定せず、後から共同で再読・修正・撤回できる**合意の記憶**へ変換する。

```text
接触
→ 第一印象が形成される
→ 期待・不安・役割の仮説が生まれる
→ 暗黙のまま進むと誤同意と責任ずれが起きる
→ 目的・条件・証拠・不利益・未確定を開示する
→ 相手自身の言葉で理解を確認する
→ 合意・未合意・保留を分離して記録する
→ 次の接点で再確認・修正・撤回する
→ 反復可能な合意の記憶になる
```

## 中心命題

```text
第一印象
≠ 永続的評価
≠ 好感度操作
≠ 暗黙の同意

合意の記憶
= 誰が何を理解し、
  何に限定的に同意し、
  何を保留・拒否し、
  どの条件で修正・撤回できるかを
  共同で再読できる状態
```

## 六層アーキテクチャ

### 1. 存在層
誰が、何の立場と責任で、何を扱うのかを示す。肩書や権威だけで信頼を要求しない。

### 2. 意味層
相手にとって何が重要で、どの語が同じ意味を持ち、何がまだ不明かを分ける。

### 3. 条件層
費用、期限、役割、対象外、前提、リスク、不利益、撤退条件を同じ判断面へ置く。

### 4. 証拠層
発言と実態を接続する資料、行動、一次ログ、実演、第三者確認を示す。

### 5. 確認層
相手が自分の言葉で理解・誤解・疑問・拒否・保留を表明できる場を作る。沈黙や相槌を同意へ変換しない。

### 6. 記憶層
合意、未合意、保留、変更、修正理由、次の確認時点を共同で再読可能に残す。

## 実行フロー
1. 接触時の事実と推測を分けて観測する。
2. 目的、役割、責任、対象範囲を明示する。
3. 条件、不利益、代替案、撤退経路を同じ場所で示す。
4. 相手自身の言葉で理解を再表現してもらう。
5. 合意・未合意・保留・質問を別状態として記録する。
6. 次工程へ進む前に再確認時点を置く。
7. 条件変化、違和感、時間経過時に修正または撤回する。

## 適用例

### 商談
「興味があります」を契約意思へ変換しない。関心対象、予算、決裁者、検討条件、保留理由、次の確認を分ける。

### 採用・協業
好印象と役割適合を分ける。期待成果、権限、支援、評価、報酬、撤退条件を確認する。

### 会議・組織運営
反対が出なかったことを合意にしない。賛成、非反対、保留、未確認、反対を別状態として残す。

### AI協働
AIの提案、人間の判断、承認、実行、監査を分ける。生成物の流暢さを人間の合意へ変換しない。

## 測定
- 理解再現率
- 条件不一致率
- 保留・拒否の可視化率
- 再確認到達率
- 修正・撤回可能性
- 責任帰属の一致率
- 接点間説明整合率
- 誤同意・苦情・再作業率

## 必須区別
- 第一印象設計 vs 印象操作
- 合意の記憶 vs 都合のよい記憶固定
- 小さな合意 vs 暗黙の全面同意
- 安心 vs 判断停止
- 共感 vs 迎合
- 記録 vs 監視
- 継続 vs 囲い込み
- 再確認 vs 同じ結論の強要

## 成立条件
- 相手が理解、非理解、拒否、保留を表明できる。
- 条件、費用、責任、不利益、撤回経路が見える。
- 言葉、行動、証拠が接点間で矛盾しない。
- 第一印象の仮説を事実として固定しない。
- 合意を後から共同で再読・訂正できる。
- 沈黙を同意に変換しない。
- 権力差がある場合は第三者確認、冷却時間、不利益禁止を設ける。

## 失敗・反証条件
- 好感度、権威、恐怖、急かしだけで同意を得る。
- 沈黙、曖昧な相槌、場の空気を合意として記録する。
- 不利益、条件変更、撤回経路を後出しする。
- 記録を拘束、監視、責任転嫁に使う。
- 接点ごとに説明、価格、責任が変わる。
- 再確認で理解が再現せず、修正後も不一致が続く。

## 誤読禁止
```text
第一印象を操作して相手を従わせる理論
営業クロージングや暗黙同意の技法
笑顔・沈黙・非反対を同意へ変換する方法
記録によって相手を拘束する仕組み
一度の同意を永続化する制度
権威や安心感で判断を停止させる方法
```
