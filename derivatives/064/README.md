## 位置づけ
親原典は、第一印象を単なる好感・不快感ではなく、接触直後に形成される期待、警戒、役割、責任、選択可能性の暫定仮説として扱う。合意設計は、この暫定仮説を演出や暗黙同意で固定せず、後から共同で再読・修正・撤回できる「合意の記憶」へ変換する。

重要なのは、第一印象を良くすること自体ではない。誰が何を理解し、何に限定的に同意し、何を保留・拒否し、どの条件で修正・撤回できるかが、相手自身の言葉と再読可能な記録によって追跡できる状態を作ることにある。

## 中心命題
**合意は、好感、沈黙、相槌、非反対から自動的に成立するものではない。目的、条件、証拠、不利益、責任、未確定を開示し、相手自身の言葉で理解を確認し、合意・未合意・保留・撤回を別状態として保持するとき、第一印象は反復可能な合意の記憶へ変わる。**

## 因果線
```text
接触
→ 第一印象と期待・不安の暫定仮説
→ 暗黙のまま進行
→ 誤同意・責任ずれ・条件認識差
→ 存在・意味・条件・証拠・確認・記憶へ分解
→ 費用・期限・役割・不利益・対象外・撤回経路を開示
→ 相手自身の言葉で理解を再表現
→ 合意 / 未合意 / 保留 / 質問を分離
→ 次接点で再確認・修正・撤回
→ 共同で再読可能な合意の記憶
```

## 構造層
**1. 存在層。** 誰が、何の立場と責任で、何を扱うのかを示す。肩書や権威だけで信頼を要求しない。

**2. 意味層。** 重要語、目的、期待、未確定語を分け、同じ言葉が同じ意味を指しているか確認する。

**3. 条件層。** 費用、期限、役割、前提、対象外、リスク、不利益、撤退条件を同じ判断面に置く。

**4. 証拠層。** 発言と実態を接続する資料、履歴、行動、実演、一次ログ、第三者確認を示す。

**5. 確認層。** 相手が自分の言葉で理解、誤解、疑問、拒否、保留を表明できるようにする。沈黙や相槌を同意へ変換しない。

**6. 記憶層。** 合意、未合意、保留、変更、修正理由、次の確認時点を共同で再読可能に残す。

## 状態モデル
```yaml
- contact_observed
- first_impression_separated_from_fact
- parties_and_issue_defined
- meanings_and_unresolved_terms_recorded
- roles_costs_deadlines_risks_disclosed
- non_applicable_conditions_disclosed
- evidence_available
- understanding_reexpressed_by_counterparty
- agreement_nonagreement_hold_separated
- withdrawal_path_available
- revision_log_available
- next_confirmation_defined
- power_asymmetry_protection_available
- origin_return_available
```

状態語 CONTACT / PROVISIONAL_UNDERSTANDING / PROVISIONAL_AGREEMENT / CONFIRMED / REVISED / WITHDRAWN は、合意関係の推移を区別するための状態列であり、成熟度順位や人物評価ではない。

## 適用例
**1. 商談。** 「興味があります」を契約意思へ変換せず、関心対象、予算、決裁者、検討条件、保留理由、次の確認を分ける。

**2. 採用・協業。** 好印象と役割適合を分け、期待成果、権限、支援、評価、報酬、撤退条件を確認する。

**3. 会議。** 反対が出なかったことを合意にせず、賛成、非反対、保留、未確認、反対を別状態として残す。

**4. AI協働。** AIの提案、人間の判断、承認、実行、監査を分け、生成物の流暢さを人間の合意へ変換しない。

**5. 権力差のある関係。** 冷却時間、第三者確認、匿名質問、拒否による不利益禁止等を置き、形式上の同意を自由意思と混同しない。

## 測定・監査点
- **六層**: 存在・意味・条件・証拠・確認・記憶という原典明示の6分類。6点満点や合意成熟度ではない。
- **理解再現率**: 相手が自分の言葉で理解内容を再現できるかを見る観測候補。
- **条件不一致率**: 費用・期限・責任・対象範囲等の理解差を観測する候補。
- **保留・拒否の可視化率**: 非同意が記録・追跡可能かを見る観測候補であり、低い保留率を成功とする指標ではない。
- **再確認到達率**: 次の確認が実際に行われるかを見る候補。
- **責任帰属一致率 / 接点間説明整合率**: 責任や説明が接点間で一致するかを見る候補。
- **誤同意・苦情・再作業率**: 合意設計の不一致を観測する候補。

反転評価では、合意到達が速くなっても、質問・拒否・保留・撤回が出にくくなったなら改善とみなさない。苦情や再作業が減っても、異議経路を閉じた結果なら成功ではない。

## 成立条件
- 相手が理解、非理解、拒否、保留、訂正を自由に表明できる。
- 条件、費用、責任、不利益、対象外、撤回経路が見える。
- 言葉、行動、証拠が接点間で矛盾しない。
- 第一印象の仮説を事実として固定しない。
- 合意を後から共同で再読・訂正できる。
- 沈黙や非反対を同意へ変換しない。
- 権力差がある場合、冷却時間・第三者確認等の保護を設ける。

## 失敗条件
- 好感度、権威、恐怖、急かしだけで同意を得る。
- 沈黙、笑顔、相槌、場の空気を合意として記録する。
- 不利益、条件変更、撤回経路を後出しする。
- 記録を拘束、監視、責任転嫁に使う。
- 接点ごとに説明、価格、責任が変わる。
- 一度の同意を永続化する。
- 再確認で理解が再現しないのに進行を続ける。

## 反証・改訂条件
- 確認を重ねても理解内容が再現されない。
- 条件不一致や責任転嫁が反復して減らない。
- 記録を増やすほど質問・拒否・保留が減り、監視圧力が高まる。
- 再確認が同じ結論の強要として機能する。
- 権力差保護を入れても自由な拒否が成立しない。
- 合意時間短縮が説明・比較・冷却時間の省略によって達成される。

## 必須の区別
- 第一印象設計 / 印象操作
- 合意の記憶 / 都合のよい記憶固定
- 小さな合意 / 暗黙の全面同意
- 沈黙 / 同意
- 非反対 / 賛成
- 安心 / 判断停止
- 共感 / 迎合
- 記録 / 監視・拘束
- 継続 / 囲い込み
- 再確認 / 強制収束
- 修正・撤回 / 不履行の自動認定

## 解釈制約
合意設計論を営業クロージング、心理操作、暗黙同意、記録による拘束、責任転嫁へ縮約しない。六層と状態列は評価スコアではなく、理解と意思の位置を区別する構造である。合意速度や合意率だけを成功指標にせず、質問・拒否・保留・撤回可能性と併読する。
