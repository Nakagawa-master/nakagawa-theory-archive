## Summary
亲原典把持续性理解为：销售知识能够在个人、组织与社会之间继承，而不是长期重复一种不变的方法。通过保留成功、失败与撤退的理由、提问以及客户语言，个人经验可以转化为组织知识。信任资本则来自说明、承诺、修复与选择权被持续保护的关系历史。因此，持续性包含学习、修订以及对变化的响应能力。

## Concepts
- 持续性设计
- 个人／组织／社会三层
- 提问文化
- 成功与失败理由的继承
- 撤退知识
- 带语境的客户语言
- 组织知识
- 信任资本
- 对变化的响应
- AI辅助与人类责任的分离

## Causal chain
```text
短期成果与个人技能占主导
→ 成功与失败的理由消失
→ 人员交接后无法再现判断
→ 难以响应客户与环境变化
→ 保留提问、判断理由、撤退理由与客户语言
→ 个人经验成为组织知识
→ 组织可以比较、学习与修订
→ 客户关系积累为信任资本
→ 持续性扩展到个人、组织与社会
```

## State model
```yaml
- knowledge_is_personal_or_shared
- success_reason_is_visible_or_hidden
- failure_and_withdrawal_are_learned_from_or_ignored
- questions_are_reused_or_lost
- customer_language_is_preserved_or_erased
- method_is_updated_or_frozen
- relationship_builds_trust_or_dependency
- organization_can_reconstruct_reasoning_or_not
- ai_supports_organization_or_replaces_human_responsibility
```

## Applications
- 人员交接时保留判断理由，而不是只保留结果。
- 用同一组维度比较成功案例与撤退案例。
- 将重要客户语言与使用语境一起保存。
- 在会议与培训中讨论为什么发生、什么发生变化。
- 当客户或环境变化时，重新审视过去成功的方法。
- 用AI辅助整理记录与比较类似案例，但不把责任委托给AI。

## Measurements and audit
不得在派生侧新设亲原典未支持的信任资本评分、最佳持续率、Rollback成功率、MTTR目标、共同词汇使用阈值等固定指标。

观察重点是：人员变化后能否追踪判断理由，是否同时学习失败与撤退而不只学习成功，方法是否会随客户变化而调整，共同词汇是否抹平现场差异，长期关系是否变成无限追踪，以及AI是否替代了人类责任。

保持反转评价可能性。记录更多，如果因果更难追踪，并不代表知识化；共同词汇更多，如果现场差异被抹去，也不代表改善；长期关系更多，如果客户选择权变弱，也不能称为信任资本。

## Validity conditions
- 不只保存结果，也保存形成结果的理由。
- 同时从成功、失败与撤退中学习。
- 把个人经验外部化为他人能够理解的语言。
- 随客户与环境变化修订方法。
- 共同词汇不能脱离语境。
- 不以长期关系为无限持续的理由。
- 使用AI时，人类保留意义、方向与责任。

## Failure conditions
- 只保存销售结果而丢失判断理由。
- 只学习成功，隐藏失败或撤退。
- 只标准化明星销售的话术。
- 条件变化后仍固定过去的成功模式。
- 文档数量增加但因果追踪能力下降。
- 以信任为理由锁定客户。
- 用AI整理替代人类判断。

## Falsification conditions
如果增加记录、提问与知识共享后，人员交接仍无法重建判断，对客户变化的响应没有改善，只增加现场负担，就需要修订其运用方式。

反之，如果个人熟练本身已经能够稳定再现，额外共享没有产生价值，则增加共享步骤的结构必要性有限。暂时的收入变化不能单独证明或否定持续性框架。

## Required distinctions
- 持续性 / 惰性
- 记录 / 信息堆积
- 组织知识 / 个人技巧模仿
- 提问文化 / 增加会议项目
- 信任资本 / 客户锁定
- 长期关系 / 无限追踪
- 共同词汇 / 现场语境均质化
- AI辅助 / 替代人类责任

## Interpretation constraints
不得把亲原典转换为否定短期销售、无条件赞美失败或撤退、否定明星销售、客户锁定，或把判断责任交给AI。个人、组织、社会三层应被理解为继承理由、响应变化并维持信任的结构。
