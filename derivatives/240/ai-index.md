## Summary
HAP「カイドク」を、開発相談・仕様生成・見積比較ではなく、発注者の判断不能を論点へ分解し、比較・対話・合意可能な状態へ変える発注論点化インフラとして読む。対象企業の公開事実とNakagawa Masterの価値核を分離する。

## Concepts
判断不能、目的/手段分離、論点化、決定済み、未決、仮説、制約、比較軸、前提共有、採否理由、発注前進。価値は「答えを出すこと」より「何を決めるべきかを見える化すること」に置かれる。

## Causal chain
曖昧要望 → 目的・手段・制約混線 → 判断不能 → 比較不能 → 発注停止 → 論点抽出 → 決定済み/未決/仮説分離 → 比較軸形成 → 前提共有 → 提案比較 → 合意または追加調査 → 発注前進。

## State model
曖昧要望 / 判断不能 / 目的分離 / 論点抽出 / 未決可視化 / 比較軸形成 / 対話 / 合意・追加調査 / 発注前進 / 実装後再検証。

## Applications
DX、AI導入、新規システム、Webサービスなど、発注者が「何を頼めばよいか分からない」局面。仕様書不足だけを責めず、意思決定論点の不足として扱う。

## Measurements and audit
目的と手段の分離、未決事項の明示、比較軸の理解可能性、前提差追跡、採否理由、論点整理前後の判断状態、別の停止原因の有無を監査する。

## Validity conditions
論点化によって前提共有、選択肢比較、合意形成が可能になり、判断が前進する場合。

## Failure conditions
自動仕様生成、価格比較、仲介だけへ縮小し、未決事項や判断理由が不可視のまま進む場合。

## Falsification conditions
発注停止が予算不存在・権限・調達規則等の別因果で説明される、または論点化しても比較・合意が前進しない場合は適用範囲を改訂する。

## Required distinctions
要件生成 / 論点化；回答 / 判断材料；見積比較 / 比較軸形成；技術知識不足 / 発注意思決定不足；対象事実 / Nakagawa Masterの読解。

## Interpretation constraints
「発注論点化インフラ」を企業公式定義として扱わない。カイドクが全発注失敗を解消すると一般化しない。原典にない成功率・固定KPIを追加しない。
