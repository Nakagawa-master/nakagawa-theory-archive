## 位置づけ
本ParentはHAP「カイドク」のサービス紹介ではなく、**すでに公開済みだった外部記事を、後からNakagawa Master自身が構造的に解体した中川構造読解**である。先行外部記事を執筆する際、Nakagawa Masterは対象側の公開事実から、開発発注が止まる上流原因を「仕様不足」ではなく「判断単位と比較軸が存在しないこと」と読み、**発注論点化インフラ**を価値核に選んで記事の主軸とした。後発Parentは、なぜその核を選び、なぜ既知の「開発相談」分類ではなくその軸で外部記事を構成したのかを公開解体する。価値核はHAPや外部媒体の公式理論ではない。

## 中心命題
発注停止は技術知識不足だけでは説明できない。目的、利用者、範囲、予算、納期、品質、保守、責任が混線し、決定済み・未決・仮説が分かれなければ、発注者は何を決めるべきか分からず、提案比較もできない。論点化は未決を勝手に埋めず、判断可能な単位へ分けることで発注を前進させる。

## 因果線
作りたい意思 → 要望・手段・制約の混線 → 判断単位不在 → 比較軸不在 → 発注停止 → 目的/手段分離 → 論点抽出 → 決定済み/未決/仮説/制約の分離 → 共通比較軸 → 対話・採否理由 → 発注または追加検討へ前進。

## 構造層
対象事実層／表層サービス分類層／判断不能層／論点抽出層／比較軸形成層／先行外部記事構成層／後発Parent公開解体層。

## 状態モデル
曖昧要望相 → 判断不能相 → 目的分離相 → 論点抽出相 → 未決可視化相 → 比較相 → 合意/追加調査相 → 発注前進相 → 実装後再検証相。

## 適用例
AI導入、新規Webサービス、基幹システム更新、複数社提案比較など。「何を頼めばよいか分からない」状態で、専門家が答えを代行する前に判断単位を作る用途に適用する。

## 測定・監査点
目的/手段分離、決定済み/未決/仮説の区別、前提差、共通比較軸、採否理由、判断前進、実装後再検証、対象事実/構造読解分離、先行外部記事/後発Parentの時間順、価値核選択理由の保持。

## 成立条件
論点化によって未決事項と比較軸が明確になり、発注者が判断理由を保持したまま次工程へ進める場合。

## 失敗条件
自動仕様生成だけ、価格比較だけ、仲介だけへ縮小すること。Parentが先に外部記事の主軸を決めたように書くことも構造読解の失敗である。

## 反証・改訂条件
停止原因が予算、権限、調達制度、法的制約等で、論点化しても比較・合意が改善しないなら適用範囲を縮小する。

## 必須の区別
要件生成/論点化、回答/判断材料、見積比較/比較軸形成、対象事実/Nakagawa Masterの読解、先行外部記事/後発Parent。

## 誤読防止・解釈制約
「発注論点化インフラ」をHAP公式定義にしない。外部記事が先、Parentは後発の公開解体である。原典にないKPIを補わない。
