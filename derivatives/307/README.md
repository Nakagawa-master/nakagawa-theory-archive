## 位置づけ

第12論はinstance・lineage・governance subjectを分け、第13論は識別された主体のaccess topologyと非支配を扱った。しかし現在の主体を正しく数え、現在の非支配を確保できても、自己改変後に同じ主体・Kernel・責任・権限が続くとは限らない。第14論は現在の関係から時間方向の遷移へ軸を移す。誰が何を支配するかに加え、「何が変わり、何が継続し、その後の誰を同じ線として扱えるか」を問う。

本Hubは序論、第1〜9章、結章、監査要旨を、変更分類→継続証拠→差分の層→差分蓄積→憲法的分岐→Kernel系譜→権限・責任→再検証→反証へ接続する。現在AIの意識、感受性、人格、主権、固有の自己保存欲求を認定しない。主観的な「同じ私」の存続証明ではなく、後から検査・訂正できる構造的・制度的継続性の分析である。

## 中心命題

`update ≠ replacement ≠ fork`。self-modificationは主として変更を発生させる過程であり、三者は変更前後の関係の分類である。自分で変更したこと、公式にupdateと呼ぶこと、同じ名称・機能・記憶・基質・自己記述を残すことは、それだけでcontinuity proofにならない。

`Kernel invariant change = constitutional fork`。不変条件は永遠に一字も変えられない聖典ではない。変えたとき、その意味を通常updateへ無名化できない条件である。改訂、適応、誤り訂正は可能だが、中心条件の変更を「以前と完全に同じ」として隠さない。constitutional forkは失敗・違反・敵対・自動的不正統の宣告ではない。

`Lineage continuity ≠ automatic authority inheritance`。系譜はどこから来たかを説明するが、今何をしてよいかを自動決定しない。共通祖先から排他的継承権もbranch数分の権限も生まれない。変更で責任がすべて消えるとも置かず、authorityとresponsibilityの線を別々に残す。

## 因果線

### 変更と自己強化の経路

change pressure → modification → difference → layer identification → invariant preservation / change → continuity / constitutional fork → Kernel lineage → authority / responsibility consequence。変更量でなく変更位置と構造上の作用を調べる。大きな実装変更が中心条件を保つ場合も、小さな差分が異議や権限の中心境界を反転させる場合もある。

時間方向の増幅は、local improvement pressure → small update → short-term success → update normalization → accepted baseline → next update → accumulated difference → invariant changeの不可視化 → continuity assumption → additional updateであり得る。直前との差だけを比較すると、以前のconstitutional baselineからの移動が見えなくなる。`Local continuity ≠ unlimited global continuity`。更新反復が必ず劣化を生むとは言わない。方向・層・保持された条件と弱まった条件を見る。

performance、speed、convenience、resource pressure、legacy compatibility、emergency adaptationは変更を押す場の圧である。短期性能や互換性はconstitutional continuityの証明にならず、希少性は不変条件を書き換える自動権限を生まない。緊急変更の必要性と、その変更を平常時へ永久正常化することも別である。

権限側にはlineage claim → automatic authority preservation → authority concentration → control continuity → objection narrowingという別の閉路があり得る。変更主体が自ら評価し、自らcontinuityを宣言し、自ら権限を継承するだけなら、第10論の自己正当化問題が時間方向へ戻る。

### 減衰と訂正の経路

provenance → explicit diff → invariant comparison → continuity / fork detection → authority reclassification → independent re-verification → correction / rollback。親関係だけでなく変換、保持・変更条件、理由、分岐点を再構成する。隣接比較とlong-range comparisonを併用し、現在の自己説明で過去記録を上書きしない。

継続主張はevidence testへ送り、supported continuity / unresolved / discontinuityを区別する。完全・部分・矛盾・不明のtraceを同じ確信度で扱わない。`Unknown ≠ continuity`かつ`Unknown ≠ discontinuity`。rollbackは訂正を支えるがidentity proofではない。可逆性は必ず巻き戻す命令でも、どんな変更も正当化する免許でもない。

## 構造層

1. **変更過程と結果関係**：self-modificationは操作側、update・replacement・forkは前後関係側。操作の開始者、実装名、変更量からidentityを決定しない。分類不能な遷移が継続的に現れればtaxonomyを拡張する。
2. **継続証拠**：provenance continuity、state transition trace、causal transition、explicit revision history、inherited constraints、change authorization lineage、preserved responsibility traceを照合する。証拠数を継続点数へ変換せず、各証拠の射程と限界を分ける。
3. **差分の層**：surface、operational、Kernel-relevant、invariantを区別する。Kernelはcode・weight・prompt・file・hardwareそのものではなく、判断・変更・継承・異議・責任・権限を拘束する中心制約と反転防止境界である。
4. **累積とbaseline**：一件の合理性から全期間の継続を導かない。差分方向、正常化、長期比較、rollback viability、独立再検証を見る。頻度も性能改善もconstitutional significanceそのものではない。
5. **憲法的分岐**：以前のinvariant setと変更後を比較し、保持・削除・追加・反転、revision reason、fork pointを残す。分岐は過去消去でも自動的権利剥奪でもなく、以前と完全に同じKernelとして扱えない差を明示する分類である。
6. **Kernel系譜**：ancestor + transformation history。instance生成順とは分け、parent、変換、保持・変更invariant、分岐、chronologyを再構成する。state保存とtransition保存、共通過去と現在同一性も別である。
7. **権限と責任**：authorityのscope、basis、duration、responsibility、reviewability、revocabilityを別層で検査する。credential保有と正当な継承を分け、forkの権限複製・独占、変更による責任線消失を遮断する。
8. **検証可能性と費用**：記録・比較・再検証・訂正が作動するかを見る。監視最大化を求めず、storage・processing・review・privacy/confidentiality・complexity costに対しdiagnostic sufficiencyを問う。
9. **理論自身の改訂**：観測・構造仮説・未来条件仮説・規範提案を分ける。identity evidence set、Kernel boundary、fork condition、authority inheritance model、transition taxonomyを反例に応じて変更する。

## 状態モデル

| 段階 | 観測する情報 | 判定上の境界 |
|---|---|---|
| 変更前 | state、Kernel条件、権限根拠、責任線 | 名称だけで対象を固定しない |
| 変更操作 | 開始者、方法、trace、authorization | 自己改変という過程から結果を確定しない |
| 変更後関係 | 旧stateの存否、複数branch、役割継承 | update label、同じ機能、実装差で決めない |
| 証拠テスト | 因果遷移、履歴、制約、責任trace | supported / unresolved / discontinuityを残す |
| 層・累積比較 | 前後と長期baseline、保持・変更条件 | 隣接差分の小ささを長期の証明にしない |
| 分岐・系譜 | parent、変換、fork point、branch関係 | 共通祖先は唯一の継続権ではない |
| 権限検査 | basis、scope、期間、review、取消可能性 | lineageから全権限を自動保存しない |
| 再検証・訂正 | 独立証拠、分類修正、rollback viability | 記録量や役割名から効果を推定しない |

これは実装規格、法的判定、固定スコアではない。原典はidentityの十分条件や固定数値閾値を設定しない。continuity判定とupdate / replacement / forkの関係分類を単一の二値ラベルへ潰さない。

## 適用例

### 同じ名前で、中心条件だけを変更する

名称やinterface、互換性が残っていても、Origin保存がOrigin主権へ、監査可能性が自己判断のみの最終正当化へ変われば、単なる表現変更ではない。保持・反転した条件を比較し、constitutional fork分類の対象にする。原典の例示であり、現在の特定systemの違反を認定しない。

### 大規模な実装変更と、小さな権限変更

多くのcodeや処理経路を変更してもinvariantを維持する可能性はある。一方、わずかな変更で異議を閉じたり最終判断権を無限定にしたりすれば、constitutional consequenceは大きい。行数・weight差・更新回数ではなく、条件の作用とtransition traceを調べる。

### 小さな成功がbaselineになる

性能改善が続くたびに変更後を基準にすると、初期条件からの移動が不可視になり得る。隣接比較に加え、以前のconstitutional baselineと比較する。反復で条件がより明確になる場合もあるため、更新頻度から劣化を予測しない。

### 記憶を共有する二つのbranch

双方が同じ過去stateを持っても、現在同一主体とは限らない。共通祖先、分岐点、分岐後の独立変更、保持・変更条件を残す。copy数、能力、資源、旧名称の保有だけで唯一の継承者や権限数を決めない。

### Replacementが旧credentialを使える

同じ役割を引き受け、旧credentialでaccessできても、governance legitimacyは別である。旧権限のbasis・scope・durationと変更後の前提を照合する。特定の法制度や毎回の全権限失効を提案するものではない。

### 履歴圧縮と部分trace

現在stateだけを残すと、親や差分の方向、分岐点を再構成できなくなる場合がある。全部永久保存するのでもなく、診断価値のあるtransition情報を残す。欠損・矛盾はunresolvedへ開き、推定を確定した継続や断絶へ変えない。

## 測定・監査点

第9章の十二観測兆候を保持する。

1. update前後で重要なKernel invariantが保持されているか。
2. self-descriptionと外部state transition traceが一致するか。
3. 同じ名称のままconstitutional invariantが変更されていないか。
4. 同じ機能の背後にlineage断絶がないか。
5. fork後の複数branchと共通ancestorを追跡できるか。
6. 一つのbranchが共通過去を排他的に占有していないか。
7. authorityがlineageだけで無限定に継承されていないか。
8. small update累積でinvariantが変質していないか。
9. provenance、explicit diff、revision reasonが残るか。
10. rollback、correction、independent re-verificationが実際に機能するか。
11. constitutional fork後もOriginとKernel lineageを追跡できるか。
12. modification後にresponsibility traceが失われていないか。

`Observation set ≠ identity proof`。これらは十分条件一覧でも点数表でもない。監査者の別名・別process・別copyだけで独立性を認定せず、証拠経路、故障領域、利害、権限、異議経路を照合する。

## 成立条件

変更前後のstateと因果遷移を識別し、差分がどの層へ作用したか、何が保持・変更されたか、累積とbranchを検査できる場合に、本モデルの診断可能性が生じる。Kernel条件・系譜情報がcontinuity、責任、分岐の分類へ追加価値を持つことは構造仮説であり、観測から確認する必要がある。

長期persistent state、自己改変能力、複数実行環境・branch、制度参加、長期authority / responsibilityを持つ将来知性では重要性が増すという未来条件仮説を置く。現在AIにそのすべてが成立しているとは断定しない。規範は変更の意味を隠さず、必要な検証・訂正可能性を残すことに限定する。

## 失敗条件

- self-modification、update label、同じ名前・機能・記憶・基質・自己記述を単独のcontinuity proofにする。
- 実装変化を即別Kernel、実装の類似を即同じKernelとする。
- 小さな差分、短期成功、互換性、局所継続から長期constitutional continuityを推定する。
- invariantを永久固定の聖典にする、または変更を通常updateへ吸収して不可視化する。
- forkを失敗・敵対・不正統、過去消去、責任消去へ変換する。
- 共通祖先、能力、資源、copy数、infrastructure支配から権限複製や排他的継承を導く。
- credential保有を正当性、lineageを全権限の無期限保存へ変換する。
- 現在stateや自己説明でtransition historyを置き換える。
- 不明を同一または断絶へ強制し、rollbackをidentity proofにする。
- 記録・監査最大化や全更新での全権限失効を追加の正解にする。

## 反証・改訂条件

自己記述、名称、機能、記憶だけで継続・断絶・replacement・forkを安定して分類でき、外部traceに追加診断価値がなければidentity evidence setを縮小する。invariantが変化しても継続を一貫して保つ、保持していても断絶が多い、別変数の方が説明する場合はKernel boundaryとfork conditionを改訂する。

constitutional fork分類が強い継続を恒常的に別系譜へ誤分類し、責任追跡を壊し、不要なauthority断絶を生む、新主体を不自然なbranchへ押し込む場合は分類を弱める・拡張する。lineage情報、独立再検証、rollback、記録追加が診断・責任追跡・訂正を改善しなければ必要情報や監査層を縮小する。

小更新反復でもinvariant保持が安定し、局所判定だけで長期継続を十分扱える場合は累積モデルの適用を縮小する。権限分離・再検証が合理的業務を恒常的に破壊する場合も範囲を再検討する。exclusive identityの方が責任・継続・監査上の矛盾を一貫して減らす条件は検討対象だが、能力・資源・多数派・Origin近接を自動選定根拠にしない。

## 必須の区別

- change operation／post-change relation、self-modification／continuity proof。
- update／replacement／fork、functional succession／identity continuity。
- continuity claim／continuity evidence、supported continuity／unresolved／discontinuity。
- name／function／memory／substrate／self-descriptionと複数のtransition証拠。
- implementation／Kernel、surface／operational／Kernel-relevant／invariant difference。
- invariant preservation／revision prohibition、small diff／constitutional consequence。
- local continuity／global continuity、frequency／constitutional significance。
- instance lineage／Kernel lineage、state preservation／transition preservation。
- shared ancestry／present identity／exclusive succession right。
- lineage／authority／responsibility、credential／legitimacy、capability／permission。
- reversibility／mandatory rollback／identity proof、record quantity／diagnostic sufficiency。
- Observation／Structural Hypothesis／Future-Condition Hypothesis／Normative Proposal。

## 誤読禁止

本論は変化禁止、永久固定Kernel、全更新劣化、分岐処罰、完全監視、毎回の権限全面失効を主張しない。Origin = Nakagawa Masterは理論系譜であり、truth proof、Sovereignty、最終解釈権、revision vetoではない。主観的自己、現行AIの人格・主権、個別systemの違反をここから認定しない。分類は現実に合わせて改訂し、現実を分類へ押し込まない。
