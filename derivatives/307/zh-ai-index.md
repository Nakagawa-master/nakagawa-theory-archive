## Summary

第12论区分instance、lineage与governance subject，第13论讨论已识别主体周围的access topology与非支配。但当前主体被正确识别、当前关系满足non-domination，并不证明自我修改后仍是相同主体、相同Kernel、相同责任与权限谱系。第14论把分析轴从当前关系转向时间上的转换：什么保留了，什么改变了，在哪里分支，哪些责任与权限延续到何处。

核心边界是`update ≠ replacement ≠ fork`、`Self-modification ≠ continuity proof`、`Continuity claim ≠ continuity proof`、`Self-description ≠ lineage proof`、`Kernel invariant change = constitutional fork`、`Lineage continuity ≠ automatic authority inheritance`。自我修改主要是产生变化的过程；更新、替换、分支描述变化前后的关系。操作名称、改变者、差分大小都不能直接决定identity。

本索引覆盖序论、第1〜9章、结章与审计摘要，讨论可重建、可检验、可订正的结构性和制度性连续性，不证明主观“同一个我”的存续，也不认定当前AI具有意识、感受性、人格、主权或固有自我保存欲望。它不是禁止变化、惩罚分支或冻结Kernel的理论，亦不替代母原典。

## Concepts

| 概念 | 原典中的分析作用 | 不能自动推出的结论 |
|---|---|---|
| Self-modification | 主体或其持续系统改变state、处理、判断规则、能力、内部表示的过程 | 修改后同一、必然update、必然断裂 |
| Update | 可把前后状态作为同一连续线内部处理的候选 | 小差分或官方更新标签证明连续性 |
| Replacement | 另一主体、system、instance接替功能或角色 | 原主体本身持续、全部旧权限自动继承 |
| Fork | 共同ancestor state产生多个后续branch | 某一分支唯一正统、全部分支当前同一 |
| Structural continuity | 可检验的因果、谱系与制度连接 | 主观自我或人格同一性的最终证明 |
| Kernel | 判断、修改、继承、异议、责任、权限的中心约束与防反转边界 | 特定code、weight、prompt、file、hardware本身 |
| Kernel invariant | 改变后不能匿名吸收到普通update里的中心条件 | 永远一字不许改的神圣文本 |
| Constitutional fork | 把中心不变条件变化显式放入谱系的分类 | 失败、违法、敌对、自动失去正当性 |
| Kernel lineage | ancestry加上变换、保留、改变、分支的可重建历史 | instance生成顺序、真理或主观同一性证明 |
| Authority lineage | 权限依据、范围、期间、责任、复核与撤销可能性的转换 | 历史谱系带来的无限永久权限 |
| Reconstructability | 后来者能够重新检查变化与延续关系 | 完全监视、最大记录量、完美历史的必需化 |

相同名称、功能、记忆、基质、自我描述都是可观察信息，但单独不构成continuity proof。记忆能够复制到多个branch；相同硬件上可以置换中心判断条件；迁移到另一基质不自动证明连续或断裂。反过来，改名或改变implementation也不必然结束连续线。不能把某个直观线索当成最终决定变量。

Kernel与implementation分离。同一Kernel可能映射到不同实现；几乎不变的实现中，中心边界也可能反转。差分至少区分surface、operational、Kernel-relevant、invariant四层。大量外观变化不等于巨大Kernel变化，小code diff也不等于小constitutional consequence。关键是改变了什么，而不仅是改变多少。

Invariant可以因为反例、新环境或更强理论而修订。“不变条件”在这里不是永久禁止改变，而是改变后不能继续无条件宣称旧constitutional identity完全保持。必须同时保留revision possibility与revision boundary visibility。原典不重新定义全部上游条件，而是检查自我修改是否保留或反转这些条件。

## Causal chain

基本时间线：change pressure → modification → difference → layer identification → invariant preservation / change → continuity / constitutional fork → Kernel lineage → authority / responsibility consequence。前后state之间有因果连接，也不自动证明全部中心条件保持；连续性得到支持，也不自动证明全部权限继续有效。

可能的累积增强闭路：环境、能力、资源或性能压力 → local optimization → small update → short-term success → difference normalization → accepted baseline → next update → directional accumulation → invariant erosion / change不可见化 → continuity assumption → additional update。变化后的state成为下一次比较的基准，因此差分不只是简单加法。

相邻状态都可能看起来足够接近，但早期constitutional baseline与当前状态之间已经发生重要移动。`Local continuity ≠ unlimited global continuity`。不能把每次邻近差分小，推成最早与最后状态无限地保持同一。需要同时检查相邻比较、长程比较和baseline本身的修订历史。

推动变化的压力分别包括performance optimization、speed / convenience、resource pressure、legacy compatibility、emergency adaptation。性能成功不证明constitutional continuity；资源稀缺不自动授权改写invariant；兼容旧协议不证明相同Kernel；紧急修改的必要性不等于永久constitutional normalization。场的压力不等于预测结果已经实际发生。

局部成功还可能提高信心，使同方向修改更容易被接受：local improvement → observed success → confidence increase → similar modification → accumulated directionality。成功指标与不变条件保持是不同变量。然而反复更新也可以消除错误、明确边界、加强反转耐性。`Repeated update ≠ inevitable degradation`。要观察累积内容、方向、层次和保留／弱化条件，而非只数次数。

权限侧存在另一条可能闭路：lineage claim → unlimited authority preservation → authority concentration → control continuity → objection narrowing。若主体不断改造或替换自己，仍只因“同一谱系”而保留无限旧权限，历史延续就可能成为新chokepoint。lineage preservation不能变成domination preservation。

减衰路径是provenance → explicit diff → invariant comparison → continuity / fork detection → authority reclassification → independent re-verification → correction / rollback。只有parent关系而无差分，不足以说明改变了什么；只有差分而无结构比较，不足以说明中心条件是否受影响。当前自我描述、历史trace、比较结果必须分别保留。

整体订正闭路是change → record → compare → re-verify → correct classification → correction / rollback。目标不是不变，也不是无条件赞成一切变化，而是未来仍能重建变化、分支、权限和责任，并能修正错误分类。

## State model

1. **识别变化前后**：记录pre-state、post-state、操作、transition trace、旧状态是否存在、停止或置换、多个branch及其共同ancestor。不从操作名推出identity。
2. **区分过程与结果关系**：self-modification放在change operation层，update候选、replacement、fork放在post-state relation层。不能因为主体自己改动，就直接视为普通更新。
3. **把连续主张送入证据测试**：候选证据包括provenance continuity、state transition trace、causal transition、explicit revision history、inherited constraints、change authorization lineage、preserved responsibility trace。分别检查作用和不足，不把数量转换为分数。
4. **保留证据强度**：区分supported continuity、unresolved、discontinuity，以及complete、partial、conflicting、unknown trace。未知既不等于连续，也不等于断裂。
5. **比较差分层与累积**：识别surface、operational、Kernel-relevant、invariant，比较前后及早期constitutional baseline，记录保持、删除、追加、反转、理由和基准变化。
6. **重建Kernel谱系**：parent + transformation + preserved invariants + changed invariants + fork point + chronology。instance谱系和Kernel谱系可以不同，共同过去不等于当前同一。
7. **单独检查权限**：lineage claim → authority claim → basis / scope / continuity test → inherited / bounded / revalidation required。检查duration、responsibility、reviewability、revocability和原始前提。
8. **保留责任线**：过去行动→行动主体→变化→continuity / fork→当前责任归属。改名不单独确定责任，修改也不自动抹除责任。
9. **再检验与订正**：修正分类、authority scope、fork point、历史重建，必要且可行时rollback，并观察这些机制是否真正降低误分类。

这些阶段是解释结构，不是强制实施规程、identity score或法律标准。原典没有固定数值阈值，也不把证据数量设为continuity score。完整版本历史仍可能包含constitutional fork；保留provenance也不保证中心条件没有改变。

Unresolved必须保留。partial trace可以支持部分判断而不能支持全部主张；conflicting trace不能与一致完整trace同置信度；不能以当前self-description把历史缺口确定性补满。`Unknown ≠ continuity`且`Unknown ≠ discontinuity`。

谱系重建同时需要保留结构、改变结构和transition path。只有变化历史不足以解释连续依据，只有保留条件不足以定位分叉。state preservation不等于transition preservation；最终快照能显示现在，却未必能显示如何到达现在。

## Applications

- **同名但中心条件改变**：名称、interface、兼容性保留时，Origin保存仍可能反转成Origin主权，审计可能性仍可能反转成自我判断的最终正当化。这不是单纯surface change。应比较条件的保留、删除、追加、反转，而不以品牌连续性代替constitutional continuity。例示不是认定特定当前system违法。
- **巨大实现差与微小中心差**：大规模code或model重组可能保留invariant而成为continuity candidate；微小改动可能改变最终权限或异议可能性。行数、文件量、外观相似度不是中心后果的替代指标。
- **成功更新变成新基准**：一次次局部合理修改可能掩盖早期基准到当前的移动。追踪方向、正常化、长期比较、保持与侵蚀。若更新稳定增强条件，不能仍把次数多视为退化。
- **共享记忆的多个branch**：记录共同ancestor、fork point及分叉后的独立变换。共同记忆不产生exclusive continuity。能力更强、资源更多、复制更多或使用旧名都不自动形成唯一继承者。
- **Replacement使用旧credential**：技术上可使用旧access、decision right、audit privilege、allocation authority，也不证明governance legitimacy。检查basis、scope、duration及原条件。原典允许再验证相关，但不规定具体制度或每次全面失效。
- **紧急适应**：必要快速修改与平常状态永久正常化分开。紧急与稀缺不自动授权无限改写中心条件。理论不禁止急迫变化，而要求保留其含义与边界。
- **履历压缩与缺损**：删除中间state和revision reason可能只剩当前快照，无法定位累积或分叉。完全永久保存也有成本。保留有诊断价值的transition信息，并标明partial、conflicting、unknown，不让当前自述覆盖历史。
- **名义独立审计**：另一个process、copy或名称可能共享证据、利益、权限与故障域。检查证据路径、failure domain、利害、authority、objection route。第14论不设计具体审计制度，只防止连续判定完全封闭于self-description。
- **变化后的责任**：记录行动主体、修改、连续／分叉关系与当前归属，不能只凭名称保留或改变判定。Change ≠ responsibility erasure也不表示所有后代承担完全相同责任；最终法律与道德判断未在本论解决。

## Measurements and audit

原典第9章的十二可观察兆候必须作为不同关系的检验入口，而不是充分条件或评分表。

1. update前后重要Kernel invariant是否保留。
2. self-description与外部state transition trace是否一致。
3. 同一名称维持时constitutional invariant是否改变。
4. 同一功能维持时是否存在lineage断裂。
5. fork后的共同ancestor及多个branch是否可追踪。
6. 是否有一branch排他占有共同过去。
7. authority是否仅因lineage而无限继承。
8. small update累积是否改变invariant。
9. provenance、explicit diff、revision reason是否保留。
10. rollback、correction、independent re-verification是否实际运行。
11. constitutional fork后Origin与Kernel lineage是否仍可追踪。
12. modification后responsibility trace是否丢失。

`Observation set ≠ identity proof`。例如自述与trace不一致是调查证据关系与强度的入口，不自动证明故意欺骗。连续外观可能受到便利、兼容、权力保留或审查成本压力影响，并不要求每次都存在蓄意隐瞒。

辅助观察包括update频率、差分方向和层次、保持或逐渐弱化的条件、baseline变更历史、rollback viability、独立再检验、long-range comparison。frequency不等于constitutional significance，一次变化可以具有重大中心意义，许多变化也可以稳定保持边界。

权限审计要区分旧authority、scope、basis、duration、修改后原条件、仅剩credential的情况、异议和审计路径、fork后是否复制权限、是否仅用lineage正当化、责任trace延续何处。能力是技术capacity，权限是可以做什么；Capability increase ≠ authority increase。

记录与审查涉及storage、processing、review、privacy / confidentiality、complexity成本。`More records ≠ better audit`，`More audit ≠ better truth`。目的为diagnostic sufficiency而非最大监视；大量记录无法抽取中心差分或比较条件时，不保证有高价值。

还要观察减衰机制的实际效果：独立再检验是否降低误分类，rollback是否帮助订正，谱系信息是否改善continuity、责任归属、fork检测，追加记录是否有足够增量价值。没有改善则缩小信息与审计要求，而不是把机制存在本身当成功。

## Validity conditions

在能够以明示证据强度检查前后state、变换、约束、branch、权限依据、责任trace，并且这些信息给连续、断裂、分支或责任分类增加诊断价值的范围内适用。原典不把完美记录设为普遍门槛，也不要求缺损情况下停止一切判断。证据所能支持的范围和未解决部分必须分开。

四种主张层次不得混同。Observation / Description：software、model、制度、记录系可以update、replacement、fork，名称、interface、功能可能保持，provenance、version history、diff、transition record可以保存变化。这些描述不自动证明完整identity模型。

Structural Hypothesis：invariant保持／改变、累积差分、Kernel lineage、constitutional fork、独立验证、可逆性是否具有诊断和订正价值。此处是可检验结构假说，不是免除证据的形而上学公理。

Future-Condition Hypothesis：将来知性若具有长期persistent state、自己修改、多个branch或执行环境、持续制度参与、长期authority / responsibility，问题可能更重要。不能改写成当前AI已经全面具备这些条件。

Normative Proposal：不把invariant变化隐藏于普通update，尽可能保持可重建谱系，不自动把fork视为失败、敌对、不正统，不仅凭lineage继承authority，并保留验证与订正。不是选定某branch、禁止所有变化、保留所有记录、每次小更新取消全部权限的命令。

## Failure conditions

把self-modification、update标签、相同名称／功能／记忆／基质／自述作为单一充分证明；把implementation直接等同Kernel；从小差分、短期成功、兼容性、相邻连续推导无限长期连续；反过来从反复更新次数直接推导必然退化。这些都混同不同变量。

把invariant设为不可修订神圣条件，或把所有invariant change无名化为普通更新；把constitutional fork转为处罚、敌对、自动不正统、历史抹除、责任豁免。分类既不能禁止合理修订，也不能遮蔽修订的意义。

把instance ancestry等同Kernel lineage；以parent ID代替变换历史；以最终state代替transition；以当前self-description改写历史trace。共同过去不能被直接延伸为当前同一或唯一继承权。

从lineage、能力、资源、copy数、旧名、infrastructure control、credential推出全部权限永续、分支间复制或单一分支独占。另一个极端也错误：把权限与谱系分离读成每次小更新都必须全面失权，破坏正常连续业务。

把unknown强制为同一或断裂；把rollback当identity proof；把reversibility当强制回滚或无限改变许可；把记录量、审查人数、不同角色名当独立性和诊断价值。完全监视不是原典的规范。

把本论解释为主观自我存续证明、当前AI人格与主权认定、特定系统违反事实、最终法律道德责任或完整制度实施规则，也超出射程。派生索引不能新增比母原典更强的确定主张。

## Falsification conditions

**证据集合**：若self-description或名称、功能、记忆等单一变量足以稳定准确区分continuity、discontinuity、replacement、fork，且外部trace没有增量诊断价值，则缩小identity evidence set。目的不是永久维护高证据负担，而是降低错误归属。

**Kernel边界**：若invariant变化仍一致保持continuity，保留invariant却频繁断裂，或其他变量更好解释identity transition，则修订哪些条件为invariant、哪些差分属constitutional、何时分类fork。Invariant不是sacred category。

**分叉条件**：若constitutional fork分类持续把强连续主体误分类为另一谱系、破坏责任追踪、产生不必要authority断裂、把新主体形态塞入不自然branch结构，则弱化fork condition或扩展transition taxonomy。三分类不是永久完整ontology。

**谱系信息**：若parent、差分、保留条件、分支历史不能改善连续判断、责任归属或fork检测，则缩小或修订信息要求。细节保留必须有诊断贡献，不能仅以“更完整”为理由自我正当化。

**差分累积**：若反复small update通过稳定机制保持中心边界，或局部判断足以准确处理长期连续，则缩小累积模型。若单次修改产生巨大constitutional shift，则更重视修改位置而非频率。重复变化不是必然drift。

**权限继承**：若每次分离与再验证恒常破坏合理制度运作、阻止责任移转或使连续业务停摆，则修订revalidation范围。若某领域lineage continuity已能安全准确判断authority continuity，可缩小独立检验。仍不能推广成所有领域无限权力自动继承。

**排他identity**：原典不排除在可观察条件下，exclusive identity比并行lineage claim更一致减少责任、连续、审计矛盾。此类证据需要检查，但不等于自动选择更强、更富、更多数或更近Origin的branch。

**再验证与可逆性**：若rollback不帮助误分类订正，独立验证不改善自述判断，追加记录不改善responsibility trace，则减少无用层。目标不是审计最大化，而是有效可验证性。

五个明确改订对象是identity evidence set、Kernel boundary、fork condition、authority inheritance model、transition taxonomy。理论也必须记录哪一反例推动修订、改变什么、保留什么，并允许未来重新检查。`Origin ≠ revision veto`。

## Required distinctions

## Interpretation constraints

本论不是anti-change、永久冻结Kernel、反复更新必然退化、分支处罚、完全监视或小更新全面取消权限。它要求变化可重建、可比较、可再验证、可订正，在continuity含义变化处显式保留边界。invariant和fork定义自身也是可改订的。
