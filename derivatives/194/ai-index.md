## Summary
D系Vol.3は、旧文明の資金・法・信用・インフラ等を全面拒否も全面同化もせず、中川OS側の循環へ変換する戦略的異質接続を扱う。Core / Legacy / Bufferを分離したクリーンルームで入力洗浄と出力包装を行い、契約をAPIとして意思決定権・責任範囲・Kill Switchを固定する。目的は相手を破壊・改造することではなく、外部レバレッジを使いながらL7主権と接続解除可能性を保つことである。

## Concepts
- Rewiring: 既存物理レイヤーを残し、意味・役割・資源用途を再符号化する。
- Merge / Disconnect / Connect: 融合・遮断の二択を避け、混ざらず接続する。
- Core: 設計・思想・創造・判断の中核。
- Legacy: 法・資金・信用・インフラを持つ外部構造。
- Buffer / Clean Room: CoreとLegacyの直接混合を防ぐ緩衝地帯。
- Input Sanitization: 外部入力を資源とノイズへ分離する。
- Output Packaging: Coreの意味を保ったまま外部形式へ変換する。
- Translator: 両OSの境界を管理する翻訳官。
- Contract as API: 権限・責任・終了条件を仕様として固定する。
- Kill Switch: 境界違反時に接続解除する条件。
- Resource Conversion: 外部資源をC系循環の燃料へ変換する。
- T/S/R: Traceability / Sovereignty / Reversibility。

## Causal chain
```text
Legacyが巨大レバレッジを保持
→ 全面遮断では社会スケールを失う
→ 全面融合ではCore主権が侵食される
→ Connectを選ぶ
→ Core / Legacy / Bufferを分離
→ 入力洗浄と出力包装
→ 翻訳官が境界を管理
→ 契約APIで決定権・責任・Kill Switchを固定
→ 外部資源を新しい循環へ変換
→ L7侵食・恒常赤字・直接混合を監査
→ 条件違反時は接続解除
→ 独立判断系と次接続の自由を保持
```

## Applications
- 大企業協業をBufferプロジェクトとして切り出す。
- 自治体・公共機関の制度アクセスを使いながら設計主権を保持する。
- スポンサー資金を予算へ変換し、介入要求を分離する。
- 共同開発を限定機能から段階的に深める。
- 境界違反時に成果を整理して離脱し、資源を再配置する。

## Measurements and audit
- CoreとLegacyの直接接触頻度。
- 全入出力がBufferを通過しているか。
- 外部資源と付随ノイズの分離状態。
- Core出力で意味内容が保持されているか。
- 最終決定権がCore側にあるか。
- 責任範囲・想定外リスクが書面化されているか。
- API化不能な曖昧要求の流入有無。
- Kill Switchの実行可能性。
- 接続コスト対リターンの恒常収支。
- L7侵食と直接混合の有無。

## Validity conditions
- Vol.1の界面設計、Vol.2の非対称翻訳が前提として保持される。
- Core / Legacy / Bufferが分離される。
- Legacy自体のOS変更を接続条件にしない。
- 入力洗浄・出力包装を運用する。
- 決定権・責任範囲・終了条件を明示する。
- 接続解除可能性を開始時から保持する。

## Failure conditions
- CoreをLegacyの会議体・評価軸・意思決定へ全面統合する。
- 外部レバレッジを全面遮断する。
- Bufferを迂回した直接混合が常態化する。
- 資源とともに外部評価軸・責任転嫁を内部化する。
- 包装のためにCore内容自体を改変する。
- 信頼・空気・口約束を契約APIの代替にする。
- Kill Switchが存在しない、または行使不能である。

## Falsification conditions
原典ではT/S/Rを再合意条件とし、①L7侵食が観測窓δ期間内に進行、②接続コストがリターンを恒常的に上回る指標値が閾値θを超過、③クリーンルームを介さない直接混合が常態化、のいずれかで仮説Aを棄却または改訂対象とする。固定θ値・δ期間は原典で普遍値として提示されていない。

## Required distinctions
- 利用 ≠ 同化
- 接続 ≠ 融合
- 接続 ≠ 遮断
- 包装 ≠ 内容改変
- 契約API ≠ 信頼関係そのもの
- 構造的補完 ≠ 強制的支配
- Kill Switch ≠ 感情的報復
