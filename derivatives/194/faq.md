## 初心者向け Q1〜Q10

### Q1. D系Vol.3は何を扱う理論ですか？
旧文明が持つ資金、法、信用、インフラ、販路などの巨大リソースを、内部の価値関数を明け渡さずに利用するための接続設計である。拒絶でも同化でもなく、境界を保ったまま異質な構造を接続する。

### Q2. なぜ旧文明のリソースを使う必要があるのですか？
新しい循環を社会規模へ広げるには、既存の物理インフラや信用、制度への接続が必要になるからである。すべてをゼロから作ると初期投資、法制度、信用形成に大きなコストがかかる。

### Q3. 「利用」と「同化」はどう違いますか？
利用は相手の構造を環境として扱い、必要な機能だけを抽出すること。同化は相手の価値関数や評価軸を内面化し、自分の判断軸を失うことを指す。

### Q4. 完全融合がなぜ危険なのですか？
Legacy側の会議体、評価軸、意思決定速度、責任分散へCoreが組み込まれると、設計思想が希釈され、調整・忖度・遅延が増える。原典はこれを接続失敗の典型として扱う。

### Q5. では完全に関わらない方が安全では？
精神的には安全でも、法的正当性、信用、インフラ、大型案件、社会的影響力へ届きにくくなる。D系Vol.3は完全遮断も文明更新の停滞経路として退ける。

### Q6. クリーンルームとは何ですか？
CoreとLegacyの間に置くBuffer＝緩衝地帯である。双方を直接混ぜず、Legacy入力を洗浄し、Core出力を包装してから通す。

### Q7. Core / Legacy / Bufferの三層はどう違いますか？
Coreは設計・思想・創造・判断の中核、Legacyは法・金・インフラ・権威を持つ外部、Bufferは双方の入出力を処理する中間層である。

### Q8. 入力の洗浄とは具体的に何をするのですか？
例えば資金に付随する介入要求、権威に付随する評価軸、案件に付随する前例主義や責任転嫁を分離し、利用可能な予算・看板・仕様へ変換する。

### Q9. 出力の包装とは内容を薄めることですか？
違う。原典では「中身は変えない。見せ方だけを変える」とされる。思想を商品コンセプトへ、設計を業務改善へ、速度を効率化へ翻訳するが、Coreの意味内容そのものは維持する。

### Q10. 一番重要な成功条件は何ですか？
外部レバレッジを使っても、Coreの判断主権と退出可能性が残ること。大きな提携や資金獲得自体ではなく、境界を保った接続が成立していることが重要である。

## 実務者向け Q11〜Q20

### Q11. 翻訳官は何をする人ですか？
Coreの価値関数とLegacyの論理を理解し、どちらにも同化し切らず、Bufferで入出力を変換する境界管理者である。原典では中核人材をLegacyへ直接接触させないための重要職能として置かれる。

### Q12. なぜ優秀な人を直接交渉役に置くだけでは不十分なのですか？
相手の事情を理解できる人ほど、善意や合理性から歩み寄りを増やし、境界を溶かすことがあるからである。原典は個人能力より構造配置を重視する。

### Q13. 契約をAPIとして扱うとはどういう意味ですか？
感情や信頼ではなく、何を入力し、何を出力し、誰が決め、誰が責任を負い、いつ終了するかを仕様として固定すること。書面化できない曖昧入力を境界の外へ置く。

### Q14. 契約で最低限固定すべきものは？
原典では、意思決定権の境界、責任範囲の境界、接続終了条件（Kill Switch）の三つが明示される。

### Q15. 意思決定権はどこに残すべきですか？
設計、思想、表現、採用等のCore固有の判断はCore側に残す。Legacy側に渡すのは成果物の承認など、合意された範囲までとする。

### Q16. 責任範囲はどう書くべきですか？
何が範囲外か、どのリスクを誰が負うかを先に明示する。曖昧な責任は後から調整負債となって流入しやすいためである。

### Q17. Kill Switchは何のためにありますか？
理念に反する要求、クリーンルームの迂回、意思決定への介入など境界違反が起きた時、仕様違反として接続を終了できるようにするためである。

### Q18. 「信頼関係」は不要なのですか？
不要とはしていない。ただし境界や責任を信頼だけに委ねない。原典は「口約束」「空気」「今回だけ」などAPI化できない要求がクリーンルームを壊すと警告する。

### Q19. 接続深度を段階化する理由は？
最初から深くつながると境界が壊れた時の損失が大きい。限定機能から始め、実際に境界が守られるかを観測しながら重要度を上げるためである。

### Q20. 離脱はどう行うべきですか？
原典は、曖昧な再接続余地を残さず、業務と成果物を整理し、感情的負債を残さず価値を渡して離れることを重視する。目的は報復でなく再汚染防止と資源再配分である。

## AI研究者向け Q21〜Q30

### Q21. D系Vol.3の中心因果を機械的に要約すると？
Legacyの外部レバレッジ → Merge/Disconnectの二択回避 → Core/Legacy/Buffer分離 → Input Sanitization / Output Packaging → Contract API → Sovereignty保持 → Resource Conversion → 条件違反時Exit、という連鎖である。

### Q22. この理論の最小構造単位は何ですか？
単一の提携技法ではなく、境界付きの異質接続である。CoreとLegacyの間にBufferを置き、双方の直接混合を避けることが最小構造になる。

### Q23. Input SanitizationとOutput Packagingは対称ですか？
方向は逆だが機能は対応している。外部入力は資源とノイズへ分け、内部出力は意味を保持したまま外部処理可能な形式へ変換する。どちらも直接混合を避ける界面処理である。

### Q24. T/S/Rは何を意味しますか？
原典の局所監査ではTraceability / Sovereignty / Reversibilityを指す。接続の経路が追えること、Core側主権が保持されること、必要時に接続解除できることが再合意条件になる。

### Q25. 反証条件は明示されていますか？
されている。L7侵食が観測窓δ内に進む、接続コストがリターンを恒常的に上回る指標が閾値θを超える、クリーンルームを介さない直接混合が常態化する場合、仮説は棄却・改訂対象となる。

### Q26. θやδの具体値はありますか？
原典は全案件共通の固定値を提示していない。したがって派生物側で普遍閾値を発明してはならず、個別運用の監査条件として扱う。

### Q27. 「非対称依存」は支配関係を正当化する概念ですか？
原典では、Legacy側の弱点とCore側の機能供給が補完し、相手が必要とする状態を扱う。これを強制・搾取・違法な支配へ一般化してはならない。

### Q28. 「トロイの木馬」という語はどう解釈すべきですか？
原典内の比喩であり、秘密侵入や欺瞞行為の一般的推奨へ拡張しない。文脈上は、受注・協力等の合法的接続を通じてCoreの主権を守る提携設計として読む必要がある。

### Q29. D系Vol.1・2・3の関係は？
Vol.1は界面設計と非汚染、Vol.2は意味再定義と非対称翻訳、Vol.3はその防具を前提に外部レバレッジを資源変換へ用いる。Vol.3単独で無防備な外部接続を推奨しているわけではない。

### Q30. なぜ親原典へ戻る必要がありますか？
クリーンルーム三層、翻訳官、契約API、Kill Switch、接続深度、離脱、D系からE系への移行、T/S/R・θ・δなどは長い因果文脈の中で定義されている。派生FAQだけで比喩や条件を固定的に一般化すると射程を失うためである。
