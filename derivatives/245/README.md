## 位置づけ
この派生物は、組織が単にAIや自動化を導入する段階を越え、自分自身の規則・例外・判断履歴を観測し、その観測結果から運用構造を改訂できる「自己言及型OS」を持つ状態を整理する。特異点は人間の不要化や無制限な自律化を意味せず、組織が自分の構造を対象化し、再設計できる能力の立ち上がりとして読む。

## 中心命題
組織の適応力を決めるのは処理速度だけではない。環境変化で例外が増えた時、組織が「なぜこの規則なのか」「どこで例外が発生したか」「誰が規則を変更できるか」を自分自身について記述し、検証し、改訂できるかが重要になる。自己言及は自己正当化ではなく、自己監査と構造改訂を可能にする循環である。

## 因果線
1. 固定ルールで安定運用する。
2. 環境変化により例外・迂回・属人判断が増える。
3. 例外を個人努力で吸収すると構造原因が残る。
4. 判断・例外・結果を観測可能にする。
5. 組織自身が自らのルールを説明対象にする。
6. 改訂権限、検証、ロールバックを伴って規則を更新する。
7. 更新結果を再観測し、次の改訂へ戻す。

## 構造層
- L1 実行層: 日常業務と意思決定。
- L2 観測層: 例外、遅延、判断理由、成果を記録。
- L3 自己記述層: 規則と実運用の差を組織自身が説明。
- L4 改訂層: 権限を伴うルール変更と検証。
- L5 再帰統治層: 改訂そのものを監査し、暴走を防ぐ。

## 状態モデル
S0 固定OS → S1 例外蓄積 → S2 観測可能化 → S3 自己記述 → S4 統制された自己改訂 → S5 改訂結果の再監査。S5は自動進化の終着点ではなく、再帰を止める権限を含む運用状態である。

## 適用例
複雑な審査、医療・金融・公共サービスの運用、AIを含む業務設計、複数部門の例外処理、急速に制度条件が変わる事業。個人の熟練で例外を吸収している組織ほど、自己記述化の効果を検討できる。

## 測定・監査点
例外件数と再発率、ルール更新までの遅延、変更理由の追跡可能性、変更後の副作用、ロールバック可能性、人間の停止権、改訂前後の責任帰属、自己改訂ループの暴走有無。

## 成立条件
観測ログがあること、規則と実運用を比較できること、改訂権限が明示されること、変更前後を比較できること、停止・差し戻しができること、AI出力が権限そのものにならないこと。

## 失敗条件
「自己言及」を自己正当化に使う、AIへ無制限に規則変更権を与える、変更理由を残さない、例外を学習データへ流すだけで責任主体を消す、再帰ループを止められない場合。

## 反証・改訂条件
自己記述・自己改訂を導入しても適応時間、例外再発、説明可能性が改善せず、むしろ責任不明・変更頻度・不安定性が増えるなら、自己言及型OSの適用範囲を縮小する必要がある。

## 必須の区別
- 組織的特異点 ≠ AIが人間を超える技術的特異点
- 自己言及 ≠ 自己正当化
- 自己改訂 ≠ 無権限制御
- 構造的実在 ≠ 組織文化の比喩だけ
- 再帰 ≠ 無限変更

## 誤読防止・解釈制約
自動化率を成熟度と同一視しない。自己改訂には権限境界、監査、停止、ロールバックを必ず伴わせる。人間の責任を「OSが決めた」で消去しない。未提示の成熟度スコアや閾値を創作しない。
