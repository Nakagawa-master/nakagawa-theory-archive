## 位置づけ
Parentは、現在の便利さ・効率・速度を得る設計が、将来の選択肢、撤回可能性、保守能力、説明可能性を削るとき、その差分を「未来債務」として読む。債務は金銭だけではなく、将来世代や将来の組織が引き受ける修正負荷・ロックイン・依存・失われた選択肢を含む。

## 中心命題
**現在価値を最大化するだけでは、未来の自由を守れない。便利さを得るたびに撤回経路、代替手段、保守知、責任境界が消えるなら、現在の便益は未来の修正コストとして鋳造される。したがって設計は、今の効率と同時に、将来が別の判断へ移れる可逆性と選択肢を資産として残さなければならない。**

## 主要因果線
便利さ・速度を優先→依存先を集約→代替経路と保守知が減る→変更の影響範囲が広がる→撤回コストが上昇→将来の主体が過去の決定を引き受ける→選択肢が減る→さらに既存構造への依存が強化→未来債務が複利的に蓄積→小さな障害でも大きな修正負荷→現在便益と将来自由の両方を監査→可逆性・代替・知識継承を残すことで債務鋳造を抑える。

## 構造層
### 1. 現在便益
速度、低コスト、自動化、統合、標準化など今得られる価値を明示する。
### 2. 依存
単一ベンダー、単一技能、単一データ形式、単一制度など依存集中を可視化する。
### 3. 選択肢
代替経路、移行可能性、互換性、撤回単位を未来資産として扱う。
### 4. 保守知
誰が、なぜ、どう直せるかという知識を残す。
### 5. 時間移転
現在の決定コストが将来の修正負荷へ移されていないかを見る。
### 6. 可逆性
段階導入、差分rollback、期限、再審査によって固定化を抑える。


## 適用例
AI自動化ではモデルやベンダーを交換できる境界を残す。業務システム統合ではデータ移行経路と旧仕様の読解可能性を残す。公共制度では期限付き導入と再審査を設ける。人材配置では一人しか分からない保守知を分散する。

## 測定・監査点
撤回コスト、移行時間、代替数、依存集中、互換性、保守知の再現性、担当交代時の摩擦、再審査可能性、ロックイン、将来負担の所在を束で見る。現在のROIだけで健全性を確定しない。

## 成立条件
現在便益と将来負担を同じ図面で見る。代替を残す。保守知を継承する。差分rollbackを可能にする。将来主体の選択権を考慮する。期限と再審査を設計する。

## 失敗条件
便利さだけを評価する。依存集中を無視する。移行経路を消す。保守知を属人化する。将来負担を見えない外部性として扱う。不可逆化を効率化と呼ぶ。

## 反証・改訂条件
可逆性や代替を残しても将来修正負荷が減らない、代替維持コストが便益を恒常的に上回る、想定した依存が実際の障害原因でない場合は債務モデルと設計粒度を改訂する。

## 必須の区別
便利さ / 自由; 効率 / 可逆性; 標準化 / ロックイン; 統合 / 単一障害点; 技術的負債 / 未来債務全体; 保守 / 延命; 選択肢 / 冗長浪費。

## 誤読防止・解釈制約
便利さや技術進歩を否定する理論ではない。すべての依存を排除することも求めない。将来債務は公開されていない固定スコアではなく、現在便益と将来の撤回・移行・保守負荷を同時に見る監査概念として扱う。
