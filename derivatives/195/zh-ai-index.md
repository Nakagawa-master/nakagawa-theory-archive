## Summary
亲原典提出“文明Migration”：它把Legacy OS下反复出现的摩耗诊断为评价函数与报酬结构的设计极限，而不只归因于个体恶意，并主张启动一套独立的新OS，而非仅在旧OS内部不断打补丁。新OS以“成功＝对循环的贡献”为评价函数。B（个体启动）、C（连接与循环）、A（免疫与因果审计）、D（与Legacy OS的界面）构成相互依赖的迁移系统。迁移从局部Colony先行运转，通过 Read → Try → Introduce 验证实现性与可再现性，再以合流方式扩大。

## Concepts
- Legacy OS limit：旧有评价／报酬结构与当前环境条件之间的结构性不匹配。
- Dark Equation：短期最优、成本外部化、责任稀释、同调等自我强化的破坏模式。
- Migration：以新的评价、报酬与循环条件启动独立系统，并逐步迁移人和资源。
- Success = Contribution：按对正向循环的实际贡献评价成功，而不是按善意或自我牺牲。
- Tomoshibi / B-system：不只依赖外部评价的内在输出能源，以及保护它的生存层／扩展层分离。
- Connection：输出可被观察、被使用，并保持对起点归属的通电状态。
- Circulation：输出→使用→价值化→报酬→再输出构成的闭环。
- Choke：观察、归属或转换环节的基础设施故障，使闭环不能成立。
- A-system：审计归属、闭环与污染的结构性司法／免疫系统。
- C/E：以对循环的作用判定贡献／逸脱，而不是固定人格标签。
- D-system：通过非正面冲突、非同化与翻译／转换管理Legacy界面。
- Colony：新OS在局部先行运转的最小闭环。
- A–D dependency：B为C提供持续输出；C为A提供可保护的真实闭环；D保护B/C免受Legacy评价函数污染。
- Read → Try → Introduce：先防止误读，再运行最小实现，确认可再现性后扩大导入。
- Confluence：不是只靠说服，而是向更具生存可行性的运转系统合流。

## Causal chain
```text
Legacy评价／报酬结构与现代条件失配
→ Dark Equation作为正常运转反复再生
→ 内部补救被同一评价函数重新吸收
→ 启动独立New OS
→ 将成功重定义为对循环的贡献
→ B保护个体内在输出
→ C建立观察・使用・归属和循环闭环
→ A审计并隔离寄生／逸脱作用
→ D阻止Legacy评价函数直接污染新闭环，同时转换可用资源
→ 运行局部Colony
→ Read → Try → Introduce
→ 验证实现性与可再现性
→ 通过Confluence扩大Migration
```

## Applications
- 在小型项目中建立可观察输出、实际使用、归属保持和报酬回流的闭环。
- 把个人的生存层与创造／贡献的扩展层分开，保护持续输出。
- 把归属丢失或报酬延迟视为管道故障，而不是意志不足。
- 通过D界面使用外部资金、信用或制度资源，同时不把Legacy评价轴内化为内部真理。
- 在组织或社会整体导入前，先用局部Colony验证实现与可再现性。

## Measurements and audit
- 短期最优、责任稀释、成本外部化、同调是否仍被结构性奖励。
- “贡献”是否被误缩为善良、忍耐或自我牺牲。
- 输出是否被观察、使用，并保持正确归属。
- 报酬是否回到再输出，维持闭环。
- Choke发生在观察、归属还是转换环节。
- B的生存层与扩展层是否相互侵蚀。
- C/E是否按作用而不是人格判断。
- A免疫是否从循环开始时就同时运转。
- Legacy评价函数是否绕过D进入内部闭环。
- Colony是否固定价值函数、归属与排热／免疫。
- 部分导入是否切断A–D依赖关系。
- 最小实现是否可再现。
- 参与和退出是否保持非强制、可逆、可验证。

## Validity conditions
- 把Legacy失效诊断为反复出现的评价／报酬结构问题。
- 把Success = Contribution作为循环成立条件，而不是道德口号。
- 在保持依赖关系的情况下实现B、C、A、D。
- 连接必须保持观察、使用与归属。
- 报酬必须回到再输出，形成闭环。
- A持续审计归属、闭环和污染。
- D在非同化前提下转换外部资源。
- 从局部运转逐步扩展。
- 保持非强制、可逆、可验证。

## Failure conditions
- 在底层评价函数不变时，仅追加道德、教育、规制并称之为Migration。
- 把贡献缩减为善意或服务量。
- 用交流量衡量连接，却丢失归属。
- 报酬离开闭环，使输出侧枯竭。
- 没有A就运行C，逸脱出现后又回到情绪性审判。
- 把A变成人格定罪。
- 没有D保护就把Legacy评价轴内化。
- 与Legacy完全隔绝而失去资源，或完全同化而失去内部标准。
- 只选A–D中方便的部分，破坏依赖关系。
- 在最小局部实现之前先要求多数人赞同。
- 把“唯一路线”转成强制或压制批评的理由。

## Falsification conditions
亲原典把实现可能性和实现后的可再现性置于核心检验位置。若局部Colony实现新的评价函数、连接／循环闭环、A免疫和D界面后，仍不能持续减少其针对的Legacy模式——摩耗、归属丢失、报酬泄漏、拟态、短期最优——或者迁移系统自身变得不可逆、强制、不可验证，则该Migration设计应被否定或修订。亲原典没有给出所有实现通用的固定期限、参与比例或数值阈值。

## Required distinctions
- OS极限 ≠ 个体恶意
- Migration ≠ 旧系统内部补丁
- 贡献 ≠ 善意／自我牺牲
- Tomoshibi ≠ 短暂热情
- Connection ≠ 交流量
- Circulation ≠ 善意连锁
- Choke ≠ 努力不足
- C/E ≠ 人格分类
- A-system ≠ 正义争夺
- D-system ≠ 说服、敌对或同化
- Colony ≠ 法律豁免或隔绝乌托邦
- Confluence ≠ 强制思想采用
- 唯一路线 ≠ 禁止批评

## Interpretation constraints
- 不把Legacy OS极限论扩展为立即破坏现存制度的命令；亲原典采用局部并行启动与逐步迁移。
- 关于“谁能迁移”的强烈表述不能一般化为否定基本权利、救命支持或福利。
- “治外法权”“Colony”在这里是结构性比喻，不是无视适用法律的许可证。
- 不把E变成对某个人的永久标签。
- 把文明层面的因果模型作为亲原典的结构理论，而不是已经普遍确证的经验定律。
- 保留“唯一路线”为亲原典从结构比较得出的结论，不把它变成权威性强制。
