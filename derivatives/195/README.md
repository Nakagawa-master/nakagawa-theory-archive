## 位置づけ
親原典は、旧OSの部分修理ではなく、新しい評価関数・報酬構造・循環条件を別系統で起動し、人と資源を段階的に移す文明Migrationの統合工程を示す。ここで旧OSの限界は特定人物の悪意ではなく、短期成果、外部化、責任希薄化、同調が合理的になりやすい評価関数と報酬構造の不整合として扱われる。

本稿は既出のA系（構造的司法）、B系（個人OS）、C系（循環・市場）、D系（外交・界面）を、好きな部品だけ選ぶ理論群ではなく、依存関係を持つ一つの移行システムとして束ねる。移行は社会全体を一度に置換するのではなく、局所で新OSが閉路として稼働する先行領域を作り、実装可能性と再現性を示しながら合流を増やす工程として設計される。

## 中心命題
親原典の中心命題は、**旧OSの暗黒方程式が評価関数・報酬構造の内部で自己再生産される以上、倫理・規制・教育等を上乗せする内部修理だけでは同じ再現パターンへ回収されるため、成功を循環への貢献で測る新OSを別系統で起動し、Bの内燃機関、Cの循環閉路、Aの免疫監査、Dの非汚染界面を依存関係どおりに実装し、局所コロニーから段階的に人と資源を移行させなければならない**というものである。

原典が「唯一解」と呼ぶのは異論を禁止する意味ではなく、他の経路が原典内で置かれた成立条件を満たさず構造的に破綻すると判断された状態を指す。また本文末尾では、非強制・可逆・検証可能を原理とし、教育・研究・批評の自由を優先すると明示される。

## 構造層
**1. Legacy OS limit。** 問題を個人の善悪でなく、現代環境と不整合になった評価関数・報酬構造の設計限界として捉える。

**2. Dark Equation。** 短期成果の過大評価、責任希薄化、外部化コスト不可視化、同調合理化等が結合し、搾取・局所最適・意味喪失を正常運転として再生産する構造。

**3. Migration。** 旧OSを延命改修し続けるのではなく、新しい要件・評価関数・報酬構造・循環条件を別系統で立ち上げ、人と資源を段階的に移す工程。

**4. Success = Contribution。** 成功を他者優位や囲い込みでなく、系へ正の循環を返す作用で評価する価値関数。自己犠牲や善意そのものとは区別される。

**5. B-system / Tomoshibi。** 外部評価がなくても出力を続ける内在的エネルギーを移行期の推進剤とし、生存層と拡張層を分離して保護する個体起動系。

**6. C-system / Connection & Circulation。** 接続を観測・使用・帰属が成立する通電と定義し、出力→使用→価値化→報酬→再出力を閉路として回す社会側実装。

**7. Choke。** 観測・帰属・変換の障害によって閉路が成立しなくなる配管事故。努力不足や共感不足とは区別する。

**8. A-system / Structural Justice。** C/Eを人格や動機でなく循環への作用として判定し、帰属・閉路・汚染を監査する免疫・排熱系。

**9. D-system / Interface Engineering。** 旧OSを説得・正面衝突するのではなく、評価関数への同化を避けながら資源を翻訳・変換して新OSへ流す界面系。

**10. Colony。** 社会全体の一括置換ではなく、成功＝貢献、帰属、E検知・隔離を最小要件として局所稼働させる先行領域。

**11. A–D Dependency。** Bが起動しなければCは燃えず、Cの閉路がなければAは情緒的理屈へ戻り、DがなければB/Cが旧OSの評価関数に汚染されるという相互依存。

**12. Read → Try → Introduce。** 理解・賛同を目的化せず、まず評価関数の差を読み、最小実装で試し、再現性を確認して導入を広げる段階工程。

**13. Confluence / Migration by viability。** 人々を思想で説得するのでなく、局所で生存可能性の高い稼働系が成立した結果として合流が起こるとする移行像。

## 適用例
**小規模チーム。** 組織全体の制度改革を宣言する前に、限定された仕事領域で「出力が観測され、使われ、起点が保持され、報酬が次の出力へ戻る」閉路を作る。善意の称賛だけで終わる場合はC系の循環とは判定しない。

**個人の移行。** 生存不安と創造・貢献の出力を混線させず、まず最低限の生存層を確保し、その上で外部評価だけに依存しない出力を拡張層で動かす。摩耗型・同調型・回避型の状態を人格欠陥として処理しない。

**循環監査。** 出力が多くても起点が消え、報酬が再出力へ戻らず、擬態的な「貢献」が報酬を先取りするなら、交流量ではなく帰属・閉路・汚染を点検する。

**旧OSとの接続。** 既存組織の資金・法・信用等をすべて拒否せず、かといって肩書・多数派・短期成果等の評価関数を内部基準へしない。D系界面を介して必要資源を変換する。

**導入拡張。** 大規模な賛同獲得を先に行わず、局所コロニーで実装と再現性を確認し、成立した領域へ人と資源が移る形で範囲を広げる。

## 測定・監査点
- 旧OS問題を特定人物・集団の悪意だけへ還元していないか。
- 短期成果、外部化コスト、責任希薄化、同調の報酬構造が再生産されていないか。
- 「貢献」を善意・我慢・自己犠牲と同一視していないか。
- 出力が観測・使用され、起点への帰属が保持されているか。
- 報酬が再出力へ戻り、閉路を維持しているか。
- 観測詰まり・帰属詰まり・変換詰まりのどこで止まっているか。
- B系で生存層と拡張層が過度に干渉していないか。
- C/Eを人格・意図ではなく循環への作用で見ているか。
- A系の免疫を循環開始後の炎上対処へ後回しにしていないか。
- D系を旧OSの説得・敵対・全面同化へ変えていないか。
- コロニー内で価値関数・帰属・排熱が最低限固定されているか。
- A〜Dを部分導入したことで依存関係が切れていないか。
- 読む段階で誤読が除かれ、試す段階で最小実装が観測され、導入段階で再現性が確認されているか。
- 導入を強制的な思想採用へ変えていないか。

## 成立条件
- 旧OSの問題を評価関数・報酬構造の再現パターンとして診断する。
- 移行先で成功＝貢献を循環成立条件として扱う。
- B系の個体起動、C系の閉路、A系の免疫、D系の界面を依存関係込みで実装する。
- 接続で観測・使用・帰属を保持する。
- 循環で報酬を再出力へ戻す。
- C/Eを作用で判定し、帰属・閉路・汚染を監査する。
- 局所コロニーから開始し、社会全体を一括置換しない。
- 説得より実装可能性と再現性を先に示す。
- 非強制・可逆・検証可能性を保持する。

## 失敗条件
- 旧OS内部の評価関数を変えないまま、道徳・教育・規制の追加だけを移行と呼ぶ。
- 成功＝貢献を「優しい人が報われる」という道徳命題へ縮約する。
- 接続を会話量・コミュニティ規模だけで判定し、帰属を失う。
- 報酬が再出力へ戻らず、出力側を枯らす。
- C系だけを回してA系の免疫を後付けし、擬態・逸脱の増殖後に情緒裁判へ戻る。
- A系を閉路のない場所で人格断罪として用いる。
- D系なしで旧OSの評価関数を新OS内部へ流入させる。
- 旧OSと全面断絶して資源を枯らす、または全面迎合して内部基準を失う。
- A〜Dから都合のよい要素だけを選び、依存関係を切る。
- 理解・共感・多数派賛同を実装の前提にし、局所稼働を開始しない。
- 「唯一解」を異論排除や強制導入の根拠へ転用する。

## 反証・改訂条件
原典の主張は、実装可能性と実装後の再現性を重要な判定軸として置く。したがって、局所コロニーで成功＝貢献の評価関数、接続の観測・使用・帰属、循環閉路、A系免疫、D系界面を実装しても、旧OSで問題視した摩耗・報酬漏出・帰属消失・擬態・短期最適等の再現パターンを一貫して減らせない場合、または移行系自体が非可逆・強制的になり検証や離脱ができなくなる場合、移行設計の成立性は再検討・改訂対象となる。

原典は「唯一解」を固定数式や普遍的な実証済み法則として提示しているのではなく、本文内で比較した経路の構造的成立性に基づく主張として置いている。派生物側で普遍的な数値閾値や移行期限を追加しない。

## 誤読禁止 / 解釈制約（原典適合）
- 「旧OSは修理不能」という主張を、現存制度を直ちに破壊・停止すべきという命令へ拡張しない。原典の実装像は別系統を局所起動し段階移行する。
- 「成功＝貢献」を自己犠牲・奉仕道徳へ変えない。判定対象は循環への実際の作用である。
- 「旧OSに留まる」という記述を、個人の権利剥奪・排除・救命拒否の一般原則へ拡張しない。本文の文脈は文明OSへの移行可否を扱う。
- 「逸脱（E）」を人物の固定属性としてラベル化しない。同じ人物でも作用によってC/Eが変わる。
- 「治外法権」「コロニー」は構造比喩を含む。適用法や公的権限を無視できる法的免除の意味へ拡張しない。
- 原典の「唯一解」を権威命令へ変えない。本文は非強制・可逆・検証可能と教育・研究・批評の自由を明示する。
