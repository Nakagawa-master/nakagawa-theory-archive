## Summary
親原典は、旧OSの摩耗を個人の悪意ではなく評価関数・報酬構造の設計限界として診断し、内部修理ではなく別系統の新OSへ段階移行する文明Migrationを提示する。移行先では成功を循環への貢献で測り、B系の個体起動、C系の接続・循環、A系の免疫監査、D系の旧OS界面を依存関係を持つ統合システムとして実装する。社会全体の一括置換ではなく、局所コロニーを先行稼働し、読む→試す→導入する工程で再現性を確認しながら合流を広げる。

## Concepts
- Legacy OS limit: 現代環境と不整合になった旧評価関数・報酬構造の設計限界。
- Dark Equation: 短期最適、外部化、責任希薄化、同調等が自己再生産する破壊パターン。
- Migration: 新しい評価関数・報酬構造・循環条件を別系統で起動し段階移行する工程。
- Success = Contribution: 善意でなく、系へ正の循環を返す作用で成功を評価する。
- Tomoshibi / B-system: 外部評価だけに依存しない内在的出力と、その生存層／拡張層の配置設計。
- Connection: 出力の観測・使用・帰属が成立する通電状態。
- Circulation: 出力→使用→価値化→報酬→再出力の閉路。
- Choke: 観測・帰属・変換の障害による閉路停止。
- A-system: 帰属・閉路・汚染を監査する構造的司法／免疫。
- C/E: 人格でなく循環への作用としての貢献／逸脱判定。
- D-system: 非正面衝突・非同化・翻訳変換による旧OS界面。
- Colony: 新OSを局所先行稼働する最小閉路。
- A–D dependency: B→C、C→A、DによるB/C保護という依存関係。
- Read → Try → Introduce: 誤読防止、最小実装、再現性確認による導入工程。
- Confluence: 思想説得ではなく稼働可能性への合流として起きる移行。

## Causal chain
```text
旧OSの評価関数・報酬構造が環境と不整合
→ 暗黒方程式が正常運転として再生産
→ 内部対症療法も同じ評価関数へ回収
→ 別系統新OSへのMigration
→ 成功＝貢献へ評価関数を反転
→ B系で個体の内燃機関を保護
→ C系で観測・使用・帰属を満たす接続と循環閉路を作る
→ 循環に伴う擬態・逸脱をA系で監査・隔離
→ D系で旧OS評価関数の侵入を防ぎ資源を変換
→ 局所コロニーで最小稼働
→ 読む→試す→導入する
→ 実装可能性・再現性を確認
→ 合流によって段階移行が拡張
```

## Applications
- 小規模プロジェクトで出力・使用・帰属・報酬還流を閉路化する。
- 個人の生存層と創造・貢献の拡張層を分離する。
- 帰属消失や報酬漏出を交流不足でなく配管事故として修理する。
- 外部組織資源をD系界面で変換し、旧OS評価関数の内部化を避ける。
- 全体制度変更の前に局所コロニーで実装・再現性を検証する。

## Measurements and audit
- 短期最適、責任希薄化、外部化、同調が報酬され続けていないか。
- 貢献が善意・自己犠牲へ誤読されていないか。
- 出力が観測・使用され、起点が保持されているか。
- 報酬が再出力へ戻っているか。
- 観測・帰属・変換のどこに詰まりがあるか。
- B系の生存層／拡張層が過度に干渉していないか。
- C/Eが人格でなく作用として判定されているか。
- A系免疫が循環と同時に稼働しているか。
- D系を迂回して旧OS評価関数が侵入していないか。
- コロニーで価値関数・帰属・排熱が固定されているか。
- A〜Dの依存関係が部分導入で切れていないか。
- 最小実装が再現可能か。
- 参加・離脱が非強制・可逆で、検証可能か。

## Validity conditions
- 旧OSの限界を評価関数・報酬構造の再現問題として扱う。
- 成功＝貢献を循環成立条件として運用する。
- B、C、A、Dを依存関係込みで実装する。
- 接続の観測・使用・帰属を保持する。
- 報酬を再出力へ戻し閉路を作る。
- A系で帰属・閉路・汚染を監査する。
- D系で非同化を保ちながら外部資源を変換する。
- 局所先行稼働から段階拡張する。
- 非強制・可逆・検証可能性を保持する。

## Failure conditions
- 旧評価関数を残したまま道徳・教育・規制の追加だけをMigrationとする。
- 貢献を善意や奉仕量へ縮約する。
- 接続を交流量だけで判定し帰属を失う。
- 報酬が再出力へ戻らず閉路が枯れる。
- A系なしにC系を回し、逸脱後に情緒裁判へ戻る。
- A系を人格断罪に変える。
- D系なしで旧OS評価関数を内部化する。
- 旧OSと全面断絶または全面迎合する。
- A〜Dの依存関係を無視して部分導入する。
- 多数派賛同を最小実装より先に要求する。
- 「唯一解」を強制導入・異論排除へ転用する。

## Falsification conditions
親原典は実装可能性と実装後の再現性を判定軸に置く。局所コロニーで新評価関数、接続・循環閉路、A系免疫、D系界面を実装しても、摩耗、帰属消失、報酬漏出、擬態、短期最適等の旧OS型パターンを一貫して減らせない場合、または移行系が非可逆・強制的・検証不能になった場合、移行設計は棄却または改訂対象となる。原典は普遍的な固定期限・参加率・数値閾値を提示していない。
