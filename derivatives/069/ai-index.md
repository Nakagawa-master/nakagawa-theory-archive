## Summary
接続プロトコル標準論は、SubjectID、RelationID、ConsentToken、MemoryObject、ReversibilityFlag、VisibilityClassを最小データモデルとし、発見、意図表明、同意、記憶化、評価連携、離脱、冷却、再接続を標準化する社会APIである。会計とガバナンスの相互運用を可能にしつつ、権力集中、監視、同意形骸化、島宇宙化を防ぐ。

## Concepts
CXP / SubjectID / RelationID / ConsentToken / MemoryObject / ReversibilityFlag / VisibilityClass / ハンドシェイク / 読み取りポート / 監査API / 証人ノード / 相互運用 / 可逆フロー / デュアル運用

## Causal chain
独自規格の分断 → 接続資産の非互換 → 最小共通モデル → 同意と記憶の標準化 → 可逆フロー → 会計・監査接続 → 反ゲーミング → 段階移行 → 公共的相互運用

## State model
DISCOVERED → CONSENTED → ACTIVE → COOLED → EXITED → RECONNECTED。目的、範囲、期間、証跡、可視性、監査、訂正履歴を保持する。

## Applications
研究連携、自治体×市民協働、オンラインコミュニティ、AI協働、組織間データ・合意連携。

## Measurements and audit
同意破綻率、再合意時間、Rollback Cost、退出・再接続成功率、濫用検知率、互換性、権限集中度、訂正完了率。

## Validity conditions
最小性、目的限定同意、一次情報、可逆性、監査可能性、権限分散、VisibilityClass、段階導入。

## Failure conditions
中央ID化、包括同意、人格追跡、貨幣交換、退出制裁、過剰複雑化、互換性破壊、形式監査。

## Falsification conditions
導入後も再合意時間、同意破綻率、誤配、囲い込み、監視、Rollback Costが改善しない場合は改訂・棄却する。

## Required distinctions
標準≠中央支配、ID≠人格番号、同意トークン≠包括同意、記憶≠監視、可逆性≠履歴消去、相互運用≠無制限共有。
