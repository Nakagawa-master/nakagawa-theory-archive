## 位置づけ
親原典は、接続価値会計と接続ガバナンスを、組織・サービス・AI・地域・制度をまたいで実際に運用するための相互運用標準を扱う。焦点はログインやデータ形式の共通化ではなく、誰が、何の目的で、何に同意し、どの範囲・期限で接続し、どの証拠と責任を持ち、どの条件で停止・撤回・訂正・失効・再接続できるかを一つの接続イベントとして保持することにある。

標準化の目的は、すべてのID・履歴・権限を中央へ集約することではない。異なる制度を移動しても、本人の同意境界、権利、来歴、責任主体、退出可能性が消えず、人間にも機械にも現在状態が理解できることにある。

## 中心命題
**接続社会の相互運用性は、万能IDやデータ共有だけでは成立しない。主体、役割、目的、同意、範囲、期限、証拠、責任、状態、撤回、訂正、監査を一つの接続イベントとして束ね、状態遷移と来歴を人間可読・機械可読の両方で保持し、制度をまたいでも権利と責任を失わず再利用できる標準が必要である。**

## 因果線
```text
制度ごとにID・同意・記録・撤回形式が異なる
→ 同じ主体・合意・権利を別の場で再利用できない
→ 説明・本人確認・再同意・責任確認が反復する
→ 単純なID統合やデータ統合で解決しようとする
→ 目的外利用・同意永久化・来歴断絶・責任消失が起きる
→ 主体・目的・同意・範囲・期限・証拠・責任を接続イベントへ束ねる
→ ACTIVE / PAUSED / WITHDRAWN / CORRECTED / EXPIRED / RECONNECTEDを状態として保持する
→ 撤回・訂正・移植・監査照会・エラー処理を同じ標準へ含める
→ 異なる制度でも権利・来歴・責任・退出可能性を保持して再利用できる
```

## 構造層
**1. 主体・ID層。** 人、組織、AI、代理人、監査者を、役割・権限を伴う文脈依存の識別子として扱う。人格を一つの万能IDへ固定しない。

**2. 目的・同意層。** 接続目的、同意範囲、利用期限、再利用条件、第三者提供条件を明示し、同意を更新・停止・撤回可能な状態として扱う。

**3. 記憶・証拠層。** 合意、変更、履行、異議、訂正、撤回を一次ログとして残し、誰が、いつ、なぜ状態を変えたかを来歴として追跡可能にする。

**4. 状態・可逆層。** ACTIVE、PAUSED、WITHDRAWN、CORRECTED、EXPIRED、RECONNECTEDを区別し、期限切れ権限や実態のない幽霊接続を残さない。

**5. 相互運用層。** 制度間で必要最小限の情報、目的、状態、責任、署名・検証、エラー処理を移植し、無制限共有へ変えない。

**6. 代理権限層。** AIや代理人の権限を対象、操作範囲、上限、期限、停止条件、人間確認へ限定し、代理利用を責任移転へ変えない。

**7. 監査・変更層。** 監査照会、互換性、標準変更、廃止、救済の手続を追跡可能にし、標準準拠を自動的な安全保証へ変えない。

## 適用例
**組織間協働。** 目的、役割、権限、成果利用、秘密情報、終了条件を接続イベントとして保持し、担当者が変わっても合意来歴と責任主体を追跡できるようにする。

**AIエージェント。** 対象業務、操作上限、期限、停止条件、人間確認を伴う代理権限を記録し、別サービスへ移動しても包括権限へ自動拡張しない。

**研究・データ共有。** 利用目的、匿名化、再利用、成果帰属、保存期限、撤回状態を来歴付きで移植し、データだけ移動して同意・責任が失われないようにする。

**行政・市民サービス。** 申請、委任、審査、異議、訂正、救済を状態遷移として追跡し、本人が現在状態、責任部署、次の手続を理解できるようにする。

## 測定・監査点
```yaml
- value: ACTIVE / PAUSED / WITHDRAWN / CORRECTED / EXPIRED / RECONNECTED
  source: 親原典
  measurement_actor: NOT_A_SCORE
  measurement_object: 接続イベントの状態
  source_modality: SOURCE_EXPLICIT_STATE_SET
  permitted_use_scope: 接続の開始・停止・撤回・訂正・失効・再接続の区別
  non_guarantee_scope: 主体の信用点・成熟度順位ではない
- value: 再合意時間 / 説明回数
  source: 親原典
  measurement_actor: 接続を運用・監査する側
  measurement_object: 制度間移行時の説明・再同意摩擦
  source_modality: SOURCE_DEFINED_OBSERVATION_SET
  permitted_use_scope: 相互運用による摩擦低減の検証
  non_guarantee_scope: 短いほど常に良いとは限らず、説明省略や同意弱体化で短縮してはならない
- value: 撤回・訂正・失効の反映遅延 / 幽霊接続・不要権限の残存
  source: 親原典
  measurement_actor: 接続先・監査者・影響当事者
  measurement_object: 可逆性と状態同期の実効性
  source_modality: SOURCE_DEFINED_OPERATIONAL_OBSERVATION
  permitted_use_scope: 撤回・訂正・失効が全接続先へ反映されるかの検証
  non_guarantee_scope: 固定合格値・単独最大化指標ではない
- value: AI・代理人の権限逸脱件数 / 停止時間 / 移植後の目的・来歴・責任保持
  source: 親原典
  measurement_actor: 運営者・監査者・責任主体
  measurement_object: 代理権限境界と相互運用時の権利・責任保持
  source_modality: SOURCE_DEFINED_AUDIT_OBSERVATION
  permitted_use_scope: 権限逸脱、責任消失、目的外利用の検出
  non_guarantee_scope: 逸脱件数の低さだけで安全性を保証しない
```
反転評価では、再合意時間や説明回数が減っても、説明不足、同意の自動継承、撤回不能による短縮なら成功ではない。相互運用範囲が広がっても、目的外利用、データ集中、権限拡張、幽霊接続が増えるなら改善ではない。エラー件数が少なくても、検出不能や監査不能が原因なら安全性向上とはみなさない。

## 成立条件
- 目的、範囲、期限、責任主体が人間可読・機械可読の両方である。
- 同意が更新・停止・撤回可能な状態として管理される。
- 状態遷移に異議、訂正、失効、再接続が含まれる。
- 最小開示と必要な監査可能性が両立する。
- 制度を移っても権利、来歴、責任主体が保持される。
- AIや代理人の権限が対象、上限、期限、停止条件で限定される。
- 標準変更・互換性・廃止・救済の手続が追跡可能である。

## 失敗条件
- ID連携やSSOだけを接続プロトコルと呼ぶ。
- 同意を一度のチェックで永久化する。
- 履歴を削除不能な人格記録へ変える。
- 撤回・訂正・失効を接続先へ伝播できない。
- 中央レジストリへ全データ・権限を集中させる。
- 相互運用を理由に目的外利用を拡張する。
- AIへ包括的・無期限の代理権限を与える。
- エラー時の責任主体・救済経路が定義されていない。

## 反証・改訂条件
- 標準導入後も再合意時間・説明摩擦が下がらない。
- 撤回、訂正、失効が複数サービスへ反映されない。
- 状態遷移と実態が一致せず、幽霊接続や不要権限が残る。
- 相互運用がデータ囲い込み、監視、目的外利用を強める。
- AI・代理人の権限逸脱を検出・停止・説明できない。
- 標準変更のたびに権利、来歴、責任主体が失われる。
- 標準準拠でも人間が現在状態・責任・異議経路を理解できない。

## 必須の区別
- 接続プロトコル / 万能ID
- 同意 / 一回限りのチェック
- 記憶 / 永久保存
- 状態集合 / 人格・信用スコア
- 相互運用 / 無制限なデータ共有
- 標準化 / 中央集権化
- 代理権限 / 責任移転
- 可逆性 / 履歴の無条件消去
- 互換性 / 安全性の自動保証
- 標準準拠 / 市場参入障壁

## 解釈制約・誤読禁止
ブロックチェーン導入論、SSO、名寄せ、顧客データ統合だけへ縮約しない。同意を免責儀式へ変えず、すべての接続を永久保存しない。相互運用を無制限共有や中央集約へ変えず、AI代理を責任移転へ変えない。状態集合を信用点へ変換せず、再合意時間短縮を説明・同意省略によって達成しない。
