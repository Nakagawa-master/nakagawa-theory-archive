## 位置づけ
第12論は、合意形成の物理シリーズで分解されてきた認知干渉・共振干渉・誘因干渉への個別防衛を、単一の実行時ガバナンスへ束ねる論である。焦点は「正しい制度を設計すれば壊れない」という静的発想ではない。現実の社会や組織は常に外部入力へ晒され、設計図が正しくても、異常検知の遅れ、停止不能、誤状態の拡散、修復経路の喪失によってRuntime段階で劣化しうる。

そこで統治を、正しい判断を固定する能力ではなく、異常状態へ入ったときに安全停止し、検証可能最小単位まで縮退し、起点から再構成し、監査可能な形で再起動できる能力として捉え直す。認知・共振・誘因という入力の意味を先に裁くのではなく、外部摂動 `P_ext` がU/R/H、S、V、参照到達性、利得勾配等へ生じさせた状態変化を観測し、固定された遷移順序へ入ることが中心である。

本論は価値判断、正義、公正、望ましい主張を決める規範理論ではない。扱うのは、検知・停止・縮退・再構成・監査の経路が動作し、しかもその防衛自身が権力化・過剰化・Goodhart化せず、必要なら棄却・改訂できるかという運用仕様である。

## 中心命題
防衛の強さは「異常を絶対に起こさないこと」ではなく、異常が起きた瞬間に安全側へ状態遷移し、検証可能な起点へ戻って再構成できることにある。したがって、防衛インフラの最小核は個別対策の量ではなく、次の実行順序である。

```text
Detect
→ Stop
→ Shrink
→ Recover
→ Audit
```

この順序を固定する理由は、汚染された入力のまま議論・判断・自動化を積み増す自己増幅を断つためである。Detectは真偽判定ではなく異常状態への遷移スイッチ、Stopは処罰ではなく拡散・実行・自動化の安全停止、Shrinkは検閲ではなく検証可能範囲への縮退、Recoverは権威への服従ではなくOriginからの再構成、Auditは晒しではなく恣意性を封じる公開検証である。

さらに、Sの回復だけを成功とみなさない。Sは形式Uの注入、Rの権威化、Hの閉鎖でも表面的に上げられるため、C（合意コスト）とD（実害）を同時監視し、防衛が社会を重くして停止させたり、停止・縮退・公開による実害を増幅したりしていないかを見る必要がある。

## 因果線
```text
静的に正しいKernel / 制度設計が存在
→ 現実Runtimeへ認知・共振・誘因などの外部摂動 P_ext が継続侵入
→ U/R/H、S、V、一次参照到達性、利得勾配等に異常な状態変化
→ 原因内容の断定や議論を続けると、検知遅延・拡散・自動化・自己増幅が進む
→ 複合観測束でDetect
→ Stopで拡散・実行・自動化を安全側へ倒す
→ Shrinkで帯域・権限・論点を検証可能最小単位まで縮退
→ Recoverで人格や権威ではなく一次ログ束・定義束・監査束等のOriginから再構成
→ Auditで停止理由、観測窓δ、閾値θ、署名、差分を検証可能化
→ Sの回復速度・再現性・監査可能性を確認
→ 同時にCとDを監視して免疫暴走・攻撃転用を検知
→ θ・δ・縮退段数・R配分等を監査束付きで改訂、または棄却条件で防衛自体を捨てる
→ 「壊れない」ではなく「壊れても戻れる」動的安定へ
```

## 構造層
### 1. Kernel層
制度・ルール・価値前提・定義など、平常時の設計図を持つ層。第12論はKernelを不要としないが、Kernelの正しさだけではRuntime崩壊を防げないとする。

### 2. Observation層
入力の意味ではなく状態変化を観測する。最低限、Sの急落・停滞・回復速度、形式Uと第三者再現の乖離、H断絶、Vの急減、誘因シグナル等を束で見る。単一指標での起動は誤検知または濫用へつながるため、複合判定を使う。

### 3. Runtime Transition層
Detect → Stop → Shrink → Recover → Auditを固定順序で実行する。ここが本論の中心であり、防衛を「何を信じるか」から「異常時にどう振る舞うか」へ移す。

### 4. Responsibility層
停止権限Rを一主体へ集約しない。少なくともStop Authorizer、Stop Recorder、Resume Verifierを分離し、停止理由・再開条件・署名・ログを外部から検証可能にする。

### 5. Recovery / Origin層
停止後に何へ戻るかを定義する。人格・権威そのものを起点にすると再起動が信仰化するため、一次ログ束、定義束、監査束等へ起点を非人格化し、差分を照合して再構成する。

### 6. Audit / Revision層
防衛発動の理由と設定を公開可能な監査束へ戻し、S/C/Dの変化を測定し、結果をθ・δ・縮退段数・R配分へ還流する。改訂は差分保存され、防衛自体にも棄却条件を置く。

normal_runtime:

## 適用例
### 組織の重大インシデント
誤情報や異常判断が疑われるとき、誰が正しいかを即座に決めず、S、一次参照到達性、論点多様性、責任配置、誘因シグナルの複数面を観測する。異常束が発火したら、新規承認・自動配信・拡散等を一時停止し、影響範囲を最小単位へ絞る。元判断の一次ログ、定義、変更差分から再構成し、再開条件を満たしたかを停止判断者とは別の主体が確認する。

### AI・自動化運用
流暢な出力や高い主観納得だけをU上昇とみなさず、一次ソース到達や第三者再現可能性との乖離を見る。異常時は自動処理の継続よりStopを優先し、対象データ・権限・実行範囲をShrinkする。Recoverでは信頼された人物の説明へ戻すのではなく、入力・定義・履歴・差分へ戻る。

### 情報空間・共振
単一論点や語彙へ帯域が占有され、Vが急減して反証不能になったとき、さらに説得を増やすのではなく、状態異常としてDetectする。縮退は言論統制ではなく、参照可能な論点・根拠単位へ戻す操作であり、再開時には多様性・一次到達性・形式Uとの乖離が回復したかを見る。

### 誘因歪みを含む制度
ルール理解や履歴が残っていても、破壊・遅延の期待利得が合意維持より高ければ、説明追加だけでは戻らない。防衛発動後も破壊が合理的なままなら、その防衛は棄却条件に触れ、R/H/T等の利得配分を含む誘因場から再設計する。

## 測定・監査点
- S=U×R×Hの水準だけでなく、短い観測窓δでの急落、停滞、回復速度を観測しているか。
- 形式Uの上昇と、一次ソース到達率・第三者再現率が乖離していないか。
- H断絶、根拠深度崩壊、Vの急減、破壊・遅延合理化の兆候を単独でなく束として見ているか。
- Detectが内容の真偽判定や思想判定へ変質していないか。
- Stopの理由、観測窓δ、閾値θ、署名、再開条件、差分ログが保存されているか。
- Stop Authorizer / Stop Recorder / Resume Verifierが自己完結していないか。
- 停止に期限と再評価があり、延長に追加根拠が必要か。
- Shrinkが恒常化していないか。縮退段数が増え続けていないか。
- Recover時間が伸び続けていないか。
- S回復だけを成功KPIにしていないか。
- Cが増大し、会議・署名・承認・証跡・例外処理・監査の自己増殖で通常運転を止めていないか。
- Dが遅れて増幅し、恣意停止、公開の攻撃化、自己検閲、ブラックボックス例外処理へ変わっていないか。
- Auditの公開距離が実害を増幅せず、必要な検証可能性を残しているか。
- θ・δ・縮退段数・R配分の変更が差分として保存され、後から再現できるか。

原典はθやδを公開・監査すべき運用変数として扱うが、全場面共通の固定数値を提示していない。したがって本派生物でも独自の閾値、日数、割合を追加しない。

## 成立条件
- 防衛起動が単一指標や単独主体の恣意ではなく、公開可能な複合観測束へ接続されること。
- 異常時に議論・実行・拡散を積み増す前にStopへ遷移できること。
- Shrinkの対象と段数が検証可能性の回復に向けて限定されること。
- Recoverが人物・権威への依存ではなく、一次ログ・定義・監査・差分等のOriginへ戻れること。
- 停止判断、停止記録、再開確認の責任が分離されること。
- 再開条件が価値判断ではなく観測可能な状態として事前に明示されること。
- Auditが発動理由と設定変更を追跡可能にし、防衛運用の恣意性を抑えること。
- S/C/Dを同時に見て、防衛が回復を生みながら別の停止や実害を増幅していないか確認すること。
- 防衛自体を棄却・改訂でき、その変更が差分保存されること。

## 失敗条件
- 「正しい意見」を固定するためにDetectを使う。
- 単一のS低下、単一の通報、単一主体の判断だけで停止する。
- Stopを処罰や排除として運用する。
- 再開条件や期限がなく、停止が恒常化する。
- Shrinkが検証可能性の回復ではなく、異論・主体・情報の恒久的除去になる。
- Recoverが人物への忠誠、権威の宣言、勝者の物語へ戻る。
- Auditが晒し・追跡・報復を生み、Dを増幅する。
- Sの見かけ上の改善だけで成功判定し、C/Dの悪化を隠す。
- 監査のための監査が増殖し、Cが臨界を超えて通常運転を止める。
- 防衛後も破壊・遅延が合理的なままで、攻撃側の利得構造が変わらない。
- 防衛自身が永久化し、「安全だから」という理由だけで改訂不能になる。

## 反証・改訂条件
本論は防衛インフラを永久化しない。少なくとも、発動後も破壊の期待利得が合意維持を上回り続ける場合、防衛が根本因へ触れていないため棄却し、誘因場から再設計する。また、StopやShrinkを増やすほどDが恒常的に増える、必要機能まで萎縮する、Auditが晒し・報復・標的化を増やす場合、防衛は免疫から攻撃へ反転しているため「強化」ではなく棄却・改訂対象となる。

過剰停止、縮退段数の増加、Recover遅延、監査コストの自己増殖が続く場合は、対象側だけを責めず、防衛感度そのものを疑う。θ、δ、縮退段数、R配分等を改訂し、その前後差分を監査束へ保存する。改訂が監査不能なら閉ループは成立しない。

## 必須の区別
- Kernelの正しさ ≠ Runtimeの安全性。
- 外部干渉の意味分類 ≠ 実行時に処理すべき状態変化。
- Detect ≠ 真偽判定・思想判定。
- Stop ≠ 処罰。
- Shrink ≠ 検閲。
- Recover ≠ 権威への服従。
- Audit ≠ 晒し上げ。
- 統合 ≠ 結論の統一・統制。
- S回復 ≠ 防衛成功。
- 高いS ≠ 低いC・低いD。
- 停止権限 ≠ 単独権力。
- 起点Origin ≠ 特定人格。
- 公開可能性 ≠ 無制限公開。
- 防衛の継続 ≠ 防衛の正当性。
- 壊れないこと ≠ 不滅性。本論の不滅性は再起動能力である。

## 誤読禁止 / 解釈制約
第12論を中央集権的な統制OS、検閲プロトコル、思想判定装置として読まない。原典は正しさ、善悪、誰が正義か、どの分配が公正かを測定対象から明示的に外し、外部摂動による状態変化と回復可能性を扱う。

「異常を見つけたらすぐ止める」という単純論でもない。停止条件が曖昧なら恣意化し、単純すぎれば暴走するため、複合観測、最低複数系統の一致、複数主体署名、期限、再開条件、ログ、Auditが一体で必要になる。個別要素だけを抜き取ると、Detectは監視、Stopは圧政、Recoverは物語化、Auditは晒しへ反転しうる。

Sは重要だが単独目的関数ではない。形式Uの注入、Rの権威化、Hの閉鎖でも見かけ上改善できるため、CとDを同時に監視する。原典内には評価記述上「S回復速度」に強く収束する箇所がある一方、その直後にS回復≠成功と明示され、閉ループではC/D同時監視が必須化されている。この力関係を保持し、Sだけの最適化へ縮約しない。

とくに、各記号や閾値は文脈依存の運用変数であり、本派生物から独立した固定数値基準を導いてはならない。第12論の核心は単独モジュールではなく、測定・停止・縮退・再構成・監査・改訂が循環参照として結ばれることである。
